# Планер Astro-Cargo: модель и файлы для печати

Здесь лежит сам самолёт: проект в Fusion 360 и STL-файлы для 3D-печати. Электронику и плату полётника описывает [FC_BOARD.md](../docs/FC_BOARD.md), а сборку и первый полёт — [гайд пилота](../docs/PILOT_GUIDE.md).

## Версия модели: v2

В этой папке лежит **Astro-Cargo v2**. Версии v1 в репозитории не будет: первая модель не публикуется, поэтому вторая стала первой выложенной.

- [Проект Fusion 360](fusion360/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.f3d), 14 МБ;
- [STL-файл для печати](stl/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.stl), 6 МБ.

Файлы названы так, чтобы по имени было сразу видно, что в этой версии не так (подробности ниже).

> [!WARNING]
> **В v2 найдены критические недостатки конструкции:**
>
> 1. **Слабое крепление шасси к фюзеляжу.** Оно не выдерживает вес самолёта, и фюзеляж рвётся в месте крепления.
> 2. **Нет крепления для ленты-липучки (велкро), которой фиксируется аккумулятор.**
>
> Оба недостатка будут исправлены в следующем прототипе, **Astro-Cargo v3**. Его модель появится в этой папке, как только будет готова. До тех пор не поднимайте v2 в воздух без доработки: усильте крепление шасси и сделайте место под липучку сами.

## Что где лежит

| Папка | Что в ней |
|---|---|
| [`fusion360/`](fusion360/) | Исходный проект: файл `.f3d` (или архив `.f3z`, если в проекте несколько файлов). Из него можно менять размеры и заново выгружать детали |
| [`stl/`](stl/) | Детали, готовые к печати, в формате STL |

## Как называть файлы

- Имена — латиницей, с номером версии. Файлы v2 названы так, чтобы имя говорило о недостатках, но дальше лучше обходиться без пробелов и скобок: `astro-cargo_v3.f3d`, `astro-cargo_v3.stl`. Так на файл проще ссылаться из документации. Если деталей несколько, то каждая лежит в своём файле: `fuselage_v3.stl`, `wing_left_v3.stl`.
- Файлы v3 будут лежать рядом (`astro-cargo_v3.f3d`), а файлы v2 останутся: по ним видно, что именно исправлено.
- Единицы — миллиметры. Если в проекте другие, напишите об этом рядом с файлом.

## Если файл слишком большой

GitHub не принимает файлы тяжелее 100 МБ, а предупреждает уже начиная с 50 МБ. Поэтому перед коммитом проверьте размер файла. Такие файлы кладите не в репозиторий, а:

- в раздел **Releases** на GitHub: файл можно прикрепить к релизу, и он может весить до 2 ГБ;
- в [Git LFS](https://git-lfs.com), если файл должен лежать прямо в репозитории и меняться вместе с кодом;
- на внешний хостинг, а ссылку на него добавьте в этот README.

Файлы `.stl`, `.f3d`, `.f3z`, `.step`, `.stp` и `.3mf` в этой папке git считает бинарными (см. [`.gitattributes`](../.gitattributes)): он не меняет в них переводы строк и не показывает построчные различия.
