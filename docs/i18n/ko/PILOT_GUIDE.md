## 필요한 하드웨어

현재 구성의 키트입니다(펌웨어는 이 구성에서 검증했습니다).

- **ESP32-S3 N16R8 보드**(USB-C가 두 개 달린 DevKitC-1 호환 보드. "USB"와 "COM").
- **FS-i6 조종기 + FS-iA6B 수신기**(iBUS 프로토콜, 10채널). 데이터선은 한 가닥만 필요합니다. iBUS SERVO 포트입니다. 조종기에서 failsafe를 설정할 수 있어야 하며, 이 설정은 필수입니다. failsafe 장을 참고하세요.
- 에일러론용 **MG90S 서보 2개**. 날개 반쪽마다 하나씩입니다(독립된 서보 두 개이며, 양쪽 날개에 하나가 아닙니다).
- 승강타용 **MG90S 서보 1개**.
- 방향타용 **MG90S 서보 1개**. 같은 축에 랜딩기어의 조향 바퀴가 달려 있습니다(지상 주행용).
- **변속기(ESC)** 60–80 A, 5 V BEC 포함(BEC가 서보와 수신기에 전원을 공급합니다).
- **모터 D3548 1100KV** + **프로펠러 10x5**.
- **LiPo 3S 배터리**.

오토파일럿 센서(모두 I2C이며, 없어도 기체는 수동 모드로 날 수 있습니다):

- **GY-521**: 자이로 + 가속도계(보드에는 MPU6050이 달려 있을 수도 있고, 저희처럼 MPU6500일 수도 있습니다. 둘 다 지원합니다).
- **BMP388**: 기압계.
- **GY-273**: 나침반(저희 것에는 QMC5883P가 달려 있고, QMC5883L도 지원합니다).
- 선택 사항인 **OLED 128×64 SSD1306**(I2C): 기체에 다는 상태 표시 화면.

기체: 날개폭 1200 mm, 시위 250 mm, NACA 4412 날개골, PETG 구조(3D 프린팅). 첫 번째 시제기는 ESP32-C3, D2212 1000KV 모터, 40 A ESC로 날았습니다.

## 보드 선택과 핀 배치

펌웨어는 보드 세 종류를 지원하며, 바꾸려면 빌드 매개변수 하나면 됩니다(`pio run -e <환경 이름>`). 핀 배치는 보드마다 다르고 환경별로 펌웨어에 고정되어 있습니다. 배선을 마음대로 바꾸지 말고, 자기 보드의 표를 보세요.

> **중요:** 이제 주력 보드는 **esp32-s3**(N16R8)입니다. 이 보드의 핀 배치는 모든 센서를 갖춘 테스트 벤치에서 검증했습니다. **esp32-c3**는 비행 실적이 있는 예전 시제기입니다. **esp32-dev**의 핀 배치는 칩 문서를 바탕으로 정한 것이며 **실제 하드웨어에서는 확인하지 않았습니다**.

### esp32-s3 (N16R8): 주력 보드, 테스트 벤치에서 검증됨

`pio run -e esp32-s3`, 보드는 `esp32-s3-devkitc-1`이며 N16R8 모듈(플래시 16 MB, 옥탈 PSRAM 8 MB) 설정을 씁니다. 기본 보드입니다(`default_envs = esp32-s3`).

| 용도 | GPIO |
|---|---|
| 에일러론, 왼쪽 날개 | GPIO4 |
| 에일러론, 오른쪽 날개 | GPIO5 |
| 승강타 | GPIO6 |
| ESC(스로틀) | GPIO7 |
| 방향타 + 조향 바퀴 | GPIO18 |
| 수신기의 iBUS (RX) | GPIO17 |
| 센서 I2C SDA / SCL(MPU, BMP388, 나침반) | GPIO41 / GPIO42 |
| OLED I2C SDA / SCL(별도 버스) | GPIO1 / GPIO2 |
| 예비: GPS RX / TX | GPIO39 / GPIO40 |
| 예비: AUX1 / AUX2(서보), AUX3, 부저, LIGHT | GPIO15 / 16, 47, 38, 21 |
| 배터리 / 전류 센서(ADC, 블랙박스가 기록), 예비: 텔레메트리 TX / RX | GPIO8 / GPIO3, GPIO9 / GPIO10 |
| 테스트 벤치 전용: SPI (ICM42688) SCK / MISO / MOSI / CS | GPIO12 / 13 / 11 / 14 (+ BMP388의 CS: GPIO21) |

> 센서 버스는 예전에 GPIO8/9에 있었는데, 비행 컨트롤러 보드의 배선에 맞춰 41/42로 옮겼습니다.
> 테스트 벤치에서는 SDA 8→41, SCL 9→42입니다.

사용하지 마세요: GPIO0/45/46(부팅 모드가 여기에 달려 있습니다), 19/20(USB), 26–32(플래시), 33–37(N16R8의 PSRAM), 43/44("COM" 커넥터), 48(RGB LED). 남는 핀은 이미 예비로 배분해 두었습니다. 앞으로를 위한 커넥터 달린 캐리어 보드는 [`FC_BOARD.md`](FC_BOARD.md)에 있습니다.

테스트 벤치에서의 센서 연결(모든 모듈은 5 V가 아니라 **3.3 V**로 동작합니다):

| 모듈 | 핀 |
|---|---|
| MPU-6050 / GY-521(보드에는 MPU6500이 달려 있을 수 있으며, 정상입니다) | VCC–3.3V, GND–GND, SCL–GPIO42, SDA–GPIO41, AD0–GND, INT/XDA/XCL은 연결하지 않습니다. 칩을 위로 향하게 하고 X 화살표를 기수 쪽으로 합니다. 칩 축의 회전은 `Config.h`의 `IMU_ROTATION_CW_DEG`로 정합니다(저희 호환품은 90) |
| BMP388 | VCC–3.3V, GND–GND, SCL–GPIO42, SDA–GPIO41, SDO–GND(주소 0x76), **CSB–3.3V**(그렇지 않으면 칩이 SPI로 넘어갑니다), INT는 연결하지 않습니다 |
| GY-273 (QMC5883P) | VCC–3.3V, GND–GND, SCL–GPIO42, SDA–GPIO41, DRDY는 연결하지 않습니다. 서보, ESC, 모터의 배선에서 멀리 두세요 |
| OLED 128×64 SSD1306 | VCC–3.3V, GND–GND, SCL–GPIO2, SDA–GPIO1 |

서보에는 전원을 **보드가 아니라** ESC의 BEC(또는 2 A 이상인 별도의 5 V 전원)에서 공급합니다. 모든 전원의 접지는 공통으로 합니다. USB가 꽂혀 있는 동안에는 ESC의 빨간 선을 보드의 5 V에 연결하지 마세요.

### esp32-c3: 예전 시제기, 비행 실적 있음

`pio run -e esp32-c3`, 보드는 `esp32-c3-devkitm-1`입니다.

| 용도 | GPIO |
|---|---|
| 에일러론, 왼쪽 날개 | GPIO5 |
| 에일러론, 오른쪽 날개 | GPIO4 |
| 승강타 | GPIO6 |
| ESC(스로틀) | GPIO7 |
| 방향타 | —(남는 핀 없음) |
| 수신기의 iBUS (RX) | GPIO8 |
| I2C SDA(센서) | GPIO1 |
| I2C SCL(센서) | GPIO3 |

### esp32-dev(일반적인 표준 ESP32, 38핀): 테스트 벤치와 디버깅용, 비행 실적 없음

`pio run -e esp32-dev`, 보드는 `esp32dev`입니다.

| 용도 | GPIO |
|---|---|
| 에일러론, 왼쪽 날개 | GPIO13 |
| 에일러론, 오른쪽 날개 | GPIO14 |
| 승강타 | GPIO27 |
| ESC(스로틀) | GPIO26 |
| 방향타 | GPIO25 |
| 수신기의 iBUS (RX) | GPIO16 |
| I2C SDA(센서) | GPIO21 |
| I2C SCL(센서) | GPIO22 |

장점은 이 계열에서 가장 흔하고 저렴한 보드라는 점입니다. 테스트 벤치에서 펌웨어를 디버깅하기에는 좋지만, 핀 배치는 하드웨어에서 확인하지 않았습니다.

## 수신기 연결

수신기에서 필요한 것은 **iBUS 데이터선 한 가닥**뿐이며, 대부분의 FlySky 호환 수신기에서는 별도의 포트로 나와 있습니다(보통 "iBUS"라고 적혀 있거나, PPM이 아닌 유일한 출력입니다). 연결 방법은 다음과 같습니다.

- **수신기 TX(iBUS 출력)** → 위 표에 나온 **보드의 RX 핀**(esp32-c3에서는 GPIO8, esp32-s3에서는 GPIO17, esp32-dev에서는 GPIO16).
- **수신기의 접지(GND)** → **보드의 GND**. 반드시 연결해야 합니다. 접지를 공유하지 않으면 프로토콜이 동작하지 않습니다.
- **수신기 전원**: 별도의 BEC/레귤레이터에서 공급하거나 보드의 5 V에서 가져옵니다. 평소 조립하실 때 수신기에 어떻게 전원을 주는지에 따라 달라지며, 펌웨어의 특정 핀과는 관계가 없습니다.

펌웨어는 수신기에 아무것도 되돌려 보내지 않고 듣기만 하므로, 보드의 TX선은 어디에도 연결할 필요가 없습니다.

펌웨어에서 iBUS 포트의 속도는 115200 보레이트이며 프로토콜의 표준값입니다. 수신기가 스스로 이 속도를 유지하므로 바꿀 필요가 없습니다.

## RC 채널 배치도

이 배치도는 FS-i6 조종기(10채널, 모드 2)와 FS-iA6B 수신기로 테스트 벤치에서 검증했습니다.

| 채널 | 조종기의 조작부 | 이름 | 하는 일 |
|---|---|---|---|
| CH1 | 오른쪽 스틱 ←→ | AILERON | 롤: 에일러론 (2000 = 오른쪽) |
| CH2 | 오른쪽 스틱 ↑↓ | ELEVATOR | 피치: 승강타 (2000 = 스틱을 앞으로, 기수 아래) |
| CH3 | 왼쪽 스틱 ↑↓ | THROTTLE | 스로틀. 1000 µs = 꺼짐, 2000 µs = 최대, 제한 없음 |
| CH4 | 왼쪽 스틱 ←→ | RUDDER | 방향타와 랜딩기어의 조향 바퀴 (서보 하나) |
| CH5 | SwA | ARM | ARM 스위치: 아래의 ARM 장 참고 |
| CH6 | SwB | SWB | 기본값은 플랩: 아래(자기 쪽)가 전개, 위가 접힘 (아래 참고) |
| CH7 | SwC (3단) | SWC | 기본값은 모드: 위 MANUAL, 가운데 STABILIZE, 아래 AUTO_TAKEOFF |
| CH8 | SwD | SWD | 기본값은 RTH(귀환), 켜져 있는 동안 |
| CH9 | VrA | VRA | 기본값은 안정화 세기 |
| CH10 | VrB | VRB | 기본값은 순항 속도 |

CH6–CH10은 `include/config/Controls.h`에서 **한 줄로 무엇이든** 지정할 수 있습니다. 12가지 모드, 10가지 기능(플랩, 브레이크, 화물 투하, 지오펜스, 부저 등), 7개의 노브 중 어느 것이든 됩니다. 보드의 전원을 켜면 실제 배치가 시리얼 모니터에 출력됩니다. 모드와 지정에 관한 모든 내용은 [AUTOPILOT_GUIDE.md](AUTOPILOT_GUIDE.md)에 있습니다.

채널 값은 모두 수신기의 표준 펄스 범위인 1000–2000 µs이고, 1500 µs가 중앙(중립)입니다.

### 플랩(플래퍼론)

별도의 플랩은 없고, 에일러론이 그 역할을 합니다. **SwB 아래**(자기 쪽): 두 에일러론이 약 1초에 걸쳐 부드럽게 같은 각도만큼 내려갑니다(`FLAPS_DEPLOYED_US` = 220 µs ≈ 서보 혼 회전 20°, `include/config/Config.h`에서 바꿉니다). 양력이 늘어나 더 낮은 속도로 이륙하고 착륙할 수 있습니다. 스틱과 오토파일럿의 롤은 평소처럼 동작합니다. 에일러론이 서로 반대 방향으로 움직이는데, 이제는 내려간 위치를 중심으로 움직입니다. **SwB 위**: 마찬가지로 부드럽게 접힙니다. 플랩이 전개되어 있는 동안 OLED 첫 줄에 `FL`이 켜집니다.

플랩을 전개한 채 롤을 끝까지 주면, 내려가는 에일러론이 올라가는 에일러론보다 먼저 가동 범위의 끝에 닿습니다. 정상이며, 에일러론 차동처럼 작용합니다.

플랩을 전개하면 보통 기수가 올라갑니다. 스틱을 앞으로 조금 줄 준비를 해 두세요. 효과가 크면 `FLAPS_DEPLOYED_US`를 줄여서 조정합니다.

## 오토파일럿 채널

요약하면, 기본 배치(`include/config/Controls.h`)는 다음과 같습니다.

| 스위치 | 하는 일 |
|---|---|
| **SwC** (CH7) | 위 **MANUAL** · 가운데 **STABILIZE** · 아래 **AUTO_TAKEOFF** |
| **SwD** (CH8) | **RTH**: 켜져 있는 동안 귀환 |
| **SwB** (CH6) | 플랩 |
| **VrA / VrB** (CH9/10) | 안정화 세기 / 순항 속도 |

- **STABILIZE: "스틱이 각도를 정한다".** 스틱을 끝까지 밀면 롤 45°, 피치 25°이고, 놓으면 비행기가 스스로 수평이 됩니다. 스로틀은 직접 조작합니다.
- **AUTO_TAKEOFF.** ARM 뒤에는 스로틀을 직접 절반 위로 올리기 전까지 아무 일도 일어나지 않습니다. 그다음에는 0–1초 동안 스로틀이 부드럽게 100%까지 올라가고 날개는 수평을 유지하며, 1–3초에는 피치 +15°, 그 뒤로는 SwC를 바꿀 때까지 +10°입니다. 스로틀은 스틱과 프로그램 중 큰 쪽입니다.
- **RTH.** ARM한 지점으로 기수를 향하고, 고도 40 m에서 그 위를 선회합니다. **ARM 전에** 3D 픽스된 GPS가 필요합니다.

12가지 모드 전체(ALT_HOLD, ACRO, CRUISE, LOITER, 손으로 던지는 LAUNCH, AUTO_LAND, SOARING, RESCUE 등)와 모드마다 필요한 센서, 스위치에 지정하는 방법은 [AUTOPILOT_GUIDE.md](AUTOPILOT_GUIDE.md)에 있습니다. 대시보드나 지상국에서 고른 모드는 모드 스위치를 움직이기 전까지 유지됩니다.

기체가 **ARM되지 않았을 때도** 안정화는 조종면을 움직입니다. 그래서 책상 위에서 기울였을 때 어느 쪽으로 반응하는지 볼 수 있습니다. 이때 적분기는 쌓이지 않습니다.

각도의 부호(OLED와 로그에서와 같습니다): **롤 R > 0은 오른쪽 날개가 아래, 피치 P > 0은 기수가 위입니다.**

## ARM과 failsafe

### ARM 절차

- **ARM:** 스로틀(CH3)을 아래로 내린 상태에서 **SwA(CH5)를 아래(자기 쪽)로** 내립니다(FS-i6에서는 CH5 = 2000, 위 = 1000). Serial에 `ArmingManager: ARM`이 나타나고 OLED에 `ARMED`가 표시됩니다.
- **DISARM:** SwA를 위(몸에서 먼 쪽)로 올립니다. 언제든 즉시 적용되며 모터가 바로 멈춥니다.
- 스로틀이 아래에 있지 않은 상태에서 SwA를 ARM으로 옮겼거나 비행 전 점검을 통과하지 못하면 ARM이 **되지 않습니다**(이유는 Serial에 출력됩니다). SwA를 다시 위로 올리고 스로틀을 내린 다음 다시 아래로 내려야 합니다.
- SwA가 이미 ARM 위치(아래)에 있는 상태에서 보드의 전원을 켜면 ARM이 **되지 않습니다**. 펌웨어가 먼저 SwA가 위(OFF)에 있는 것을 확인해야 합니다.

**ARM은 실제로 스로틀을 잠급니다.** 기체가 ARM되지 않은 동안에는 스틱 위치와 상관없이 ESC로 가는 스로틀이 강제로 최솟값에 묶여 있습니다. ARM 전에는 선택한 모드에 필요한 센서가 응답하는지 확인합니다. 예를 들어 IMU가 살아 있지 않으면 MANUAL로 바꾸기 전까지 STABILIZE에서는 ARM되지 않습니다. 그래도 ARM 뒤에는 언제든 프로펠러가 돌기 시작할 수 있다고 생각하고 행동하세요.

### Failsafe

통신 두절은 다른 모든 것보다 **절대적인 우선순위**를 가집니다.

- **기체가 ARM되어 있고 GPS와 홈이 있을 때**: **모터를 쓰는 귀환**(ArduPilot/INAV와 같음). 홈 방향으로 기수를 향하고 고도 40 m에서 통신이 돌아올 때까지 그 위를 선회합니다. OLED에는 `FSRTH`가 표시됩니다. `Config.h`의 `FAILSAFE_RTH = false`로 끌 수 있습니다.
- **기체가 ARM되어 있고 GPS가 없을 때**: **활공**. 모터를 끄고, 오토파일럿은 어떤 모드에서든(MANUAL에서도) 날개를 수평으로, 기수를 수평선보다 약간 아래(−3°)로 유지하며 플랩을 접습니다. OLED에는 `RX LOST ... GLIDE`가 표시됩니다. `FAILSAFE_GLIDE_ROLL_DEG`를 10–20으로 하면 비행기가 완만한 나선을 그리며 머리 위를 선회합니다.
- **ARM되지 않았을 때**(지상) 또는 IMU가 응답하지 않을 때: 모터는 꺼지고, 에일러론·승강타·방향타는 중립(1500 µs)이 됩니다. 통신이 10초 동안 끊기면 "나 여기 있어" 부저가 울립니다(납땜해 두었다면).

펌웨어는 두 가지 방법으로 통신 두절을 인식합니다.

1. **500 ms가 넘도록 iBUS 프레임이 없음**: 전선이 끊어졌거나 수신기에 전원이 들어오지 않습니다.
2. **스로틀이 950 µs 아래**: 수신기가 조종기를 잃었다는 것을 이렇게 알립니다. **그러려면 조종기에서 failsafe를 설정해 두어야 합니다**(아래 참고). 통신이 끊겨도 FS-iA6B는 프레임 전송을 멈추지 않고 스틱의 마지막 값을 반복합니다. 설정하지 않으면 펌웨어는 통신 두절을 알아채지 못하고 비행기는 마지막 스로틀로 계속 날아갑니다.

failsafe가 되어도 ARM은 해제되지 **않습니다**. 통신이 돌아오면 비행기는 다시 ARM하지 않고도 스틱과 선택한 모드를 따릅니다(공중에서 스로틀을 0으로 하고 스위치를 조작하는 편이 더 위험합니다).

책상 위 점검(프로펠러를 떼고): ARM → 조종기 전원 끄기 → OLED에 `RX LOST ... GLIDE`가 표시되고 모터가 멈춥니다. 비행기를 기울이면 조종면이 비행기를 수평으로 되돌려야 합니다. 조종기를 켜면 `RX ok`가 되고 조종이 다시 스틱으로 돌아갑니다.

### FS-i6 조종기에서 failsafe 설정하기(필수, 한 번만)

원리: 통신이 끊기면 수신기가 약 900 µs의 스로틀을 내보내도록 합니다. 정상 최솟값 1000보다 낮은 값입니다.

1. `Menu → Functions setup → End points` → 채널 3: 아래쪽 지점(왼쪽 값)을 **120**%로 합니다. 저장합니다(Cancel 길게 누르기).
2. 스로틀을 **맨 아래**로 내립니다.
3. `Menu → Functions setup → Failsafe` → Channel 3 → **On**. 스로틀은 아직 아래에 둔 채로 Cancel을 길게 눌러 저장합니다. 수신기가 약 900 µs를 기억합니다.
4. `End points`로 돌아가 채널 3의 아래쪽 지점을 다시 **100**%로 되돌립니다. 저장합니다.
5. 확인: ARM은 필요 없습니다. 조종기를 끄면 약 1초 뒤에 Serial에 `RX=LOST(failsafe пульта)`가 나타나고, OLED에는 반전된 `RX LOST` 줄이 표시됩니다. 조종기를 켜면 `RX=OK`가 됩니다.

스로틀 트림은 중앙에 두세요. 트림을 많이 내리면 스로틀이 950 아래로 내려가서 펌웨어가 통신 두절로 판단할 수 있습니다.

예전에는 여기에 **CH8의 부스트**와 40% 스로틀 제한이 있었지만 없앴습니다. 제한은 힘이 약한 3S1P 구성을 지키기 위한 것이었고, 새 배터리는 풀 스로틀을 견딥니다. 부스트는 또한 보드 전원을 켤 때 SwD가 위에 있으면 저절로 켜지기도 했습니다.

## 보드에 펌웨어 올리기

펌웨어는 **PlatformIO**(Arduino 프레임워크, C++)로 빌드합니다.

### PlatformIO 설치

가장 쉬운 방법은 VS Code에 **PlatformIO IDE** 확장을 설치하는 것입니다(Extensions → "PlatformIO IDE" 검색 → Install). 그러면 CLI와 화면의 편리한 빌드 버튼을 모두 쓸 수 있습니다. `pip install platformio`로 설치해서 터미널에서 작업해도 됩니다. 두 방법 모두 같은 `pio` 명령을 씁니다.

### 빌드와 업로드

PlatformIO가 설치된 VS Code에서 프로젝트(저장소 폴더)를 열고, 보드를 USB로 연결한 다음, 터미널에서 자기 보드에 맞는 명령을 실행하세요.

```bash
# esp32-s3 N16R8 (주력 보드)
pio run -e esp32-s3 -t upload

# esp32-c3 (예전 시제기)
pio run -e esp32-c3 -t upload

# esp32-dev (표준 ESP32 38핀, 테스트 벤치용)
pio run -e esp32-dev -t upload
```

`-e`를 아예 지정하지 않으면 기본 보드인 `esp32-s3`가 빌드됩니다.

**esp32-s3:** 이 보드에는 USB-C 커넥터가 두 개 있습니다. 펌웨어 업로드와 Serial은 **"COM"** 커넥터를 통해 이루어집니다(CH343 브리지, Windows에서는 "USB-Enhanced-SERIAL CH343"). "USB" 커넥터(칩 자체의 네이티브 USB)는 작업에 필요하지 않지만 꽂혀 있어도 아무 문제가 없습니다.

### 시리얼 모니터

디버그 출력(채널 상태, ARM, 센서)을 USB를 통해 콘솔에서 바로 보려면 다음을 실행합니다.

```bash
pio device monitor -b 115200
```

속도는 반드시 115200이어야 합니다. 그렇지 않으면 글자 대신 읽을 수 없는 깨진 문자가 보입니다. 10초에 한 번 `SYS` 줄이 출력됩니다. 루프 주파수(약 500 Hz여야 합니다), 10초 동안의 평균 및 최악의 루프 시간, iBUS 카운터, 남은 메모리입니다. 나머지는 로그 메뉴에서 켜 둔 채널로 출력됩니다(아래 참고).

### 콘솔: 메뉴와 로그(시리얼 모니터)

키를 누르면 바로 적용되며 Enter는 필요 없습니다(줄 단위로 전송하는 모니터에서는 글자 + Enter). 캘리브레이션과 출력 점검은 기체가 ARM되지 않았을 때만 동작합니다.

| 키 | 하는 일 |
|---|---|
| `h` | **메인 메뉴**(텍스트 방식, 항목은 숫자로 선택) |
| `l` | "로그에 무엇을 출력할지" 메뉴 |
| 스페이스 | 로그 일시 정지 / 다시 시작 |
| `s` | 모든 센서의 상세 상태(I2C 오류 카운터 포함) |
| `i` | 자이로 재캘리브레이션과 IMU 비행 전 점검: 2초 동안 비행기를 움직이지 마세요 |
| `o` | **IMU 설치 캘리브레이션**: 보드를 비행기에 설치한 뒤 한 번만 합니다(아래 참고) |
| `m` | 나침반 캘리브레이션: 15초 동안 보드나 비행기를 모든 축으로 돌려 주세요. 결과는 플래시에 저장되고 재부팅 후에도 유지됩니다 |
| `p` | 출력 점검: 각 핀의 실제 펄스 |

**채널별 로그.** 데이터 종류마다 고유한 접두사를 가진 줄이 있고, 각각 고유한 모드를 가집니다. **꺼짐**, **변경 시**(값이 실제로 바뀔 때만 줄이 나옵니다. 스틱의 떨림과 센서 잡음은 치지 않습니다), **계속**(0.2 / 0.5 / 1 / 2초마다. 주기는 같은 메뉴에서 정합니다)입니다.

| 채널 | 보여 주는 것 | 기본값 |
|---|---|---|
| `STAT` | 링크, ARM, 모드, 플랩, IMU·기압계가 정상인지 | 변경 시 |
| `RC` | 조종기 채널, µs | 꺼짐 |
| `OUT` | 조종면과 ESC로 가는 출력, µs | 꺼짐 |
| `ATT` | 롤, 피치, 방위 | 꺼짐 |
| `AP` | 오토파일럿: 목표와 보정 | 꺼짐 |
| `ALT` | 고도, 수직 속도, ALT_HOLD 목표 | 꺼짐 |
| `MAG` | 나침반 방위 | 꺼짐 |
| `GPS` | 픽스, 위성, 좌표, 속도 | 꺼짐 |
| `IMU` | 자이로와 가속도계 | 꺼짐 |
| `SYS` | 루프 주파수와 시간, 메모리(10초마다) | 켜짐 |

메뉴가 열려 있는 동안에는 메뉴가 밀려 올라가지 않도록 로그가 멈추고, 메뉴를 닫으면 켜 둔 채널이 모두 다시 출력됩니다. 선택은 메뉴를 나갈 때 플래시에 저장되고 재부팅 후에도 유지됩니다. ARM 중에는 바로 적용되지만 기록은 DISARM 뒤에 이루어집니다. 플래시에 쓰면 비행 루프가 약 0.4초 멈추기 때문입니다.

### IMU 설치: 방향은 자유, 캘리브레이션은 한 번

IMU가 달린 보드는 비행기에 **편한 대로** 설치해도 됩니다. 어떤 각도든, 옆으로 눕히든, 뒤집든 상관없습니다. 보드의 어느 쪽이 기수고 어느 쪽이 위인지는 펌웨어가 스스로 알아냅니다. 설치한 뒤 **한 번만** 하면 되고(보드 위치를 바꿨다면 다시 합니다), 방법은 다음과 같습니다.

1. 비행기를 책상 위에 놓습니다. 조종기는 필요 없고 모터는 ARM하지 않습니다. 시리얼 모니터에서 `o`를 누릅니다.
2. **1단계:** 수평 비행할 때처럼 비행기를 수평으로 놓습니다(꼬리 바퀴가 달린 비행기라면 꼬리 밑에 뭔가를 괴어 주세요). 약 3초 동안 건드리지 마세요.
3. **2단계:** **기수**를 30–60° 들어 올리고, 날개는 수평으로 유지한 채 약 1초 동안 가만히 있으세요.
4. **3단계:** 기수를 다시 내리고 **오른쪽 날개**를 30–60° 내린 채 약 1초 동안 유지하세요.

각 단계는 자동으로 인정됩니다(로그에 "засчитано", 즉 "인정됨"이 나옵니다). 마지막에는 결과("нос = +Y чипа, верх = −Z чипа", 즉 "기수 = 칩의 +Y, 위 = 칩의 −Z")와 "установка сохранена"("설치 정보 저장됨")가 표시됩니다. 잘못했다면(기수를 올리지 않고 내렸거나, 오른쪽이 아니라 왼쪽 날개를 내렸다면) 설명과 함께 캘리브레이션이 거부되니 `o`를 다시 누르면 됩니다. 결과는 플래시에 저장되고 재부팅 후에도 유지됩니다. 확인: 기수를 들면 OLED의 P가 양수가 되고, 오른쪽 날개를 내리면 R이 양수가 됩니다.

설치 캘리브레이션이 없는 동안에는 예전 방식이 적용됩니다. 보드는 반드시 칩이 위를 향하게 놓아야 하며, 회전은 `Config.h`의 `IMU_ROTATION_CW_DEG`로 정합니다.

### 전원을 켤 때의 비행 전 점검

전원을 켤 때마다 IMU는 약 2초 동안 자이로를 캘리브레이션하면서 스스로도 점검합니다.

- **비행기가 정지해 있어야 합니다.** 그때 손에 들고 있었거나 움직였다면 자이로 오프셋이 틀어집니다.
- 가속도계가 정지 상태에서 1g를 가리켜야 합니다.
- **"위"가 설치 캘리브레이션과 일치해야 합니다.** 보드를 옮기거나 뒤집었다면 바로 드러납니다(꼬리 바퀴로 서 있거나 경사면에 놓인 비행기는 문제없으며 허용 오차는 45°입니다).

**비행기를 정지시킨 채 전원을 켜세요.** 설치가 캘리브레이션되어 있다면 수평일 필요는 없습니다(그렇지 않으면 전원을 켰을 때의 자세가 수평선이 됩니다). 결과는 로그에 나옵니다. `предполётная проверка пройдена`("비행 전 점검 통과") 또는 `ПРЕДПОЛЁТНАЯ ПРОВЕРКА НЕ ПРОЙДЕНА — <причина>`("비행 전 점검 실패", 이어서 이유)입니다. 통과하지 못하면 **STABILIZE와 AUTO_TAKEOFF에서의 ARM이 금지되고**(시도하면 이유가 출력됩니다), 오토파일럿은 통신 두절 시의 활공을 포함해 어떤 모드에서도 보정을 하지 않습니다. 각도가 틀린 채라면 반대 방향으로 조타할 것이기 때문입니다. MANUAL에서는 ARM할 수 있습니다. 해결 방법: 비행기를 정지시켜 놓고 배터리를 다시 연결하거나(`i`를 눌러도 됩니다), 보드를 옮겼다면 `o`를 누르세요.

### OLED 화면

OLED가 연결되어 있다면(GPIO1/GPIO2) 초당 5번 다음 내용을 표시합니다.

```
RX ok disarm STAB        <- 링크 / ARM / 모드(링크가 끊기면 줄이 반전 표시됩니다)
R  +1.2 P  -0.4          <- 롤 / 피치, °
Alt +0.3 Vz +0.1         <- 전원을 켠 지점 기준 고도, m / 수직 속도, m/s
Hdg 123  Thr 1000        <- 나침반 방위 / ESC로 가는 스로틀, µs
L1500 R1500 E1500        <- 에일러론과 승강타의 PWM, µs
Loop 500Hz max 1100us    <- 주파수와 최악의 루프 시간
```

## 현장에서 쓰는 웹 대시보드

보드가 자체 Wi-Fi 액세스 포인트를 띄웁니다. 집 공유기도, 인터넷도 필요 없고, 모든 것이 현장에서 스마트폰만으로 바로 동작합니다.

**접속 방법:**

1. 스마트폰이나 노트북에서 Wi-Fi 네트워크 목록을 엽니다.
2. 네트워크 **`OpenPlane-Debug`**(비밀번호 **`12345678`**)에 연결합니다.
3. 브라우저에서 **`http://192.168.4.1`** 주소를 엽니다.

앱을 설치할 필요는 없습니다. 평범한 웹 페이지입니다.

**현장에서 스마트폰으로, 프로그래밍 없이 할 수 있는 일:**

- **10개 RC 채널 전체의 실시간 막대**를 볼 수 있습니다. 서보를 연결하기 전에도 조종기와 수신기가 스틱에서 움직인 값을 제대로 보내고 있는지 편하게 확인할 수 있습니다.
- 각 출력(왼쪽/오른쪽 에일러론, 승강타, ESC)의 상태를 볼 수 있습니다. 채널이 소프트웨어적으로 연결되어 있는지 알 수 있습니다.
- 센서(IMU, 기압계)를 납땜해 두었다면 응답하는지 볼 수 있습니다. 실제 데이터(롤/피치/고도)가 정직하게 표시되거나, 센서가 물리적으로 없거나 응답하지 않는다는 표시가 분명하게 나옵니다.
- 페이지의 버튼으로 **오토파일럿 모드를 바꿀** 수 있습니다(수동 / 안정화 / 자동 이륙 / 고도 유지). 조종기는 필요 없습니다.
- 페이지의 양식으로 **PID 컨트롤러 계수를 조정**할 수 있습니다(롤과 피치). 펌웨어를 다시 올리지 않고 안정화를 조금씩 맞출 때 유용합니다.

이 액세스 포인트의 도달 거리는 실제로는 수십 미터입니다. ESP32의 평범한 Wi-Fi일 뿐 장거리 텔레메트리가 아닙니다. 책상 위, 테스트 벤치, 비행장 옆에서 설정하는 도구이며, 멀리 떨어진 곳에서 비행 중인 기체를 조종하는 용도가 아닙니다.

## 블랙박스

ESP32-S3 펌웨어는 모든 비행을 스스로 플래시에 기록합니다. 센서가 본 모든 것, 스틱의 움직임, 서보가 움직인 방향, 오토파일럿의 판단까지 담습니다. 따로 할 일은 없습니다.

- 기체가 ARM되고 스로틀이 올라간 순간부터 **기록합니다**(그 전의 10초 포함).
- DISARM 10초 뒤에 **멈춥니다**. 또는 ARM된 기체가 모터를 끈 채 30초 동안 움직이지 않을 때도 멈춥니다(착륙했거나 추락했는데 DISARM을 잊은 경우).
- 통신 두절, 모터 0, 활공은 기록을 **멈추지 않습니다**.

전원을 켜면 시리얼 모니터에 한 번의 비행에 쓸 수 있는 공간이 표시됩니다(콘솔은 러시아어로 출력합니다. 아래 줄은 "ARM과 스로틀 대기 중 | 앞쪽 삭제됨 12.9 MB(약 11분) / 전체 13.9 MB | 비행 1회"라는 뜻입니다):

```
BlackBox: ждёт ARM и газ | стёрто впереди 12.9 МБ (≈11 мин) из 13.9 МБ | полётов 1
```

**비행이 끝난 뒤**에는 USB(COM 커넥터)를 연결하고, 시리얼 모니터를 닫은 다음 비행 기록을 내려받습니다.

```bash
python tools/blackbox.py download
```

비행 기록은 분석 결과와 함께 `blackbox/` 폴더에 저장됩니다. `summary.txt`(요약과 이벤트), `events.txt`, 센서별 CSV 표입니다. 블랙박스는 공간이 필요하면 오래된 비행 기록을 스스로 지우므로 **비행할 때마다 내려받으세요**. 콘솔의 메뉴는 `k` 키입니다. 자세한 내용은 모두 [BLACKBOX.md](BLACKBOX.md)에 있습니다.

**STM32H743 보드에서는** 블랙박스가 SD 카드에 기록합니다. 카드는 FAT32로 포맷하고, PC에서 한 번만 준비합니다(`python tools/blackbox.py sd-prepare E:`). 비행 후에는 같은 `download` 명령으로 USB를 통해 내려받을 수도 있고, 카드를 빼서 파일을 카드에서 바로 분석할 수도 있습니다: `python tools/blackbox.py ring E:/BLACKBOX.BIN`.

## 비행 전 체크리스트와 안전

이 장은 사고가 난 뒤가 아니라 처음 전원을 켜기 **전에** 끝까지 읽으세요.

### 테스트 벤치 시험 전에 반드시 지킬 것

- [ ] 채널, ARM, 대시보드를 확인하거나 PID를 조정할 때, 또는 새 핀 배치로 보드에 처음 전원을 넣을 때는 **프로펠러를 물리적으로 분리해 둡니다**. ESC는 시험의 어느 단계에서든 모터를 덜컥 움직일 수 있습니다. 가정 속의 위험이 아니라 처음 전원을 켤 때 나타나는 정상적인 동작입니다.
- [ ] LiPo 배터리는 부풀거나 손상된 곳이 없는지 점검했고, 올바른 LiPo 충전기로 충전했으며, 불에 타지 않는 표면에서 보관하고 충전합니다.
- [ ] 조종기가 켜져 있고, 배터리를 ESC에 연결하기 **전에** 대시보드(`http://192.168.4.1`)에서 조종기 채널을 확인했습니다.

### 비행 전

- [ ] 탁 트인 장소로, 서보나 날개가 비정상적으로 동작하는 상태에서 수동 조종 중인 날개폭 1200 mm 비행기에게 충분한 반경 안에 사람도 건물도 없습니다(아래 "시제기 기체의 현재 상태" 장을 참고하세요. 모터 마운트와 날개는 아직 카본으로 보강되지 않았습니다).
- [ ] 세 조종면이 모두 올바른 방향으로 움직입니다. 지난번 기억에 의존하지 말고 비행할 때마다 책상 위에서 확인하세요.
  - 오른쪽 스틱을 오른쪽으로 → **오른쪽 에일러론 위, 왼쪽 아래**
  - 오른쪽 스틱을 자기 쪽으로 → **승강타 위**
  - 왼쪽 스틱을 오른쪽으로 → **방향타와 조향 바퀴가 오른쪽**
  - SwB(플랩)를 아래로 → **두 에일러론이 부드럽게 아래로 내려가며**, 이때 스틱으로 롤을 주어도 두 에일러론은 여전히 서로 반대 방향으로 벌어집니다
  - STABILIZE에서 비행기를 오른쪽 날개가 아래로 가게 기울이기 → **오른쪽 에일러론 아래, 왼쪽 위**(조종면이 기체를 수평으로 되돌립니다). 기수 아래로 → **승강타 위**
  뭔가 맞지 않으면 조종기의 리버스가 아니라 `include/config/Config.h`의 해당 `*_REVERSED`("서보 방향" 부분)를 바꾸세요. 그렇지 않으면 스틱과 오토파일럿이 서로 어긋납니다.
- [ ] 전원을 켤 때 비행기가 정지해 있었고, 로그나 대시보드에 `ПРЕДПОЛЁТНАЯ ПРОВЕРКА НЕ ПРОЙДЕНА`라는 문구가 없습니다. 비행기를 손에 들고 기울이면 OLED의 P와 R이 올바른 방향으로 바뀝니다.
- [ ] 조종기에 failsafe를 설정하고 확인했습니다. 조종기를 끄면 OLED나 Serial에 `RX LOST`가 나옵니다(failsafe 장을 참고하세요).
- [ ] 조종기의 도달 거리를 확인했고, 조종기 배터리는 충전되어 있습니다.
- [ ] 전원을 켤 때 로그에 `BlackBox: ... стёрто впереди N МБ (≈M мин)`가 나왔다면 비행에 쓸 공간이 충분합니다. 지난 비행 기록이 필요하면 이미 내려받았습니다(`python tools/blackbox.py download`).
- [ ] LiPo가 ESC에 연결되어 있는 동안에는 언제든 프로펠러에서 손과 얼굴을 멀리 두세요. ARM 후에는 스로틀이 별도의 경고 없이 스틱에 곧바로 반응합니다. DISARM은 SwA 위입니다.
- [ ] 신호 상실 시의 failsafe에만 의존하지 말고, 전원을 물리적으로 빠르게 끊을 수 있는지(LiPo 커넥터에 손이 닿는지) 확인하세요.

### LiPo 일반 안전 수칙

- 충전 중인 LiPo를 절대 방치하지 마세요.
- 프로펠러 회전면 옆에 선 채로 LiPo를 ESC에 연결하거나 분리하지 마세요.
- LiPo는 보호 가방이나 보호 케이스에 넣어 운반하고 보관하세요.

## 문제 해결

**"수신기 신호 없음" / RX는 정상으로 보이는데 대시보드의 채널이 움직이지 않는다**
수신기의 데이터선이 사용 중인 보드 표에 나온 iBUS RX 핀(GPIO8/GPIO17/GPIO16)에 정확히 연결되어 있는지, GND나 전원선과 바뀌지 않았는지, 수신기와 보드의 GND가 서로 이어져 있는지 확인하세요. 핀 배치가 맞고 배선도 멀쩡한데도 신호가 없다면, 수신기가 조종기와 애초에 바인딩(bind)되어 있는지, 수신기 출력이 PPM/SBUS가 아니라 iBUS로 설정되어 있는지 확인하세요.

**센서(IMU, 기압계, 나침반)가 "응답 없음" / NO_RESPONSE라고 표시된다**
펌웨어는 0을 내보내는 대신, 센서가 응답하지 않는다고 솔직하게 알려 줍니다. 다음을 확인하세요. (1) 모듈 전원: 3.3V와 보드의 GND. (2) SDA/SCL: 사용 중인 보드의 I2C 핀에 연결되어 있는지. (3) 버스의 주소: MPU 0x68(AD0을 GND에), BMP388 0x76(SDO를 GND에, **CSB를 3.3V에** 연결해야 하며, 그렇지 않으면 칩이 SPI 모드가 됩니다), QMC5883P 0x2C, QMC5883L 0x0D. 센서가 응답했다 안 했다 하거나(또는 엉뚱한 주소로 응답하면) 브레드보드의 접촉 불량입니다. VCC/GND/SDA/SCL을 꾹 눌러 끼우고, 모듈마다 보드의 3.3V/GND에서 직접 전원을 받게 하는 것이 가장 좋습니다. 콘솔의 `s` 명령은 센서별 I2C 오류 카운터를 보여 줍니다.

**OLED의 각도가 뒤바뀌었거나(기수를 들면 P가 아니라 R이 변함) 부호가 반대다**
IMU 설치 캘리브레이션(`o`, "IMU 설치" 참고)을 하세요. 칩이 모듈에 어떻게 납땜되어 있는지, 모듈이 비행기에 어떻게 놓여 있는지와 무관합니다. 캘리브레이션이 없을 때: GY-521 호환품은 칩이 인쇄된 화살표에 대해 돌아간 채 납땜되어 있는 경우가 있습니다. `Config.h`의 `IMU_ROTATION_CW_DEG`(0/90/180/270)에서 축을 돌려 주세요. 확인: 기수 위로 → P가 플러스, 오른쪽 날개 아래로 → R이 플러스.

**ARM이 거부됨: "IMU: ..."**
IMU 비행 전 점검을 통과하지 못한 것입니다("전원을 켤 때의 비행 전 점검" 참고). 전원을 켤 때 비행기를 움직였다면 가만히 놓고 배터리를 다시 연결하세요. "위"가 캘리브레이션과 맞지 않는다면 보드 위치를 바꾼 것이니 `o`를 하세요. "보드가 칩을 위로 하고 놓여 있지 않다"면 설치가 캘리브레이션되지 않은 것이니 `o`를 하세요.

**서보나 ESC가 엉뚱한 스틱에 반응한다 / 반응하지 않는다**
콘솔의 `p` 명령은 각 출력(GPIO4–7)의 실제 펄스를 측정해 기대값과 비교합니다. 모두 "OK"인데 서보가 움직이지 않는다면 문제는 보드 너머에 있습니다. (1) 서보에 전원이 들어오지 않음(BEC/5V, 공통 GND). (2) 신호선이 다른 핀에 연결됨. (3) 기구가 걸려 있음. "НЕ СОВПАДАЕТ"("불일치")가 나오면 문제는 펌웨어나 주변 장치에 있으니 개발자에게 알려 주세요.

**OLED나 대시보드의 스로틀은 스틱에 반응하는데 모터가 전혀 돌지 않는다**
LiPo가 ESC에 연결되어 있는지, 기체가 정말 ARM되어 있는지 확인하세요. ARM 전에는 ESC로 가는 스로틀이 강제로 최소로 유지되며, 이는 고장이 아닙니다. 전원을 켤 때 스로틀이 최소가 아닌 것을 본 ESC는 계속 삑삑거리며 ARM되지 않을 수 있습니다. 스로틀을 내린 채 배터리를 다시 연결하세요. SwA를 내렸는데 `ArmingManager: ARM`이 나오지 않으면 Serial을 보세요. 펌웨어가 이유를 출력합니다(스로틀이 내려가 있지 않음, 센서가 응답하지 않음, 지금 CH7에서 선택된 모드에 필요한 센서 등). SwA를 다시 위로 올리고, 원인을 없앤 다음 다시 내리세요.

**가속할 때 모터가 멈추거나 덜덜 떤다**
ESC를 실험실용 전원 공급기로 구동한다면 공급기의 전류 제한에 걸린 것입니다. 프로펠러가 없어도 모터는 잠깐 몇 암페어를 끌어 쓰고, 전압이 처지면서 ESC가 재시작됩니다. 전류 제한을 올리거나 LiPo를 쓰세요. 이런 재시작에서 나오는 노이즈가 보드의 USB 브리지를 멈추게 할 수 있습니다("COM" 포트가 더 이상 열리지 않음). 이때는 케이블을 다시 꽂으세요.

**펌웨어를 올린 뒤 보드가 응답하지 않는다 / 액세스 포인트 `OpenPlane-Debug`가 나타나지 않는다**
업로드(`pio run -e <사용 중인 보드> -t upload`)가 오류 없이 끝났는지, 그리고 손에 들고 있는 보드에 해당하는 환경을 정확히 올렸는지 확인하세요(esp32-c3는 esp32-s3, esp32-dev와 핀뿐 아니라 칩도 다릅니다. 다른 칩용 펌웨어는 보드에 올라가지 않거나 잘못 올라갑니다). 보드가 재부팅한 직후 시리얼 모니터의 출력(`pio device monitor -b 115200`)을 확인하세요. 보드가 setup()의 어느 단계에 있는지 출력됩니다.

## 시제기 기체의 현재 상태

기대치를 정직하게 유지하기 위해 밝힙니다.

- 첫 시제기는 **이미 비행했습니다**. 그 결과 문제점이 확인되었습니다. **모터 마운트의 강도 부족**과 **날개의 강도 부족**으로, 날개는 카본 보강이 필요합니다. 서보도 추가 조정이 필요합니다. 직접 비행을 계획할 때 이 점을 감안하세요. 이는 추상적인 단서 조항이 아니라 이 시제기에서 이미 실제로 일어난 고장입니다.
- **esp32-s3 테스트 벤치는 모든 센서를 갖춰 구성되어 있습니다**(MPU6500이 달린 GY-521, I2C로 연결한 BMP388, QMC5883P가 달린 GY-273, OLED). 모두 응답하며 루프는 500 Hz로 돕니다. 오토파일럿 모드는 책상 위에서 검증했지만 **아직 비행에서는 시험하지 않았습니다**.
- BMP388 기압계는 Bosch의 전체 보정 공식으로 계산합니다. 고도는 전원을 켠 지점 기준의 상대값입니다. 해발 절대 고도는 표준 대기로 계산하며 날씨 보정은 없습니다.
- QMC5883P 나침반은 조립을 마친 비행기에서 캘리브레이션해야 합니다(콘솔에서 `m`). 모터와 배선 근처에서는 오프셋이 브레드보드와 다릅니다. 방위에는 아직 기울기 보정이 없고 어떤 모드에서도 사용하지 않습니다.
