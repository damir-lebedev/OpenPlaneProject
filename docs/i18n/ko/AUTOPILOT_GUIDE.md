# OpenPlane 오토파일럿 레퍼런스

> 🌐 이 문서는 [러시아어 원문](../../AUTOPILOT_GUIDE.md)을 번역한 것입니다. 번역과 원문이 다를 경우 원문이 우선합니다. 펌웨어는 콘솔 메시지를 러시아어로 출력하므로 그대로 인용했습니다. 이 번역은 AI가 작성했으며 원어민의 검수를 거치지 않았습니다. 오류를 발견하면 [Damir Lebedev](https://github.com/damir-lebedev)에게 알려 주시거나 [이슈](https://github.com/damir-lebedev/OpenPlaneProject/issues)로 남겨 주세요.

오토파일럿이 할 수 있는 일, 각 기능을 켜는 방법, 그리고 조종기의 어떤 스위치나 노브에든 **한 줄로** 연결하는 방법을 설명합니다.

> 먼저 솔직하게 밝힙니다. 모든 모드는 단위 테스트와 폐루프 비행 시뮬레이션(`test/native/test_sim`: 펌웨어 전체가 비행기 모델을 조종합니다)으로 검증되었습니다. 모델은 단순화되어 있고, `Config.h`의 계수는 시작값입니다. **모든 모드는 먼저 고도 50 m 이상에서 손가락을 MANUAL 스위치에 올려 두고 시험하세요**. 지금까지 실제로 비행한 것은 수동 모드뿐입니다(ESP32-C3를 쓴 첫 시제기). 안정화는 테스트 벤치에서 검증했고, 조종면은 기울기에 올바른 방향으로 반응합니다. STM32H743 보드는 빌드되며 같은 테스트를 통과합니다. 실제 하드웨어에서는 DevEBox 보드를 센서 없이 검증했습니다. SD 카드, 블랙박스, 조종기로 하는 서보와 모터의 수동 조종입니다(영상으로 촬영했습니다). 센서는 아직 연결하지 않았고, 이 보드에서 오토파일럿 모드는 시험하지 않았습니다.

## 1분 만에 보는 구조

```
스틱 ───┐
        ├─► PilotSwitches (config/Controls.h) ─► 모드, 기능, 노브
스위치 ─┘                                              │
                                                       ▼
센서(IMU, 기압계, 나침반, GPS, 피토관) ────────────► Autopilot ─► 조종면과 스로틀 명령
                                                       │
                          FlightController: 플랩, 화물, 카메라, 부저, failsafe
                                                       ▼
                                          에일러론 · 승강타 · 방향타 · ESC · AUX1 · AUX2
```

- **모드**는 누가 조종하는지를 정합니다. 파일럿(MANUAL), 보조를 받는 파일럿(STABILIZE, ALT_HOLD, ACRO), 파일럿의 보정을 받는 오토파일럿(CRUISE, LOITER, RTH 등)입니다.
- **기능**은 어떤 모드 위에든 겹쳐서 켭니다. 플랩, 브레이크, 화물 투하, 지오펜스 등입니다.
- **노브**는 숫자를 부드럽게 바꿉니다. 안정화 세기, 순항 속도, 선회 반경 등입니다.
- 안정화가 있는 모드에서는 **스틱이 각도를 지정합니다**. 조종면의 꺾임 정도가 아닙니다. 스틱을 놓으면 비행기가 스스로 수평을 잡습니다.
- 센서가 고장 나도 비행기가 "덜컥"거리는 일은 없습니다. IMU가 없으면 조종면은 파일럿 몫이고, 기압계가 없으면 고도는 파일럿이 유지하며, GPS가 없으면 내비게이션이 없고 GPS가 필요한 모드는 안전하게 동작합니다([표](#모드별-필요-조건) 참고).

## 조종기 기본 배치

FS-i6 + FS-iA6B, iBUS, 10채널(`config/Channels.h`).

| 채널 | 조종기 부위 | 기본값 |
|---|---|---|
| CH1–CH4 | 스틱 | 롤, 피치, 스로틀, 방향타(재지정 불가) |
| CH5 | **SwA** | **ARM**(아래 = ARM됨, 스로틀이 아래일 때만. 재지정 불가) |
| CH6 | SwB | 플랩(`Feature::FLAPS`) |
| CH7 | **SwC**(3단) | 위 **MANUAL** · 가운데 **STABILIZE** · 아래 **AUTO_TAKEOFF** |
| CH8 | SwD | **RTH** — 홈으로 귀환, 켜져 있는 동안 |
| CH9 | VrA | 안정화 세기(`Knob::STAB_GAIN`) |
| CH10 | VrB | 순항 속도(`Knob::CRUISE_SPEED`) |

보드의 전원을 켜면 시리얼 모니터에 실제 배치, 즉 보드에 실제로 올라간 내용이 출력됩니다(펌웨어는 러시아어로 출력하며, "вверх / середина / вниз"는 "위 / 가운데 / 아래"라는 뜻입니다):

```
SwC (CH7): MANUAL / STABILIZE / AUTO_TAKEOFF (вверх / середина / вниз)
SwB (CH6): FLAPS, пока включён
SwD (CH8): RTH, пока включён
VrA (CH9): крутилка STAB_GAIN
VrB (CH10): крутилка CRUISE_SPEED
```

> FS-i6에서는 채널 7–10이 기본적으로 출력되지 않습니다. 조종기 메뉴: **Functions setup → Aux. channels**에서 SwC, SwD, VrA, VrB를 지정하세요.

## 한 줄로 기능 지정하기

모든 설정은 한 파일, `include/config/Controls.h`에 있습니다:

```cpp
constexpr Binding BINDINGS[] = {
    Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_AUTO_TAKEOFF),
    Bind::feature(Channels::SWB, Feature::FLAPS),
    Bind::mode   (Channels::SWD, MODE_RTH),
    Bind::knob   (Channels::VRA, Knob::STAB_GAIN),
    Bind::knob   (Channels::VRB, Knob::CRUISE_SPEED),
};
```

| 줄의 형태 | 하는 일 |
|---|---|
| `Bind::modes(채널, 위, 가운데, 아래)` | 3단 스위치로 모드를 고릅니다 |
| `Bind::modes(채널, 위, 아래)` | 2단 스위치로 두 모드 중 하나를 고릅니다 |
| `Bind::mode(채널, 모드)` | 스위치가 켜져 있는 동안 다른 모드 **위에** 적용되는 모드. 끄면 모드 스위치의 모드로 돌아옵니다 |
| `Bind::feature(채널, 기능)` | 스위치가 켜져 있는 동안 기능이 동작합니다 |
| `Bind::knob(채널, 노브)` | 노브: 중앙 = `Config.h`의 값, 양 끝 = 최솟값과 최댓값 |

"켜짐"은 채널이 1750 µs를 넘는 상태를 뜻합니다(FS-i6에서는 스위치를 아래, 자기 쪽으로 내린 상태). 수신기의 첫 프레임이 오기 전까지 모든 채널은 꺼진 것으로 간주합니다. 그래서 전원을 넣을 때 무언가가 펼쳐지거나 투하되는 일은 없습니다.

### 바로 쓸 수 있는 예시

```cpp
// 서멀 글라이더: SwD — 소어링, SwB — 오토 트림, VrB — 선회 반경
Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_SOARING),
Bind::feature(Channels::SWB, Feature::AUTO_TRIM),
Bind::knob   (Channels::VRA, Knob::STAB_GAIN),
Bind::knob   (Channels::VRB, Knob::LOITER_RADIUS),

// 초보자: 안정화만, "비상 버튼"에 RESCUE, 부드러운 스틱
Bind::modes  (Channels::SWC, MODE_STABILIZE, MODE_ALT_HOLD, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_RESCUE),
Bind::feature(Channels::SWB, Feature::GEOFENCE),
Bind::knob   (Channels::VRA, Knob::RATES),
Bind::knob   (Channels::VRB, Knob::MAX_BANK),

// 촬영과 배송: 안정화 카메라, 화물 투하, 한 지점 위에서 선회
Bind::modes  (Channels::SWC, MODE_STABILIZE, MODE_CRUISE, MODE_LOITER),
Bind::feature(Channels::SWB, Feature::PAYLOAD_DROP),
Bind::feature(Channels::SWD, Feature::CAMERA_STAB),
Bind::knob   (Channels::VRA, Knob::CAMERA_TILT),
Bind::knob   (Channels::VRB, Knob::LOITER_RADIUS),

// 랜딩기어 없이 손으로 던져 이륙: SwD — LAUNCH, 플랩은 노브로 부드럽게
Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_LAUNCH),
Bind::feature(Channels::SWB, Feature::AIRBRAKE),
Bind::knob   (Channels::VRA, Knob::FLAPS),
Bind::knob   (Channels::VRB, Knob::CRUISE_SPEED),
```

### 컴파일러가 실수를 잡아냅니다

표는 빌드할 때 검사되므로(`static_assert`), 펌웨어가 비행기에 올라가기 전에 실수가 드러납니다.

- 스틱과 SwA(ARM)는 지정할 수 없고, 채널 번호는 `Channels::COUNT`보다 작아야 합니다.
- 채널 하나에는 지정을 하나만 할 수 있습니다.
- 모드를 고르는 스위치(`Bind::modes`)는 하나를 넘을 수 없습니다.

여러 `Bind::mode` 스위치가 동시에 켜져 있으면 표의 위쪽 줄이 우선합니다.

## 모드

모드는 스위치를 **전환했을 때** 바뀝니다. 대시보드나 지상국에서 켠 모드는 파일럿이 모드 스위치를 다시 전환할 때까지 유지됩니다. OLED에는 짧은 이름(괄호 안)이 표시됩니다.

### MANUAL (MAN)
조종면 = 스틱, 비행 컨트롤러가 없을 때와 같습니다. 기능(플랩, 브레이크, 화물)과 오토 트림만 동작합니다. **가장 중요한 안전 모드**입니다. 항상 손가락 아래의 스위치에 지정해 두세요.

### STABILIZE (STAB) — "스틱이 각도를 정한다"
롤 스틱은 `MAX_BANK_DEG`(45°, 노브 `MAX_BANK`은 15…60°)까지의 뱅크 각을, 피치 스틱은 `STAB_MAX_PITCH_DEG`(25°)까지의 각도를 정합니다. 스틱을 놓으면 비행기가 스스로 수평을 잡습니다. 스로틀은 파일럿 몫입니다. PID의 적분은 목표 가까이(±10°)에서만 쌓이므로, 급한 기동 뒤에도 비행기가 수평선을 "넘어가지" 않습니다.
**필요한 것:** IMU. IMU가 없으면 MANUAL과 같습니다.

### ALT_HOLD (ALT) — "고도를 유지한다"
롤은 STABILIZE와 같고, 승강타는 기압계로 고도를 유지합니다. 피치 스틱을 움직이면 직접 조종하고, 놓으면 비행기가 **새** 고도를 유지합니다. 스로틀은 파일럿 몫입니다(스로틀을 더 주세요. 그러지 않으면 상승에 필요한 속도가 모자랍니다).
**필요한 것:** IMU + 기압계.

### ACRO — "스틱이 회전 속도를 정한다"
스틱을 끝까지 밀면 180°/s입니다. 놓으면 비행기는 **그때의 자세를 유지합니다**(뒤집힌 채여도). 자이로스코프가 돌풍을 눌러 줍니다. 곡예비행용입니다.
**필요한 것:** IMU. IMU가 없으면 조종면 = 스틱입니다.

### CRUISE (CRZ) — "침로, 고도, 속도를 유지한다"
비행기는 현재 고도에서 직진하며, 스로틀은 자동입니다(노브 `CRUISE_SPEED`: 스로틀 30…55…85 %, 피토관이 있으면 **대기속도** 10…14…22 m/s). 롤 스틱으로 선회하고(놓으면 새 침로를 유지합니다), 피치 스틱으로 고도를 바꿉니다. 피토관이 있으면 실속 방지가 동작합니다. 침로는 GPS에서 가져오고(대지속도가 3 m/s를 넘을 때. 2 m/s 아래로 내려가면 나침반으로 돌아갑니다), GPS가 없으면 나침반, 그것도 없으면 자이로스코프에서 가져옵니다. 시뮬레이션에서는 4 m/s의 옆바람에서도 지상 항적이 ±5° 이내, 고도가 ±3 m 이내로 유지됩니다.
**필요한 것:** IMU + 기압계. 침로가 흘러가지 않게 하려면 GPS나 나침반이 필요합니다.

### LOITER (LOIT) — "여기서 선회한다"
모드를 켠 지점 위를 시계 방향으로 반지름 50 m(노브 `LOITER_RADIUS`는 25…150 m), 현재 고도에서 선회하며, 스로틀은 자동입니다. 유도는 벡터장 방식입니다. 멀리서는 접선 방향으로 원에 들어가고, 원 위에서는 선행 뱅크를 유지합니다. GPS가 없으면 그 자리에서 일정한 뱅크로 원을 그릴 뿐입니다.
**필요한 것:** IMU + 기압계 + GPS.

### RTH — "홈으로 귀환"
홈(ARM한 지점)으로 침로를 잡고, 고도는 `RTH_ALTITUDE_M` = 40 m입니다(그보다 낮으면 가는 도중에 상승하고, 높으면 그대로 유지합니다). 홈 위에서는 파일럿이 조종을 되찾을 때까지 LOITER 반지름으로 선회합니다. GPS나 홈이 없으면 그 자리에서 선회합니다. 통신 두절과 지오펜스도 같은 모드를 작동시킵니다.
**필요한 것:** IMU + 기압계 + 홈이 기록된 GPS.

### AUTO_TAKEOFF (TKOFF) — "스로틀로 이륙"
ARM 뒤에는 파일럿이 스로틀을 중간 위로 올릴 때까지 아무 일도 일어나지 않습니다. 그다음에는 프로그램이 진행됩니다. 날개를 수평으로 유지한 채 1초 동안 스로틀을 100 %까지 올려 가속하고, 피치 15°로 2초 동안 지면에서 떼어 올린 다음, 파일럿이 모드를 바꿀 때까지 피치 10°로 상승합니다. 스틱 조작은 프로그램 위에 더해지므로 이륙 활주 중에 침로를 바로잡을 수 있습니다.
**필요한 것:** IMU.

### LAUNCH (LNCH) — "손으로 던져 이륙"
1. ARM하고 스로틀을 중간 위로 올리면 발사가 **대기 상태**가 되며, 모터는 멈춰 있습니다.
2. 던지기: 전방 과부하가 1.5 g를 넘는 상태가 40 ms보다 오래 이어질 때.
3. 0.3초 뒤(손이 프로펠러에서 멀어진 뒤)에 스로틀 100 %, 피치 15°, 날개 수평으로 6초 동안 또는 30 m까지 상승합니다.
4. 그 뒤로는 도달한 고도에서 CRUISE와 같습니다.

던지기 전에 스틱을 조금이라도 움직이면(150 µs 초과) 발사가 취소되고, 비행기는 파일럿의 손에 돌아갑니다.
**필요한 것:** IMU(가속도계). 시뮬레이션에서는 손 높이에서 9 m/s로 던지면 비행기가 한 번도 땅에 닿지 않고 15초 동안 15 m 넘게 상승합니다.

### AUTO_LAND (LAND) — "착륙"
모터를 끄고 침로를 따라 피치 −4°로 활공하며, 기압계 기준 3 m 아래에서는 플레어(+4°)로 들어갑니다. 롤 스틱으로 진입 침로를 바로잡을 수 있습니다. 직선 구간에서, 맞바람을 받으며, 20–40 m 고도에서, 활주로에 여유를 두고 켜세요. 시뮬레이션에서는 접지 시 수직 속도가 1.5 m/s 미만이고, 날개는 수평이며, 기수부터 처박히지 않습니다.
**필요한 것:** IMU + 기압계(전원을 켤 때 지상에서 영점을 맞춘 것).

### SOARING (SOAR) — "서멀에서 소어링"
모터를 끄고 활공합니다. 승강계(피토관이 있으면 총에너지 방식이라 스틱을 당겨서 생기는 가짜 "서멀"이 나오지 않습니다)가 0.5 m/s를 넘는 상태가 1.5초보다 오래 이어지면 서멀로 판단하고 뱅크 25°로 선회합니다. 8초 평균 상승률이 −0.2 m/s 아래로 떨어지면 서멀에서 빠져나옵니다. 30 m보다 낮으면 100 m까지 모터를 씁니다. 홈에서 400 m보다 멀어지면 홈을 향해 활공합니다. 시뮬레이션에서는 서멀(중심부 3 m/s)을 찾아 모터 없이 50 m 넘게 상승합니다.
**필요한 것:** IMU + 기압계. 홈으로 돌아가려면 GPS가 필요합니다.

### RESCUE (RESQ) — "살려 줘"
날개 수평, 기수 +8°, 스로틀 70 %로 어떤 나선 강하에서든 회복합니다. 방향 감각을 잃었다면 스위치를 전환하고 한숨 돌리세요. 시뮬레이션에서는 뱅크 70°, 기수 −40°의 나선 강하에서 4초 안에 날개가 수평이 되고 상승으로 전환합니다.
**필요한 것:** IMU.

## 노브

노브의 중앙 = `Config.h`의 기본값이고, 양 끝은 최솟값과 최댓값입니다. 지정하지 않으면 기본값이 적용됩니다.

| 노브 | 최소 … 중앙 … 최대 | 적용 범위 |
|---|---|---|
| `STAB_GAIN` | ×0.25 … ×1 … ×2 | 안정화가 있는 모든 모드와 ACRO — "부드럽게/뻣뻣하게" |
| `MAX_BANK` | 15° … 45° … 60° | 스틱과 내비게이션의 최대 뱅크 각 |
| `CRUISE_SPEED` | 스로틀 30 … 55 … 85 %(피토관이 있으면 10 … 14 … 22 m/s) | CRUISE, LOITER, RTH, SOARING의 모터 |
| `FLAPS` | 플랩 0 … 50 … 100 % | 스위치 대신 부드럽게 조절하는 플랩 |
| `CAMERA_TILT` | −90° … 0° … +30° | 카메라 각도(AUX2) |
| `RATES` | 스틱 행정의 30 … 65 … 100 % | 모든 모드: 스틱 감도 |
| `LOITER_RADIUS` | 25 … 50 … 150 m | LOITER와 홈 위의 선회 |

> 유용한 요령: VrA에 노브 `STAB_GAIN`을 지정하면 비행 중에 계수를 "실시간으로" 맞출 수 있습니다. 흔들리면 줄이고, 둔하면 늘린 다음, 정해진 배율을 `Config.h`로 옮기세요.

## 통신 두절, 지오펜스, 홈

**홈**은 GPS가 좋으면(3D 픽스, 위성 ≥ 6개, 정확도 ≤ 5 m) ARM할 때 기록됩니다. ARM 시점에 GPS가 아직 위치를 잡지 못했다면, 잡는 즉시 홈이 기록됩니다. 현장에서 바꾸려면 `HOME_RESET` 기능을 쓰세요.

**통신 두절**(iBUS 프레임이 0.5초 넘게 오지 않거나 수신기가 950 µs 아래의 스로틀을 보낸 경우로, 조종기에서 설정한 failsafe입니다. `docs/PILOT_GUIDE.md` 참고):

| 상황 | 기체의 동작 |
|---|---|
| 지상(ARM되지 않음) | 모터 0, 조종면 중립. 10초 뒤 부저 |
| 공중, GPS와 홈이 있음 | 모터를 쓰는 **RTH**. 홈 위에서는 40 m 고도로 선회 |
| 공중, GPS 없음 | **활공**: 모터 정지, 날개 수평, 기수 −3° |
| 통신 복구 | 즉시 파일럿 스위치의 모드로 복귀 |

이미 시작된 귀환은 GPS가 잠깐 끊겨도 활공으로 바뀌지 않습니다. `FAILSAFE_RTH = false`이면 활공만 합니다.

**지오펜스**(`GEOFENCE` 또는 `GEOFENCE_ALWAYS_ON`): `FENCE_RADIUS_M`(500 m)보다 멀리 나가거나 `FENCE_ALTITUDE_M`(120 m)보다 높이 올라가면 RTH입니다. 조종을 되찾으려면 모드 스위치를 다른 위치로 전환하세요(모드는 위치가 바뀔 때 켜집니다). 비행기가 10 %의 여유를 두고 안쪽으로 돌아오면 다시 작동합니다.

## 직접 만드는 피토관

구매한 차압 센서 없이 대기속도를 얻는 방법: **기압계 두 개**.

```
              유입 기류 ─►  ┌──────────── 튜브(PVC/황동, Ø4–6 mm) ──┐
                            │  BMP581 (I2C 0x47) — 전체 압력        │  기밀
                            └───────────────────────────────────────┘
   동체: 메인 기압계(BMP581 0x46 / SPL06 / BMP388) — 정압

   속도  V = √(2·(P_tube − P_static − zero) / ρ),   ρ — 정압과 온도로 계산
```

**제작.** BMP581(주소 0x47 모듈: SDO 핀을 VCC에 연결)을 앞쪽만 열린 튜브 안에 붙입니다. 보드는 기밀 공간 안에 들어가고, 배선은 실런트를 통해 빼냅니다. 튜브는 앞을 향하게, 프로펠러 후류를 피해(날개 위나 기수 위) 설치합니다. 두 번째 기압계는 동체 안에 두고 직접 바람이 닿지 않게 막습니다(스펀지).

**펌웨어에서 켜기** — `sensors/SensorSelection.h`: `SENSOR_KIT_LSM6DSV_PITOT` 또는 `SENSOR_KIT_ICM45686_PITOT`(미리 만들어 둔 키트), 또는 직접 구성한 키트에서 `SENSOR_AIRSPEED = SENSOR_AIRSPEED_PITOT_BMP581`.

**영점.** 기압계 두 개는 항상 조금씩 어긋납니다. 각각의 절대 정확도는 수십 파스칼인데, 저속에서는 그것이 압력 차이의 전부입니다(10 m/s ≈ 60 Pa). 전원을 켠 뒤 첫 1초 동안 펌웨어가 그 차이를 평균 내어 영점으로 삼습니다. **전원을 켤 때 비행기는 정지해 있어야 하고, 튜브는 손가락이나 캡으로 막거나 바람 방향으로 돌려 둡니다.** OLED, 대시보드, 텔레메트리에는 영점을 잡은 뒤에 속도가 나타납니다.

**`PITOT_SCALE` 캘리브레이션.** 동체 안의 압력은 엄밀한 정압이 아닙니다. 바람이 없는 날 CRUISE로 직선을 왕복 비행한 다음, GPS의 평균 대지속도와 튜브의 속도를 비교하세요: `PITOT_SCALE = V_GPS / V_tube`.

**보호.** 압력 차이가 크게 음수인 상태가 2초를 넘거나(호스가 뒤바뀜, 물) 튜브의 측정값이 0.2초보다 오래되면 속도를 내보내지 않으며, 오토파일럿은 노브로 정한 스로틀과 대기속도 없는 침로 제어로 전환합니다. 두 기압계에 노이즈를 넣은 폐루프 시뮬레이션에서 검증했으며, 비행 중 속도 오차는 0.5 m/s 미만입니다.

튜브가 주는 것: CRUISE가 스로틀이 아니라 **대기속도**를 유지하고, 실속 방지, SOARING용 총에너지 승강계, 텔레메트리의 정직한 속도입니다.

## 지상국: Wi-Fi 대시보드와 MAVLink

**ESP32 — Wi-Fi 대시보드.** 액세스 포인트는 `OpenPlane-Debug`, 비밀번호는 `12345678`이며, 주소는 시리얼 모니터에 표시됩니다. 채널, 출력, 모든 센서, 모드, 내비게이션, 켜진 기능을 볼 수 있고 모드와 PID를 바꿀 수도 있습니다. 자세한 내용은 `docs/PILOT_GUIDE.md`를 참고하세요.

**STM32H743 — 무선 모뎀을 통한 MAVLink**(UART4: PD0 RX, PD1 TX, 57600 보 — SiK의 기본값). SiK 433/868/915 MHz, MAVLink 모드의 ELRS, Wi-Fi 브리지로 쓰는 ESP-01을 사용할 수 있습니다. **QGroundControl**과 **Mission Planner**는 이 기체를 ArduPilot 비행기로 인식합니다:

- 수평선, 홈이 표시된 지도, 속도(피토관이 있으면 그 값), 고도, 승강계, 스로틀.
- 모드는 ArduPlane의 이름으로 표시됩니다: STABILIZE → FBWA, ALT_HOLD → FBWB, CRUISE → CRUISE, LOITER → LOITER, RTH → RTL, AUTO_TAKEOFF/LAUNCH → TAKEOFF, SOARING → THERMAL, RESCUE → STABILIZE, AUTO_LAND → AUTO. failsafe는 RTL이나 CIRCLE로 표시됩니다.
- 메시지 목록: ARM/DISARM, 모드 전환(OpenPlane의 이름으로), 통신 두절, 지오펜스.
- **지상에서의 모드 전환**: GCS의 모드 버튼으로 합니다(AUTO 제외. OpenPlane에는 미션이 없습니다).
- **파라미터** `RLL_KP … PTCH_KD`: 롤과 피치의 PID로, 비행 중에도 GCS의 파라미터 창에서 읽고 바꿀 수 있습니다(재부팅하면 저장되지 않으므로, 좋은 값은 `Config.h`로 옮기세요).

지상에서 보낸 ARM/DISARM은 **거부됩니다**. 조종기의 스위치로만 가능합니다. 하드웨어 없이 데이터 스트림을 확인하려면: `OPENPLANE_MAVLINK_DUMP=/tmp/tlm.bin pio test -e native -f native/test_mavlink && python3 tools/check_mavlink.py /tmp/tlm.bin` (`pip install pymavlink`가 필요합니다).

## 새 비행기 설정 순서

1. **지상에서 MANUAL:** 조종면 방향(`Config.h`의 `*_REVERSED`), 플랩을 아래로, AUX. 출력 점검은 콘솔의 `p`로 합니다(프로펠러를 빼 두세요!).
2. **지상에서 센서:** `b`는 버스 조회, `s`는 상태, `o`는 IMU 설치 캘리브레이션(3가지 자세, 한 번만), `m`은 나침반입니다.
3. **지상에서 STABILIZE:** 비행기를 오른쪽으로 기울이면 오른쪽 에일러론이 **아래**로 움직여야 합니다(수평으로 되돌리려고). 기수를 들면 승강타는 아래로 움직입니다. 그렇지 않다면 리버스 설정이나 IMU 설치가 뒤바뀐 것입니다.
4. **첫 비행은 MANUAL로**, 50 m 이상 올라간 뒤 STABILIZE로 전환합니다. 흔들리면 `STAB_GAIN`을 낮추고, 둔하면 높입니다.
5. 수평 비행에서 **AUTO_TRIM**을 20–30초 동안 작동시키고, 착륙해 DISARM합니다. 트림이 저장됩니다.
6. **ALT_HOLD**, 그다음 **CRUISE**로 고도와 침로를 확인합니다. 피토관이 있으면 `PITOT_SCALE`을 캘리브레이션합니다.
7. **LOITER**와 **RTH**는 충분한 고도에서, 시야 안에서, 손가락을 MANUAL에 올려 두고 시험합니다.
8. 그런 다음에야 **failsafe 시험**(높은 곳에서 조종기를 끄면 비행기가 홈으로 가야 합니다)과 자동 이륙/착륙을 해 봅니다.

## 오토파일럿 비행 전 점검

- [ ] 전원을 켤 때 출력된 배치가 기대한 그대로입니다.
- [ ] 콘솔/OLED: IMU ok, IMU 비행 전 점검을 통과했습니다(전원을 켤 때 비행기가 정지해 있었습니다).
- [ ] 기압계가 지상에서 영점을 맞췄습니다(OLED의 고도가 ~0).
- [ ] 피토관이 있으면: 지상에서 속도가 ~0이고, 튜브에 바람을 불면 올라갑니다.
- [ ] GPS: **ARM 전에** 3D 픽스, 위성 ≥ 6개여야 합니다. 그렇지 않으면 홈도 RTH도 없습니다.
- [ ] 지상에서의 STABILIZE: 에일러론과 승강타가 비행기를 수평으로 되돌리는 방향으로 움직이고, 더 기울이는 방향으로는 움직이지 않습니다.
- [ ] 조종기에 failsafe가 설정되어 있고(통신 두절 시 스로틀 950 미만), **지상에서** 프로펠러 없이 조종기를 꺼서 확인했습니다.
- [ ] MANUAL이 손가락 아래에 있습니다.
