# COPTER.md — 멀티콥터용 펌웨어

같은 펌웨어, 같은 보드(Matek H743-WING V3, DevEBox H743), 같은 센서와 수신기입니다. 다만 비행기 대신 쿼드콥터, 헥사, 옥토, Y6, X8을 날립니다. Betaflight, INAV, ArduPilot과 가장 큰 차이는 **PID, 필터, 아이들, 레이트를 손으로 조정하지 않는다**는 점입니다. 콥터의 구성(프레임, 프로펠러, 모터, 배터리, 질량)을 기술하면 펌웨어가 물리 모델로부터 설정을 스스로 도출하고, 모델이 부정확하게 추정한 부분은 비행 중에 스스로 맞춥니다.

> **솔직히 말씀드리면.** 콥터 펌웨어는 지금까지 시뮬레이터(6자유도 모델, 12개 구성 × 3가지 “틀린” 물리)와 보드용 빌드로만 확인했습니다. 아직 하늘을 날아 본 적이 없습니다. Betaflight나 ArduPilot보다 더 잘 난다고 말할 수 있는 것은 비행 시험 이후입니다. 그때까지 이것은 사실이 아니라 목표입니다.

## 동작 방식

```mermaid
flowchart LR
    D["콥터 기술<br/>프레임 · 프로펠러 · 모터<br/>배터리 · 질량"] --> M["추진계 모델<br/>Propulsion.h"]
    M --> T["설정<br/>Presets.h"]
    T --> C["CopterController<br/>1 kHz"]
    G["자이로<br/>회전수 노치 · 로우패스"] --> C
    C --> X["믹서<br/>airmode · 추력 선형화"]
    X --> E["변속기(ESC)<br/>PWM · OneShot · Multishot"]
```

1. **추진계 모델**(`copter/Propulsion.h`): 역기전력과 권선 저항(KV와 스테이터 부피로부터)을 가진 모터, 프로펠러의 추력과 토크(지름, 피치, 블레이드 수로부터), 프로펠러를 포함한 로터의 관성. 6S의 5" 2207 1950KV에서 모델은 풀 스로틀에서 약 28 000 rpm, 약 1.6 kg 추력, 약 45 A를 냅니다. 시험대 값과 같습니다.
2. **그로부터 나오는 것**(`copter/Presets.h`): 호버링 스로틀, 아이들/호버링/풀 스로틀에서의 회전수, 모터 지연 τ, 프레임 관성 모멘트, 추력 대 중량비, 전류.
3. **각속도 루프**는 주파수 응답으로 선택합니다. 모터, 필터, 노치, 제어 주기와 ESC 지연이 모두 모델에 들어 있습니다. 교차 주파수는 위상 여유 50°(요는 55°)와 **이득 여유 12 dB**를 만족하는 가장 높은 값입니다. 추력과 관성이 두 배 “틀린” 콥터도 버티는 설정입니다. D의 비율은 탐색으로 고릅니다. 루프가 가장 넓어지는 값입니다. P, I, D와 피드포워드(FF)는 교차 주파수에서 나옵니다.
4. **스로틀에 따른 이득 보정(TPA)**도 같은 모델에서 나옵니다. 낮은 스로틀에서는 모터 응답이 약하고, 높은 스로틀에서는 강합니다.
5. **비행 중** 펌웨어는 호버링 스로틀을 스스로 학습하고(더 무거운 배터리, 짐벌) 노치를 회전수에 맞춰 옮깁니다.

## 나만의 콥터

`include/config/CopterConfig.h`:

```cpp
#define COPTER_BUILD "freestyle5"     // 카탈로그에서 가장 가까운 구성
constexpr float MASS_G = 742;          // 배터리 포함 무게 — 가장 중요합니다
constexpr float PROP_DIAMETER_IN = 5.1f, PROP_PITCH_IN = 3.6f;
constexpr float MOTOR_KV = 2150;       // 0 — 구성 그대로
constexpr copter::EscProtocol ESC_PROTOCOL = copter::EscProtocol::ONESHOT125;
```

구성은 빌드 플래그로도 고를 수 있습니다: `-D COPTER_BUILD=\"race5\"`. 펌웨어를 업로드한 뒤 콘솔에서 `t` 키를 누르면 도출된 내용이 표시되고, 문제가 있으면 경고합니다: 추력이 부족함, 모터가 이 프로펠러를 감당하지 못함, 이웃한 프로펠러끼리 닿음, 호버링이 스로틀 60%를 넘음, 모터가 제어 주기의 절반보다 빨리 회전함.

## 펌웨어 업로드와 첫 시동

```bash
pio run -e matek-h743-quad -t upload          # Matek H743-WING V3: BOOT 버튼 + USB
pio run -e stm32h743-devebox-quad -t upload   # DevEBox H743
```

모터 출력은 순서대로 Matek — S1…S8, DevEBox — PA0–PA3, PD14, PD15, PE9입니다. **첫 시동은 프로펠러 없이**, 시리얼 모니터 115200에서:

| 키 | 동작 |
|---|---|
| `t` | 설정: 추력, 호버링, 회전수, 모터 τ, 필터, 루프 대역폭과 여유, P/I/D/FF, 레이트, 경고 |
| `m` | 모터 테스트: `y`로 확인을 요청하고(프로펠러 제거!), 각 모터를 2 s씩 돌리며 위치와 돌아야 할 방향을 알려 줍니다 |
| `s` | 상태와 **시동이 걸리지 않는 이유** — 이유마다 문장으로 |
| `o` | 세 가지 자세로 보드 장착 보정(Matek에서는 ARM 전에 필수) |
| `i` · `r` · `l` · `D` | 자이로 · 조종기 채널 · 실시간 줄 · DFU 부트로더 |

엉뚱한 모터가 돌면 `CopterConfig::MOTOR_PINS`의 순서를 바꿉니다. 반대로 돌면 ESC 설정 도구(BLHeliSuite, ESC-Configurator)에서 방향을 바꿉니다. 배선을 다시 납땜하지 않습니다.

## 조종기와 모드

모드 2: CH1 롤, CH2 피치, CH3 스로틀, CH4 요. **ARM** — SwA(CH5), 비행기와 같습니다. **모드** — SwC(CH7):

| SwC | 모드 | 스틱의 역할 |
|---|---|---|
| 위 | ANGLE | 기울기(스타일의 한계까지). 놓으면 콥터가 스스로 수평이 됩니다. 요는 수직축 기준 |
| 가운데 | ALT_HOLD | ANGLE + 고도 유지: 스로틀 가운데 — 호버링, 위/아래 — 최대 3 m/s 상승, 최대 2 m/s 하강 |
| 아래 | ACRO | 레이트 곡선에 따른 회전 각속도. airmode — 스로틀 0에서도 조종됩니다 |

HORIZON(가운데 부근은 ANGLE, 끝에서는 ACRO)은 `CopterConfig.h`의 한 줄을 바꾸면 켜집니다.

## 보호 기능

- **ARM**은 다음 조건에서만 됩니다: 링크가 있음, 스로틀이 아래, 콥터가 수평(25°까지)이고 움직이지 않음, 자이로가 응답함, 자세가 결정됨, 배터리가 비지 않음, 모터 테스트 중이 아님, 보드 장착이 보정됨(필요한 경우). 너무 일찍 켠 ARM 스위치는 껐다가 다시 켜야 합니다.
- **ARM 스위치를 내리면 같은 주기 안에 모터가 멈춥니다.** 모든 모드에서 같습니다.
- **신호 상실**: 0.3 s까지의 끊김에는 아무것도 바뀌지 않습니다. 더 길면 지상에서는 즉시 DISARM, 공중에서는 수평을 잡고 0.7 m/s로 하강(기압계로, 없으면 가속도계로)하며 접지하면 DISARM합니다. 링크가 1 s 동안 돌아오면 조종은 다시 조종사에게 넘어갑니다.
- **사고**: ANGLE/ALT_HOLD에서 90°를 넘는 기울기가 0.7 s 이상 계속되거나, 스틱이 요구하는 기울기와 30° 이상 차이가 2 s 이상 계속될 때(모터 고장, 옆으로 넘어짐), 어떤 모드에서든 1 s 동안 뒤집혀 있을 때 — 모터가 멈춥니다. 다시 ARM하려면 먼저 스위치를 꺼야 합니다.
- **지상에서는 적분이 쌓이지 않습니다** — 이륙할 때 콥터가 튀거나 넘어지지 않습니다.

## 어떻게 확인했는가

`test/native/test_copter_sim` — **실제** `CopterController`와 6자유도 콥터 모델: 역기전력을 가진 모터, 전류에 따른 배터리 전압 강하, 프로펠러 반동 토크, 공기 저항, 돌풍이 있는 바람, ESC 지연, 노이즈와 모터 진동이 있는 자이로(제어 주기의 절반을 넘는 진동은 보드에서처럼 접혀 들어옵니다), 50 Hz 기압계, 지면. 카탈로그의 각 구성은 자기 설정으로 날고, 일부러 기술과 맞지 않게 만든 모델로도 납니다:

- **“둔한”**: 프로펠러 추력 20% 적음, 모터와 프레임 관성 30% 큼, 20% 더 무거움, 무게 중심이 앞으로 이동;
- **“예민한”**: 추력 +20%, 관성 −30%, 질량 −15%, 무게 중심이 옆으로 이동 — 루프 이득이 계산값의 거의 두 배입니다.

| 항목 | 36회 비행(12개 구성 × 3가지 물리)의 결과 |
|---|---|
| ALT_HOLD 이륙과 호버링 | 고도 ±0.3 m, 기울기 < 1°, 호버링 스로틀 학습(“예민한” whoop: 계산값 0.31 대신 0.22) |
| ANGLE: 스틱 최대 | 기울기의 90%까지 0.14–0.35 s, 오버슈트 < 3%, 0.15–0.4 s 안에 3° 이내로 수평 복귀 |
| ACRO: 스틱 최대 | 레이트의 90%까지 0.04–0.15 s, 오버슈트 < 12% |
| 10 m에서 신호 상실 | 하강 ≤ 0.94 m/s, 접지 — DISARM, 17–28 s |

그리고 5"에서 따로: 스로틀 0에서의 airmode, 요, 4.5 m/s 돌풍, 기압계 없는 failsafe, 일반 PWM ESC, 링크 끊김과 복귀, 뒤집혀 추락, 모터 고장, 모터 테스트, 배터리 전압 강하. `test_copter`는 각 블록을 따로 확인하고(테스트 41개), `native_stm32/test_app_stm32_copter`는 Matek H743 가짜 환경에서 펌웨어 전체를 돌립니다: ARM 전 “정지” 펄스, 장착 보정, ARM 후 아이들, 스위치로 모드 전환, 지상 신호 상실, 콘솔.

시뮬레이터는 계산에서는 보이지 않는 실제 버그를 찾아내고 고치는 데 도움을 주었습니다: 믹서 주기마다 튀던 노치, 루프 대역폭 근처 노치가 만든 추가 위상 지연, “둔한” 헥사가 가속하는 동안 쌓인 적분(오버슈트 32%), 호버링 스로틀에서 플립할 때 정확히 1 g를 가리켜 수평선을 10° 끌고 가던 가속도계, 모터가 고장 난 채 지상에서 계속 돌던 콥터.

## 아직 없는 것

- **DShot**(양방향 포함 — 노치를 위한 정확한 회전수): DMA 드라이버가 필요합니다. 프레임과 CRC 계산은 이미 있습니다(`copter/EscProtocol.h`).
- **1 kHz보다 빠른 제어 주기** — 모터가 500 Hz보다 빨리 도는 whoop용(시뮬레이션에서 4 kHz일 때 확실히 좋아집니다).
- 콥터용 블랙박스, MAVLink, OpenPlane Studio. GPS 위치 유지, 귀환, 미션.
- 비행 시험.
