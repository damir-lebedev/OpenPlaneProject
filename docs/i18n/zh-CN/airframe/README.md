# Astro-Cargo 机体：模型与打印文件

> 🌐 本页是[俄语原文](../../../../airframe/README.md)的译文。译文与原文如有出入，以原文为准。固件的控制台信息以俄语输出，因此文中照原样引用。

这里存放飞机本体：Fusion 360 项目和用于 3D 打印的 STL 文件。电子部分和飞控板见 [FC_BOARD.md](../FC_BOARD.md)，组装和首飞见[飞手指南](../PILOT_GUIDE.md)。

## 模型版本：v2

本文件夹中存放的是 **Astro-Cargo v2**。仓库中不会有 v1：第一版模型不公开发布，因此第二版成了第一个公开的版本。

- [Fusion 360 项目](../../../../airframe/fusion360/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.f3d)，14 MB；
- [用于打印的 STL 文件](../../../../airframe/stl/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.stl)，6 MB。

文件名直接写明了这一版本的问题所在（详见下文）。

> [!WARNING]
> **v2 存在严重的结构设计缺陷：**
>
> 1. **起落架与机身的连接过于薄弱。** 连接处承受不住飞机的重量，机身会在连接处撕裂。
> 2. **没有用于固定电池的魔术贴绑带的安装位。**
>
> 这两个缺陷都会在下一个原型机 **Astro-Cargo v3** 中修复。v3 的模型一旦完成就会放到这个文件夹里。在此之前，请勿在未改进的情况下让 v2 升空：请自行加固起落架的连接处，并自行为魔术贴绑带留出安装位置。

## 文件位置

| 文件夹 | 内容 |
|---|---|
| [`fusion360/`](../../../../airframe/fusion360/) | 源工程：`.f3d` 文件（如果工程包含多个文件，则为 `.f3z` 压缩包）。可以在其中修改尺寸并重新导出零件 |
| [`stl/`](../../../../airframe/stl/) | 可直接打印的零件，STL 格式 |

## 文件命名规则

- 名称使用拉丁字母，并带上版本号。v2 的文件名特意写明了缺陷，但今后最好避免使用空格和括号：`astro-cargo_v3.f3d`、`astro-cargo_v3.stl`，这样在文档中引用文件更方便。如果有多个零件，每个零件各用一个文件：`fuselage_v3.stl`、`wing_left_v3.stl`。
- v3 的文件将放在旁边（`astro-cargo_v3.f3d`），v2 的文件仍会保留，方便对照看出具体修复了什么。
- 单位为毫米。如果工程使用其他单位，请在文件旁注明。

## 文件太大怎么办

GitHub 不接受大于 100 MB 的文件，从 50 MB 起就会发出警告。因此提交前请先检查文件大小。这类文件不要放进仓库，而应放到以下位置之一：

- GitHub 的 **Releases** 栏目：文件可以作为附件挂在发布版本上，单个文件最大可达 2 GB；
- [Git LFS](https://git-lfs.com)：适用于需要直接放在仓库里、并随代码一起更新的文件；
- 外部托管服务，并把链接添加到本 README 中。

本文件夹中的 `.stl`、`.f3d`、`.f3z`、`.step`、`.stp` 和 `.3mf` 文件会被 git 视为二进制文件（见 [`.gitattributes`](../../../../.gitattributes)）：git 不会修改其中的换行符，也不会显示逐行差异。
