## 需要哪些硬件

当前这套配置（固件就是在它上面验证的）：

- **STM32H743 开发板 DevEBox H743**（MCUDEV）——主力板。之前的主力板，即下面的 ESP32-S3，也仍然支持。
- **ESP32-S3 N16R8 开发板**（DevKitC-1 的仿制板，有两个 USB-C 口：“USB”和“COM”）。
- **FS-i6 遥控器 + FS-iA6B 接收机**（iBUS 协议，10 个通道）。只需要一根数据线——iBUS SERVO 接口。遥控器必须能设置 failsafe，这项设置是必需的，见 failsafe 一节。
- **或其他遥控器，配 SBUS 接收机**（FrSky、Futaba、RadioMaster、Jumper……）**或 CRSF 接收机**（ExpressLRS、TBS Crossfire）——协议在 `Config.h` 中选择（`RX_PROTOCOL`），接线见下文。
- **2 个 MG90S 舵机**用于副翼——每侧机翼各一个（两个独立舵机，而不是两侧机翼共用一个）。
- **1 个 MG90S 舵机**用于升降舵。
- **1 个 MG90S 舵机**用于方向舵——起落架的转向轮装在它的同一根轴上（地面滑行转向）。起落架：前面两个轮子，加一个可转向的尾轮（`Config.h` 里的 `LANDING_GEAR = TAIL_WHEEL`；前轮式起落架为 `NOSE_WHEEL`）。
- **电调（ESC）BLHeli 80A，双向**（Bidirectional/3D 模式），带 5 V BEC（BEC 给舵机和接收机供电）。普通的单向电调也能用——在 `Config.h` 里设 `ESC_BIDIRECTIONAL = false`，见[电机反转](#电机反转-swd)。
- **D3548 1100KV 电机** + **10x5 螺旋桨**。
- **3S 锂聚合物电池**。

自动驾驶仪的传感器（全部走 I2C；没有它们时，飞机以手动模式飞行）：

- **GY-521**——陀螺仪 + 加速度计（板上可能是 MPU6050，也可能像我们这样是 MPU6500，两种都支持）。
- **BMP581**——气压计（之前的 BMP388 也支持）。
- **GY-273**——罗盘（我们这块上是 QMC5883P；QMC5883L 也支持）。
- 可选的 **OLED 128×64 SSD1306**（I2C）——机上状态屏。

机体：翼展 1200 mm，翼弦 250 mm，NACA 4412 翼型，PETG 结构（3D 打印）。第一架原型机用的是 ESP32-C3、D2212 1000KV 电机和 40 A 电调。

## 选择开发板与引脚分配

固件支持四种开发板；切换只需一个构建参数（`pio run -e <环境名>`）。每块板的引脚分配各不相同，并且针对具体的构建环境写死在固件里——不要自作主张挪线，请对照自己那块板的表格。

> **重要**：现在的主力板是 **STM32H743 (DevEBox H743)**——已在它上面验证了启动、USB 控制台、SD 卡、iBUS、舵机和电机；传感器是第一次接上去。**esp32-s3 (N16R8)** 是之前的主力板，它的引脚分配已在装有全部传感器的台架上验证。**esp32-c3** 是飞过的旧原型机。**esp32-dev** 的引脚分配是根据芯片文档选定的，**没有在真实硬件上验证过**。

### STM32H743 (DevEBox H743)——主力板

`pio run -e stm32h743-devebox`，开发板 MCUDEV DevEBox H743（STM32H743VIT6）。这是默认开发板（`default_envs = stm32h743-devebox`）。已在它上面验证了启动、USB 控制台、SD 卡和黑匣子、iBUS 接收、ARM、用遥控器控制舵机和电机；传感器是第一次接上去。

| 用途 | 引脚 |
|---|---|
| 副翼，左侧机翼 | PA0 |
| 副翼，右侧机翼 | PA1 |
| 升降舵 | PA2 |
| 电调（油门） | PA3 |
| 方向舵 + 转向轮 | PD14 |
| 接收机（RX）：iBUS、SBUS、CRSF | PE7 |
| 传感器 I2C SDA / SCL（MPU、BMP581、罗盘） | PB11 / PB10 |
| OLED 的 I2C SDA / SCL（独立总线） | PB9 / PB8 |
| GPS：RX（← GPS 的 TX）/ TX（→ GPS 的 RX） | PD9 / PD8 |
| MAVLink 遥测（数传电台）：RX / TX | PD0 / PD1 |
| AUX1 / AUX2（舵机）、蜂鸣器 | PD15 / PE9, PE15 |
| 传感器 SPI SCK / MISO / MOSI，IMU 的 CS / 气压计的 CS | PB13 / PB14 / PB15, PB12 / PD10 |
| 电池 / 电流传感器（ADC，由黑匣子记录） | PC0 / PC1 |

控制台、日志和黑匣子下载都走开发板的 USB-C（虚拟 COM 口）。不要占用：PA11/PA12（USB）、PA13/PA14（SWD）、PC8–PC12 和 PD2（µSD 卡槽）、PE3 和 PC5（K1/K2 按键）。

台架上的传感器接线（所有模块都用 **3.3 V** 供电，不是 5 V）：

| 模块 | 引脚 |
|---|---|
| MPU-6050 / GY-521（板上可能是 MPU6500——这是正常的） | VCC–3.3V, GND–GND, SCL–PB10, SDA–PB11, AD0–GND, INT/XDA/XCL——不接。单独的 MPU-6500 模块（10 个引脚）：接法相同，另外 **NCS–3.3V**（否则芯片会切换到 SPI）、FSYNC–GND，EDA/ECL——不接。芯片朝上，X 轴箭头指向机头；芯片坐标轴的旋转由 `Config.h` 中的 `IMU_ROTATION_CW_DEG` 设定（我们这块仿制板上是 90） |
| BMP581 | VCC–3.3V（**只能接 3.3V**：很多模块没有自己的稳压器）, GND–GND, SCL–PB10, SDA–PB11, **SDO–GND**（地址 0x46；不要悬空）, **CSB–3.3V**（否则芯片会切换到 SPI）, INT——不接 |
| GY-273 (QMC5883P) | VCC–3.3V, GND–GND, SCL–PB10, SDA–PB11, DRDY——不接。远离舵机、电调和电机的导线 |
| OLED 128×64 SSD1306 | VCC–3.3V, GND–GND, SCL–PB8, SDA–PB9 |

舵机**不由开发板供电**，而是由电调的 BEC（或另一个不低于 2 A 的 5 V 电源）供电；所有电源的地线共地。USB 插着的时候，不要把电调的红线接到开发板的 5 V 上。

## 连接接收机

接收机用一根数据线接到你的板子表格中的**接收机 RX 引脚**（`PIN_RC_RX`：DevEBox 上为 PE7，esp32-s3 上为 GPIO17，esp32-c3 上为 GPIO8，esp32-dev 上为 GPIO16）。协议要与接收机一致，由 `Config.h` 中的 `RX_PROTOCOL` 设定（在 OpenPlane Studio 中为“遥控器”步骤）：

| `RX_PROTOCOL` | 接收机 | 接线 |
|---|---|---|
| `IBUS`（默认） | FlySky FS-iA6B、FS-iA10B | iBUS SERVO 端口（iBUS 输出）→ RX 引脚 |
| `SBUS` | FrSky、Futaba、RadioMaster、Jumper 及大多数其他品牌 | SBUS 输出 → RX 引脚；不需要反相器——板子的 UART 自己反相信号 |
| `CRSF` | ExpressLRS、TBS Crossfire 和 Tracer | 接收机 TX → RX 引脚；接收机 RX 可接到 TX 引脚（`PIN_RC_TX`）——暂未使用 |

- **接收机地线（GND）** → **板子 GND**。必须连接，没有共地协议无法工作。
- **接收机供电**——5 V，来自独立的 BEC/稳压器或板子的 5V。

端口速率由固件设定：iBUS——115200 波特，SBUS——100000（8E2），CRSF——420000（ExpressLRS 的默认值）。EdgeTX 遥控器按 FS-i6 的方式设置（见下面的通道表）：CH5——ARM，CH6–CH8——拨动开关，CH9–CH10——旋钮。

## RC 通道表

此表已用 FS-i6 遥控器（10 通道，模式 2，即美国手）和 FS-iA6B 接收机在台架上验证。

| 通道 | 遥控器上的操作件 | 名称 | 作用 |
|---|---|---|---|
| CH1 | 右摇杆 ←→ | AILERON | 横滚——副翼（2000 = 向右） |
| CH2 | 右摇杆 ↑↓ | ELEVATOR | 俯仰——升降舵（2000 = 推杆向前，机头向下） |
| CH3 | 左摇杆 ↑↓ | THROTTLE | 油门。1000 µs = 关闭，2000 µs = 最大，无限制 |
| CH4 | 左摇杆 ←→ | RUDDER | 方向舵和起落架转向轮（同一个舵机） |
| CH5 | SwA | ARM | ARM 开关——见下文 ARM 一节 |
| CH6 | SwB | SWB | 默认是襟翼：向下（拨向自己）为放下，向上为收起（见下文） |
| CH7 | SwC（3 档） | SWC | 默认是模式：向上 MANUAL，中间 STABILIZE，向下 AUTO_TAKEOFF |
| CH8 | SwD | SWD | 默认是电机反转，只在上锁（DISARM）时切换（见下文） |
| CH9 | VrA | VRA | 默认是增稳强度 |
| CH10 | VrB | VRB | 默认是巡航速度 |

CH6–CH10 在 `include/config/Controls.h` 中**只需一行就能随意指定**：12 种模式、11 项功能（襟翼、减速板、载荷投放、地理围栏、蜂鸣器、反转……）和 8 个旋钮中的任意一个。开发板上电时，实际的分配方案会打印到串口监视器。关于模式和绑定的全部内容见 [AUTOPILOT_GUIDE.md](AUTOPILOT_GUIDE.md)。

所有通道值都使用接收机标准的 1000–2000 µs 脉宽范围，1500 µs 为中位/中立。

### 襟翼（襟副翼）

没有单独的襟翼，由副翼来充当。**SwB 向下**（拨向自己）：两侧副翼会平滑地、用大约一秒钟下偏相同的角度（`FLAPS_DEPLOYED_US` = 220 µs ≈ 摇臂转动 20°，可在 `include/config/Config.h` 中修改）。这会增加升力，使起飞和降落可以用更低的速度。用摇杆和自动驾驶仪控制横滚的方式照常工作——副翼向相反方向偏转，只不过现在是围绕着下偏后的位置。**SwB 向上**时，它们同样平滑地收回。放下襟翼时，OLED 第一行会亮起 `FL`。

放下襟翼并大幅度横滚时，下偏的那侧副翼会比上偏的那侧更早到达行程末端——这是正常的，相当于副翼差动。

放下襟翼通常会让机头抬起——请准备好把杆稍微向前推；如果效果明显，可以通过减小 `FLAPS_DEPLOYED_US` 来调整。

## 自动驾驶仪通道

简要说明——默认分配（`include/config/Controls.h`）：

| 开关 | 作用 |
|---|---|
| **SwC**（CH7） | 向上 **MANUAL** · 中间 **STABILIZE** · 向下 **AUTO_TAKEOFF** |
| **SwD**（CH8） | **电机反转**——只在 DISARM 时（要把 RTH 放回开关上只需一行） |
| **SwB**（CH6） | 襟翼 |
| **VrA / VrB**（CH9/10） | 增稳强度 / 巡航速度 |

- **STABILIZE——“摇杆设定角度”。** 摇杆打满是横滚 45°、俯仰 25°；松开后飞机自己回到水平。油门由你控制。
- **AUTO_TAKEOFF。** 从跑道分阶段起飞。ARM 之后电机不转，直到你把油门推过一半；飞机用约 1 s 检查自己是否和校准时停得一样，然后全部自动完成：升降舵下压抬尾、滑跑、靠机翼离地、爬升到 30 m，之后保持航向和高度。油门归程序控制；离地前把油门杆拉到底即中止起飞。需要先做[飞机地面校准](#飞机地面校准水平基准和停机姿态)。
- **RTH。** 航向指向 ARM 点，高度 40 m，到达起点上空后盘旋。需要在**解锁前**就有 3D 定位的 GPS。

全部 12 种模式（ALT_HOLD、ACRO、CRUISE、LOITER、手抛 LAUNCH、AUTO_LAND、SOARING、RESCUE……）、每种模式需要哪些传感器，以及如何把它们挂到开关上，见 [AUTOPILOT_GUIDE.md](AUTOPILOT_GUIDE.md)。从仪表盘或地面站选定的模式会一直保持，直到你拨动模式开关。

飞机**未解锁**时，增稳也会让舵面动作——这样在桌面上就能看出它对倾斜的反应方向。此时积分器不会累积。

角度的符号（与 OLED 和日志上相同）：**横滚 R > 0——右翼向下，俯仰 P > 0——机头向上。**

## 解锁（ARM）与 failsafe

### ARM 流程

- **ARM**：油门（CH3）拉到最低 → 把 **SwA（CH5）拨下，拨向自己**（在 FS-i6 上这表示 CH5 = 2000；向上 = 1000）。串口会出现 `ArmingManager: ARM`，OLED 上显示 `ARMED`。
- **DISARM**：SwA 拨上，推离自己——立即生效，任何时候都可以，电机马上停转。
- 如果在油门没有拉到最低的情况下把 SwA 拨到 ARM，或者飞行前检查没有通过，就**不会**解锁（原因会打印在串口）。需要把 SwA 拨回上面，收油门，再重新拨下。
- 如果开发板上电时 SwA 已经在 ARM 位置（向下），它**不会**解锁：固件必须先看到 SwA 在上面（OFF）。

**ARM 真的会锁住油门**：飞机未解锁时，无论摇杆在什么位置，电调的油门都被强制保持为零（双向电调上就是 1500 µs 的中立脉冲）。解锁前，固件会检查所选模式需要的传感器是否有响应——例如，没有正常工作的 IMU 时无法在 STABILIZE 下解锁，需要先切换到 MANUAL。尽管如此，还是请时刻当作螺旋桨在 ARM 之后随时可能转起来。

### 电机反转 (SwD)

主电调是双向的 BLHeli 80A：电机可以正反两个方向转，**SwD 向下**——反转，向上——正转。反转用于在地面上倒车滑行。

- **方向只在 DISARM 时才会改变。** 解锁状态下拨动 SwD 不会有任何反应（串口打印 `MotorReverse: реверс НЕ переключён`——“反转未切换”），电机照原样转。新方向在上锁后才生效。这样就不可能在满油门时打开反转，把电调和电机烧掉。
- **改变方向后 3 秒内不能 ARM**（`REVERSE_SETTLE_MS`）：如果是带着油门上锁的，电机还在惯性转动——先让它停下来。这段时间里 ARM 会被拒绝，原因打印到串口。
- **反转时只用你的油门，而且不超过 50%**（`REVERSE_THROTTLE_LIMIT_PCT`）：摇杆推满 = 一半功率。反转时自动驾驶仪不碰油门（舵面照常工作），失去信号时电机直接停转。
- 在 OLED 上能看到（第一行的 `REV`），仪表盘上也有（徽标“Мотор: РЕВЕРС”——“电机：反转”）。

**在 BLHeliSuite 中设置电调**（只需一次，拆下螺旋桨）：Motor Direction——**Bidirectional**（BLHeli_32 上是“Bidirectional”/3D），PPM Min Throttle——1000，PPM Max Throttle——2000，Center——1500。电调看到 1500 µs 的中立信号后解锁，固件从第一个脉冲起就输出这个信号。如果推油门时电机转向不对，在 `Config.h` 中设 `MOTOR_REVERSED = true`（一行代替重新焊线）。

普通的单向电调：在 `Config.h` 中设 `ESC_BIDIRECTIONAL = false`，否则在“停止”（1500）时它会给出一半油门！这种情况下反转永远不会启用。

### Failsafe

失去信号拥有**绝对优先级**，高于其他一切：

- **飞机已解锁，有 GPS 和起点**——**带动力返航**（与 ArduPilot/INAV 相同）：航向指向起点，高度 40 m，到起点上空后盘旋，直到信号恢复。OLED 上显示 `FSRTH`。可以通过 `Config.h` 中的 `FAILSAFE_RTH = false` 关闭；
- **飞机已解锁，没有 GPS**——**滑翔**：电机关闭，自动驾驶仪在任何模式下（即使是 MANUAL）都会保持机翼水平、机头略低于地平线（−3°），襟翼收起。OLED 上显示 `RX LOST ... GLIDE`。如果把 `FAILSAFE_GLIDE_ROLL_DEG` 设为 10–20，飞机会以平缓的螺旋在你上空盘旋；
- **电机处于反转**——无论如何电机都关闭，自动驾驶仪只用舵面操纵（返航靠滑翔）；
- **未解锁**（在地面上）或 IMU 无响应——电机关闭，副翼、升降舵和方向舵回到中立位（1500 µs）；失去信号 10 s 后，“我在这里”蜂鸣器会鸣响（如果焊了的话）。

固件通过三种方式识别失去链路：

1. **超过 500 ms 没有来自接收机的帧**——断线、接收机未上电，或接收机在失去链路时停止发送（ExpressLRS 默认如此）。
2. **接收机自己报告失去链路**——SBUS 帧中的 failsafe 标志、CRSF 的链路质量为 0 %。无需任何设置。
3. **油门低于 950 µs**——接收机用这种方式报告它丢失了遥控器。**这需要在遥控器里设置 failsafe**（见下文）：失去信号时，FS-iA6B 并不会停止发送帧，而是重复最后的摇杆值——不设置的话，固件看不到失去信号，飞机会带着最后的油门继续飞。

失去信号时 ARM **不会**被重置：信号恢复后，飞机会重新听从摇杆和所选的模式，无需再次解锁（在空中拨动开关、同时把油门收到零，反而更危险）。

桌面检查（拆掉螺旋桨）：ARM → 关闭遥控器 → OLED 上显示 `RX LOST ... GLIDE`，电机停转；把飞机倾斜——舵面应该把它拉回水平。打开遥控器——`RX ok`，控制权重新回到摇杆手上。

### 在 FS-i6 遥控器中设置 failsafe（必须做，只需一次）

思路：失去信号时，接收机应当输出约 900 µs 的油门——低于正常的最小值 1000。

1. `Menu → Functions setup → End points` → 通道 3：把下端点（左边的值）设为 **120%**。保存（长按 Cancel）。
2. 把油门拉到**最低**。
3. `Menu → Functions setup → Failsafe` → Channel 3 → **On**，油门仍在最低位 → 长按 Cancel 保存。接收机会记住约 900 µs。
4. 回到 `End points` → 通道 3 → 把下端点改回 **100%**。保存。
5. 检查：不需要 ARM。关闭遥控器——约 1 s 后串口出现 `RX=LOST(failsafe пульта)`，OLED 上出现反色的 `RX LOST` 一行。打开遥控器——`RX=OK`。

油门微调请保持在中间：微调拉得很低时，油门可能降到 950 以下，固件会把这当成失去信号。

这里以前有 **CH8 上的 boost 加速档**和 40% 的油门限制——现在都已移除：限制是为了保护较弱的 3S1P 组合，而新电池不怕满油门。加速档还有一个问题：如果开发板上电时 SwD 是向上的，它会自己打开。

## 烧录开发板

固件用 **PlatformIO** 构建（Arduino 框架，C++）。

### 安装 PlatformIO

最简单的办法是在 VS Code 里安装 **PlatformIO IDE** 扩展（Extensions → 搜索“PlatformIO IDE” → Install），这样既有命令行工具，又有界面里方便的构建按钮。也可以用 `pip install platformio` 安装并在终端里使用——两种方式用的是同一套 `pio` 命令。

### 编译与上传

在装有 PlatformIO 的 VS Code 中打开项目（仓库文件夹），用 USB 连接开发板，然后在终端中运行与自己开发板对应的命令：

```bash
# STM32H743 DevEBox（主力板）
pio run -e stm32h743-devebox -t upload

# esp32-s3 N16R8（之前的主力板）
pio run -e esp32-s3 -t upload

# esp32-c3（旧原型机）
pio run -e esp32-c3 -t upload

# esp32-dev（经典 ESP32 38 针，用于台架）
pio run -e esp32-dev -t upload
```

如果完全不指定 `-e`，就会编译默认开发板——`stm32h743-devebox`。

**STM32 DevEBox：** 第一次烧录走 USB DFU：用跳线把 BT0 接到 3V3，按一下 RST，然后执行上面的命令（Windows 需要为“STM32 BOOTLOADER”安装 WinUSB 驱动，用 Zadig 安装）。之后在控制台按 `D` 键，板子会自己重启进入引导程序，跳线就不再需要了。控制台也走同一个 USB-C。

**esp32-s3**：这块板有两个 USB-C 接口。烧录和串口都走 **“COM”** 接口（CH343 桥接芯片，在 Windows 中显示为“USB-Enhanced-SERIAL CH343”）。“USB”接口（芯片自带的原生 USB）工作时用不到，但可以插着——不会影响任何东西。

### 串口监视器

想在控制台里通过 USB 直接看到调试输出（通道状态、ARM、传感器）：

```bash
pio device monitor -b 115200
```

速率必须是 115200——否则看到的不是文字，而是一堆无法阅读的乱码。每 10 秒会打印一行 `SYS`：循环频率（应约为 500 Hz）、10 s 内的平均和最差循环时间、iBUS 计数器、剩余内存。其余内容通过日志菜单里启用的通道输出（见下文）。

### 控制台：菜单与日志（串口监视器）

按键立即生效，不需要按 Enter（如果监视器是按行发送的，就输入字母再按 Enter）。校准和输出检查只能在未解锁时进行。

| 按键 | 作用 |
|---|---|
| `h` | **主菜单**（文本形式，选项用数字编号） |
| `l` | “日志输出什么”菜单 |
| 空格 | 暂停日志 / 继续 |
| `s` | 所有传感器的详细状态（包括 I2C 错误计数） |
| `i` | 重新校准陀螺仪并做 IMU 飞行前检查——2 s，不要移动飞机 |
| `o` | **IMU 安装校准**——把板子装进飞机后做一次（见下文） |
| `c` | **飞机地面校准**——水平基准和停机姿态（见下文）；正在进行时则取消 |
| `e` | 提示：舵面点头和电调提示音——检查电调是否会播放（先拆下螺旋桨！） |
| `m` | 罗盘校准——15 s 内让板子/飞机绕所有轴转动。结果会保存到闪存，重启后仍然有效 |
| `p` | 输出检查：每个引脚上的实际脉冲 |

**按通道输出日志。** 每一类数据各占一行，有自己的前缀，也有自己的模式：**关**、**变化时**（只有数值真的变了才会出现一行——摇杆抖动和传感器噪声不算）或**持续**（每 0.2 / 0.5 / 1 / 2 s 一次——周期也在同一个菜单里设置）。

| 通道 | 显示什么 | 默认 |
|---|---|---|
| `STAT` | 链路、ARM、模式、襟翼，IMU/气压计是否正常 | 变化时 |
| `RC` | 遥控器通道，µs | 关 |
| `OUT` | 舵面和电调的输出，µs | 关 |
| `ATT` | 横滚、俯仰、航向 | 关 |
| `AP` | 自动驾驶仪：目标与修正量 | 关 |
| `ALT` | 高度、垂直速度、ALT_HOLD 的目标 | 关 |
| `MAG` | 罗盘航向 | 关 |
| `GPS` | 定位状态、卫星、坐标、速度 | 关 |
| `IMU` | 陀螺仪和加速度计 | 关 |
| `SYS` | 循环频率和耗时、内存（每 10 s 一次） | 开 |

菜单打开期间，日志保持安静，免得菜单被刷走；退出后，所有已启用的通道会重新打印。选择会在退出菜单时保存到闪存，重启后仍然有效。处于解锁状态时，设置立即生效，但要等 DISARM 之后才会写入：写闪存会让飞行循环停顿约 0.4 s。

### IMU 的安装：怎么装都行，只需校准一次

带 IMU 的板子可以**随便怎么方便就怎么**装进飞机——任意角度、侧着、倒着都行：固件会自己判断哪边是机头、哪边是上方。只需在安装后做**一次**（如果挪动过板子，再做一次）：

1. 飞机放在桌上，不需要遥控器，电机未解锁。在串口监视器里按 `o`。
2. **第 1 步**：飞机放平，就像平飞时那样（尾轮式飞机可以直接停在轮子上——水平基准之后由飞机地面校准确定）。约 3 s 内不要碰它。
3. **第 2 步**：把**机头**抬高 30–60°，机翼保持水平，静止约 1 s。
4. **第 3 步**：机头放回，把**右翼**压低 30–60°，保持约 1 s。

每一步都会自动记录（日志里会显示“засчитано”，即“已记录”）。最后会显示结果（“нос = +Y чипа, верх = −Z чипа”，即“机头 = 芯片的 +Y，上方 = 芯片的 −Z”）和“установка сохранена”（“安装方式已保存”）。如果搞错了（把机头压低而不是抬高，或者压了左翼而不是右翼），校准会被拒绝并给出说明，重新按 `o` 即可。结果保存在闪存里，重启后仍然有效。检查方法：机头抬起 → OLED 上的 P 变为正；右翼向下 → R 变为正。

在做安装校准之前，沿用旧方式：板子必须芯片朝上放置，旋转由 `Config.h` 里的 `IMU_ROTATION_CW_DEG` 设定。做完 `o` 后要重做飞机地面校准：停机姿态是相对旧的水平基准测得的。

### 飞机地面校准：水平基准和停机姿态

尾轮式飞机停在地上时机头是抬起的——抬多少，事先谁也不知道。校准会自己测量并写入闪存：**水平基准**（所有模式下的 0° 俯仰和横滚——不再是“上电时怎么放就算水平”）和**停机姿态**，自动起飞据此算出机尾该抬多高、尾轮会在哪里碰到跑道。组装后做一次（挪动过板子或做过 `o` 后再做一次）。不需要电脑：

1. 飞机放在平地上，打开遥控器，**不解锁**，油门在最低。
2. **把 SwB（襟翼）连续上下拨三次**（4 s 内）——或在控制台按 `c`。一次提示——开始。
3. **第 1 步——水平基准。** 抬起机尾，直到机身像飞行时一样水平（主轮着地；把装了水平仪 App 的手机放在机身上会有帮助），保持静止约 2 s。顺便看一下螺旋桨和地面之间的间隙：起飞滑跑时大致就是这样。一次提示——已记录。
4. **第 2 步——停机姿态。** 把飞机放回三个轮子上，松开手。约 2 s 后——两次提示：完成，日志显示“Стоянка: нос вверх на 9.4°, крен 0.3°”（“停机：机头抬起 9.4°，横滚 0.3°”）。

三次提示——出错，什么也没保存（原因见控制台）：飞机一分钟内都没有静止下来，停机时机头几乎没有抬起（机尾没有放下）或超过 25°，或者横滚超过 10°。取消：同样的 SwB 手势，或者把 ARM 开关拨一下（这一下不会解锁）。前轮式（`NOSE_WHEEL`）飞机如果停放时是水平的，第 1 步可以直接在轮子上做：第 2 步会在 5 s 后自动记录。手势用的开关是 `Config.h` 里的 `CAL_SWITCH`（不能用 SwD：它控制电机反转）。

**提示。** 一次提示：升降舵和方向舵点头（第 1 步时你正托着机尾，能感觉到），未解锁时电机还会“唱歌”：发往电调的脉冲消失一秒，电调以为信号丢了，脉冲恢复时就播放就绪提示音——和上电时一样。电机不会转。通过 PWM，电调不认识别的“鸣叫”命令，所以要在台架上检查（**拆下螺旋桨**）：在控制台按 `e`——应该能听到提示音。如果听不到，在 `Config.h` 里设 `SIGNAL_MOTOR = false`，只保留点头。接在 PE15（S3：GPIO38）上的蜂鸣器或带电阻的 LED 会在点头时亮起；DevEBox 板载的 LED D2 接在 PA1——右副翼的输出上，所以不能用来提示。提示进行中会拒绝 ARM：电调可能还没有重新就绪。OLED 的角度行显示 `CAL1`、`CAL2`，结果为 `CALOK` 或 `CALER`。

### 上电时的飞行前检查

每次上电时，IMU 会花约 2 s 校准陀螺仪，同时检查自身：

- **飞机是静止的**——如果此时有人拿着它或移动了它，陀螺仪的零偏就不准；
- 加速度计静止时读数为 1g；
- **“上方”与安装校准一致**——如果板子被挪动或翻转过，立刻就能看出来（飞机立在尾轮上或停在斜坡上没关系，容差为 45°）。

**请在飞机静止不动时上电**。如果已经做过安装校准（`o` 或飞机地面校准），不一定要放平（否则上电时的姿态会被当成地平线）。结果在日志里：`предполётная проверка пройдена`（“飞行前检查通过”）或 `ПРЕДПОЛЁТНАЯ ПРОВЕРКА НЕ ПРОЙДЕНА — <причина>`（“飞行前检查未通过”，后面跟着原因）。没通过时，**STABILIZE 和 AUTO_TAKEOFF 下禁止 ARM**（尝试时会打印原因），而且自动驾驶仪在任何模式下都不会给出修正，包括失去信号时的滑翔：角度不对的话，它会往相反方向打舵。在 MANUAL 下仍然可以 ARM。修复办法：把飞机静止放好，重新接上电池（或按 `i`）；如果板子被挪动过，就按 `o`。

### OLED 屏幕

如果接了 OLED（GPIO1/GPIO2），它每秒刷新 5 次，显示如下：

```
RX ok disarm STAB        <- 链路 / ARM / 模式 / REV——电机反转（失去信号时这一行反色）
R  +1.2 P  -0.4 ROLL     <- 横滚 / 俯仰，°；校准步骤或起飞阶段
Alt +0.3 Vz +0.1         <- 相对上电点的高度，m / 垂直速度，m/s
Hdg 123  Thr 1000        <- 罗盘航向 / 油门 1000..2000 = 0..100%（反转时也一样），µs
L1500 R1500 E1500        <- 副翼和升降舵的 PWM，µs
Loop 500Hz max 1100us    <- 频率和最差循环耗时
```

开发板会自己建立一个 Wi-Fi 热点——不需要家里的路由器，也不需要互联网，在野外直接用手机就能使用。

**如何连接：**

1. 在手机或笔记本电脑上打开 Wi-Fi 网络列表。
2. 连接到网络 **`OpenPlane-Debug`**，密码为 **`12345678`**。
3. 在浏览器中打开地址 **`http://192.168.4.1`**。

不需要安装任何应用——这只是一个普通网页。

**在野外用手机、不需要任何编程就能做的事：**

- 查看全部 10 个 RC 通道的**实时条形显示**——在连接舵机之前，就能方便地检查遥控器和接收机发出的内容是否与你拨动的摇杆一致。
- 查看每个输出（左右副翼、升降舵、电调）的状态——这个通道在软件里是否已连接。
- 查看传感器（IMU、气压计）是否有响应（如果你焊了它们）——它会如实显示真实数据（横滚/俯仰/高度），或者明确标注传感器实际上不存在或没有响应。
- 直接在页面上用按钮**切换自动驾驶仪模式**（手动 / 增稳 / 自动起飞 / 定高），无需遥控器。
- 通过页面上的表单**调整 PID 控制器的系数**（横滚和俯仰各一组）——便于在不重新烧录的情况下逐步调整增稳。

这个热点的作用距离实际上只有几十米，它就是普通的 ESP32 Wi-Fi，而不是远距离遥测。它是用来在桌面、台架上和场地旁边调试的工具——不是用来在远处飞行时操控飞机的。

## 黑匣子

ESP32-S3 固件会自己把每一次飞行写进闪存：传感器看到的一切、摇杆做了什么、舵机去了哪里、自动驾驶仪做出了什么决定。你什么都不用做：

- 从飞机解锁并推起油门的时刻开始**记录**（外加此前的 10 s）；
- 在 DISARM 后 10 s **停止**——或者飞机处于解锁状态、电机关闭并静止不动满 30 s（已经降落或坠毁，而忘了 DISARM）；
- 失去信号、电机归零和滑翔**不会**停止记录。

上电时，串口监视器会显示还有多少空间可供一次飞行使用（控制台用俄语输出；下面这一行的意思是“等待 ARM 和油门 | 前方已擦除 12.9 MB（≈11 分钟），共 13.9 MB | 飞行 1 次”）：

```
BlackBox: ждёт ARM и газ | стёрто впереди 12.9 МБ (≈11 мин) из 13.9 МБ | полётов 1
```

**飞行结束后**，连接 USB（COM 接口），关闭串口监视器，然后下载这次飞行：

```bash
python tools/blackbox.py download
```

飞行记录会连同解析结果一起出现在 `blackbox/` 文件夹中：`summary.txt`（摘要和事件）、`events.txt`，以及按传感器分开的 CSV 表。黑匣子在需要空间时会自己擦除旧的飞行记录——**每次飞行后都要下载**。控制台里的菜单是 `k` 键。详细内容见 [BLACKBOX.md](BLACKBOX.md)。

**在 STM32H743 开发板上**，黑匣子写入 SD 卡：卡格式化为 FAT32，并在电脑上一次性准备好（`python tools/blackbox.py sd-prepare E:`）。飞行结束后，可以用同样的 `download` 命令通过 USB 下载，也可以取出卡，直接从卡上解析文件：`python tools/blackbox.py ring E:/BLACKBOX.BIN`。

## 飞行前检查清单与安全

请在第一次上电**之前**把这一节完整读完，而不是出了事故之后。

### 任何台架测试之前必须做到

- [ ] **螺旋桨已确实拆下**——只要你在检查通道、ARM、仪表盘，调整 PID，或者只是第一次在新的引脚分配下给板子上电。电调在测试的任何阶段都可能让电机抽动一下——这不是假设的风险，而是首次上电时的正常表现。
- [ ] 已检查锂电池没有鼓包或损坏，用合适的锂电池充电器充好电，并且存放和充电时都放在不可燃的表面上。
- [ ] 遥控器已开机，并且在把电池接到电调**之前**，已在仪表盘（`http://192.168.4.1`）上检查过各通道。

### 飞行前

- [ ] 空旷的场地，在翼展 1200 mm 的飞机于手动控制下、舵机或机翼出现异常表现时足够安全的半径内没有人和建筑（见下文关于原型机局限的一节——电机固定处和机翼目前还没有用碳纤维加固）。
- [ ] 三个舵面都朝正确的方向运动——每次飞行前都在桌上检查，不要凭上次的记忆：
  - 右摇杆向右 → **右副翼向上，左副翼向下**；
  - 右摇杆拉向自己 → **升降舵向上**；
  - 左摇杆向右 → **方向舵和转向轮向右**；
  - SwB（襟翼）向下 → **两个副翼平滑地向下**，此时用摇杆打横滚，两个副翼仍然朝相反方向分开；
  - 推油门（拆下螺旋桨，看旋转方向）→ **螺旋桨向前拉**；
  - 在 STABILIZE 下把飞机右翼向下倾斜 → **右副翼向下，左副翼向上**（舵面把它拉回水平）；机头向下 → **升降舵向上**。如果有哪里不对，就改 `include/config/Config.h` 中“反向”块里的一行：每个副翼、升降舵、方向舵、AUX、电机（`MOTOR_REVERSED`）和襟翼（`FLAPS_REVERSED`）都单独反转，其他不受影响。不要在遥控器上反转舵机——摇杆和自动驾驶仪会不一致；要让某个通道（摇杆、开关、旋钮）反向——用同一处的 `CHANNEL_REVERSED`。
- [ ] 上电时飞机是静止的，日志/仪表盘中没有 `ПРЕДПОЛЁТНАЯ ПРОВЕРКА НЕ ПРОЙДЕНА`；用手倾斜飞机时，OLED 上的 P 和 R 朝正确的方向变化。
- [ ] AUTO_TAKEOFF：已做飞机地面校准（上电时日志显示“стоянка на колёсах — тангаж …”），尾轮完好，飞机在跑道上逆风停放。最初几次滑跑要限制油门（旋钮 `THROTTLE_LIMIT`），手放在油门上：拉到底即中止起飞。
- [ ] 遥控器里已设置并测试过 failsafe：关闭遥控器 → OLED/串口中出现 `RX LOST`（见 failsafe 一节）。
- [ ] 已检查遥控器的作用距离，遥控器的电池有电。
- [ ] 上电时日志里有 `BlackBox: ... стёрто впереди N МБ (≈M мин)`——空间够一次飞行用。如果需要上一次的飞行记录，已经下载了它（`python tools/blackbox.py download`）。
- [ ] 只要锂电池接着电调，就让手和脸远离螺旋桨——ARM 之后，油门会立刻随摇杆响应，不会有任何额外警告。DISARM——SwA 拨上。
- [ ] 确认你能在物理上迅速切断电源（够得着锂电池接头），而不是只依赖失去信号时的 failsafe。

### 锂电池通用安全

- 绝不要让正在充电的锂电池无人看管。
- 不要站在螺旋桨旋转平面旁边，把锂电池接到电调上或从电调上拔下。
- 运输和存放锂电池时，请使用防护袋或防护盒。

## 故障排查

**“收不到接收机信号” / RX 看起来正常，但仪表盘上的通道不动**
检查接收机数据线是否正好接在你的板子表格中的接收机 RX 引脚上（PE7/GPIO17/GPIO8/GPIO16），没有与地线或电源接错，并且接收机与板子共地。如果引脚对应、导线完好但仍没有信号——检查接收机是否已与遥控器对频（ExpressLRS 需要与发射机相同的 binding phrase 和版本），以及其输出是否与 `RX_PROTOCOL` 一致：iBUS、SBUS 或 CRSF，而不是 PPM。

**传感器（IMU、气压计、罗盘）显示“无响应” / NO_RESPONSE**
固件会如实报告传感器没有响应，而不是输出一堆零。请检查：（1）模块的供电——3.3V 和板子的地线；（2）SDA/SCL——接在你那块板子的 I2C 引脚上；（3）总线上的地址：MPU 0x68（AD0 接 GND），BMP581 0x46（SDO 接 GND，CSB 接 3.3V；SDO 接 3.3V 时为 0x47），BMP388 0x76（SDO 接 GND，**CSB 接 3.3V**——否则芯片处于 SPI 模式），QMC5883P 0x2C，QMC5883L 0x0D。如果传感器时有响应时无响应（或者响应的是别的地址），那是面包板接触不良：把 VCC/GND/SDA/SCL 都按紧，最好让每个模块直接从板子的 3.3V/GND 取电。控制台里的 `s` 命令会显示每个传感器的 I2C 错误计数。

**OLED 上的角度错乱（机头向上时变化的是 R 而不是 P），或者符号不对**
请做一次 IMU 安装校准（`o`，见“IMU 的安装”）——它与芯片在模块上怎么焊、模块在飞机里怎么放都无关。没有校准时：GY-521 的仿制板上，芯片有时相对于印出来的箭头焊歪了——请在 `Config.h` → `IMU_ROTATION_CW_DEG`（0/90/180/270）里旋转坐标轴。检查方法：机头向上 → P 变为正，右翼向下 → R 变为正。

**ARM 被拒绝：“IMU: ...”**
IMU 飞行前检查没有通过（见“上电时的飞行前检查”）：上电时飞机被移动过——请把它静止放好并重新接上电池；“上方”与校准不一致——板子被挪动过，请做 `o`；“板子没有芯片朝上放置”——安装还没有校准，请做 `o`。

**ARM 被拒绝：“нет калибровки шасси”（没有起落架校准）**
尾轮式 AUTO_TAKEOFF 不知道机尾会在哪里碰到跑道。请做飞机地面校准：不解锁时把 SwB 上下拨三次（或按 `c`）。

**“Автовзлёт: старт отменён — тангаж не стояночный”（起飞前取消：俯仰不是停机姿态；舵面点头了三次）**
飞机停放的样子和校准时不同：没有停在三个轮子上、斜坡、尾轮坏了或板子移位。把它放平；如果挪动过板子，重做 `o` 和地面校准。

**舵机或电调响应的不是它该响应的那根摇杆 / 没有反应**
控制台里的 `p` 命令会测量每个输出（GPIO4–7）上的真实脉冲，并与预期值比较。如果全部显示“OK”而舵机不动，问题就出在板子之外：（1）舵机没有供电（BEC/5V，共地）；（2）信号线接错了引脚；（3）机构卡住了。如果显示“НЕ СОВПАДАЕТ”（即“不匹配”），问题出在固件或外设上——请告知开发者。

**电机完全不转，尽管 OLED/仪表盘上的油门随摇杆变化**
请检查锂电池是否接到了电调，以及飞机是否真的已解锁——ARM 之前，送到电调的油门被强制保持在最小值，这不是故障。上电时看到的油门不是最小值的电调，可能会一直鸣叫而无法解锁——请在油门拉到最低的情况下重新接上电池。如果把 SwA 拨下后没有出现 `ArmingManager: ARM`，请看串口——固件会打印原因（油门没有拉到最低、有传感器没有响应、当前在 CH7 上选定的模式所需的传感器等）；把 SwA 拨回上面，排除原因，再重新拨下。

**电机在加速时熄火或抽动**
如果电调由台式电源供电，那是撞上了电源的电流限制：即使没有螺旋桨，电机也会在短时间内吸取好几安培，电压下跌，电调重启。请调高电流限制，或者改用锂电池。这样的重启产生的尖峰可能会让板子的 USB 桥挂死（“COM”口再也打不开）——重新插拔数据线即可。

**烧录后开发板无响应 / 热点 `OpenPlane-Debug` 没有出现**
请确认上传（`pio run -e <你的开发板> -t upload`）没有报错，并且烧录的正是你手里这块板子对应的环境（esp32-c3 与 esp32-s3 和 esp32-dev 的区别不只是引脚，还有芯片——给别的芯片编译的固件装不到板子上，或者装上了也不正常）。板子重启后，立刻查看串口监视器的输出（`pio device monitor -b 115200`）——那里会打印板子的 setup() 执行到了哪一步。
