# OpenPlane オートパイロット リファレンス

> 🌐 このページは[ロシア語の原文](../../AUTOPILOT_GUIDE.md)の翻訳です。翻訳と原文に違いがある場合は、原文が優先されます。ファームウェアはコンソールメッセージをロシア語で出力するため、そのまま引用しています。

オートパイロットにできること、各機能の有効化の方法、そして送信機のどのスイッチやダイヤルにも **1 行で**割り当てる方法です。

> まず正直に書きます。すべてのモードは、ユニットテストと閉ループのフライトシミュレーション（`test/native/test_sim`：ファームウェア全体が飛行機のモデルを操縦します）で検証されています。モデルは簡略化されており、`Config.h` の係数は初期値です。**どのモードも、まず高度 50 m 以上で、指を MANUAL のスイッチに置いて試してください**。これまでに飛行したのは手動モードだけです（ESP32-C3 を使った最初の試作機）。スタビライズはテストベンチで検証済みで、舵面は機体の傾きに対して正しい向きに反応します。STM32H743 ボードはビルドでき、同じテストに合格します。実機では、DevEBox ボードをセンサーなしで検証しました。SD カード、ブラックボックス、送信機からのサーボとモーターの手動操作です（動画に記録してあります）。センサーはまだ接続しておらず、オートパイロットのモードもこのボードでは試していません。

## 1 分でわかる仕組み

```
スティック┐
          ├─► PilotSwitches (config/Controls.h) ─► モード、機能、ダイヤル
スイッチ ─┘                                                 │
                                                            ▼
センサー（IMU、気圧センサー、コンパス、GPS、ピトー管） ─► Autopilot ─► 舵面とスロットルへの指令
                                                            │
                               FlightController：フラップ、ペイロード、カメラ、ブザー、failsafe
                                                            ▼
                                               エルロン · エレベーター · ラダー · ESC · AUX1 · AUX2
```

- **モード**は、誰が操縦するかを決めます。パイロット（MANUAL）、補助つきのパイロット（STABILIZE、ALT_HOLD、ACRO）、パイロットの補正つきのオートパイロット（CRUISE、LOITER、RTH など）です。
- **機能**は、どのモードの上にも重ねて有効にできます。フラップ、ブレーキ、ペイロード投下、ジオフェンスなどです。
- **ダイヤル**は、数値を滑らかに変えます。スタビライズの強さ、巡航速度、旋回半径などです。
- スタビライズ付きのモードでは、**スティックが指定するのは角度**であり、舵の振れ角ではありません。スティックを放せば、機体は自分で水平に戻ります。
- センサーが故障しても、機体が「ぎくしゃく」することは決してありません。IMU がなければ舵はパイロットのまま、気圧センサーがなければ高度はパイロットが保ち、GPS がなければナビゲーションは行われず、GPS を必要とするモードは安全に振る舞います（[表](#各モードに必要なもの)を参照）。

## 送信機の標準の割り当て

FS-i6 + FS-iA6B、iBUS、10 チャンネル（`config/Channels.h`）。

| チャンネル | 送信機の操作部 | 標準 |
|---|---|---|
| CH1–CH4 | スティック | ロール、ピッチ、スロットル、ラダー（割り当て変更不可） |
| CH5 | **SwA** | **ARM**（下 = ARM、スロットルが下のときのみ。割り当て変更不可） |
| CH6 | SwB | フラップ（`Feature::FLAPS`） |
| CH7 | **SwC**（3 ポジション） | 上が **MANUAL** ・ 中央が **STABILIZE** ・ 下が **AUTO_TAKEOFF** |
| CH8 | SwD | **RTH**：ホームへ帰還、オンの間 |
| CH9 | VrA | スタビライズの強さ（`Knob::STAB_GAIN`） |
| CH10 | VrB | 巡航速度（`Knob::CRUISE_SPEED`） |

ボードの電源を入れると、シリアルモニターに実際の割り当て、つまり実際に書き込まれている内容が出力されます（ファームウェアの出力はロシア語で、「вверх / середина / вниз」は「上 / 中央 / 下」という意味です）。

```
SwC (CH7): MANUAL / STABILIZE / AUTO_TAKEOFF (вверх / середина / вниз)
SwB (CH6): FLAPS, пока включён
SwD (CH8): RTH, пока включён
VrA (CH9): крутилка STAB_GAIN
VrB (CH10): крутилка CRUISE_SPEED
```

> FS-i6 では、チャンネル 7〜10 は標準では出力されません。送信機のメニュー：**Functions setup → Aux. channels** で、SwC、SwD、VrA、VrB を割り当ててください。

## 1 行で機能を割り当てる

すべて 1 つのファイル `include/config/Controls.h` にあります。

```cpp
constexpr Binding BINDINGS[] = {
    Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_AUTO_TAKEOFF),
    Bind::feature(Channels::SWB, Feature::FLAPS),
    Bind::mode   (Channels::SWD, MODE_RTH),
    Bind::knob   (Channels::VRA, Knob::STAB_GAIN),
    Bind::knob   (Channels::VRB, Knob::CRUISE_SPEED),
};
```

| 行の形式 | 動作 |
|---|---|
| `Bind::modes(チャンネル, 上, 中央, 下)` | 3 ポジションのスイッチでモードを選ぶ |
| `Bind::modes(チャンネル, 上, 下)` | 2 ポジションのスイッチで 2 つのモード |
| `Bind::mode(チャンネル, モード)` | スイッチがオンの間、他のモードの**上に重ねて**適用される。オフにすると、モードスイッチのモードに戻る |
| `Bind::feature(チャンネル, 機能)` | スイッチがオンの間、その機能が働く |
| `Bind::knob(チャンネル, ダイヤル)` | ダイヤル：中央 = `Config.h` の値、両端 = 最小値と最大値 |

「オン」とは、チャンネルが 1750 µs を超えている状態です（FS-i6 ではスイッチを下、手前に倒した状態）。受信機の最初のフレームが届くまで、すべてのチャンネルはオフとみなされます。そのため、電源投入時に何かが展開されたり投下されたりすることはありません。

### すぐ使えるレシピ

```cpp
// 熱上昇用グライダー：SwD — ソアリング、SwB — オートトリム、VrB — 旋回半径
Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_SOARING),
Bind::feature(Channels::SWB, Feature::AUTO_TRIM),
Bind::knob   (Channels::VRA, Knob::STAB_GAIN),
Bind::knob   (Channels::VRB, Knob::LOITER_RADIUS),

// 初心者：スタビライズのみ、「パニックボタン」に RESCUE、やわらかいスティック
Bind::modes  (Channels::SWC, MODE_STABILIZE, MODE_ALT_HOLD, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_RESCUE),
Bind::feature(Channels::SWB, Feature::GEOFENCE),
Bind::knob   (Channels::VRA, Knob::RATES),
Bind::knob   (Channels::VRB, Knob::MAX_BANK),

// 撮影と配送：スタビライズ付きカメラ、ペイロード投下、一点の上空を旋回
Bind::modes  (Channels::SWC, MODE_STABILIZE, MODE_CRUISE, MODE_LOITER),
Bind::feature(Channels::SWB, Feature::PAYLOAD_DROP),
Bind::feature(Channels::SWD, Feature::CAMERA_STAB),
Bind::knob   (Channels::VRA, Knob::CAMERA_TILT),
Bind::knob   (Channels::VRB, Knob::LOITER_RADIUS),

// 降着装置なしの手投げ発進：SwD — LAUNCH、フラップはダイヤルで滑らかに
Bind::modes  (Channels::SWC, MODE_MANUAL, MODE_STABILIZE, MODE_CRUISE),
Bind::mode   (Channels::SWD, MODE_LAUNCH),
Bind::feature(Channels::SWB, Feature::AIRBRAKE),
Bind::knob   (Channels::VRA, Knob::FLAPS),
Bind::knob   (Channels::VRB, Knob::CRUISE_SPEED),
```

### コンパイラがミスを見つける

この表はビルド時に検査されるため（`static_assert`）、ファームウェアが機体に載る前にミスが見つかります。

- スティックと SwA（ARM）は割り当てできません。チャンネル番号は `Channels::COUNT` より小さくなければなりません。
- 1 つのチャンネルに割り当てられるのは 1 つだけです。
- モード選択スイッチ（`Bind::modes`）は 1 つまでです。

複数の `Bind::mode` スイッチが同時にオンになっているときは、表の上の行が優先されます。

## モード

モードは、スイッチを**切り替えた**ときに変わります。ダッシュボードや地上局から有効にしたモードは、パイロットが再びモードスイッチを切り替えるまで有効です。OLED には短い名前（括弧内）が表示されます。

### MANUAL (MAN)
舵面 = スティック。フライトコントローラーがないときと同じです。機能（フラップ、ブレーキ、ペイロード）とオートトリムだけが働きます。**最も重要な安全モード**です。常に指の下のスイッチに割り当てておいてください。

### STABILIZE (STAB) — 「スティックが角度を指定する」
ロールのスティックは `MAX_BANK_DEG`（45°、ダイヤル `MAX_BANK` は 15〜60°）までのバンク角を、ピッチのスティックは `STAB_MAX_PITCH_DEG`（25°）までの角度を指定します。スティックを放せば、機体は自分で水平に戻ります。スロットルはパイロットが操作します。PID の積分は目標の近く（±10°）でしか蓄積されないため、急な操作のあとでも機体が水平を「行き過ぎる」ことはありません。
**必要なもの：** IMU。IMU がなければ MANUAL と同じです。

### ALT_HOLD (ALT) — 「高度を保つ」
ロールは STABILIZE と同じで、エレベーターが気圧センサーで高度を保ちます。ピッチのスティックを動かしている間は自分で操縦し、放すと機体は**新しい**高度を保ちます。スロットルはパイロットが操作します（スロットルを足してください。そうしないと上昇に必要な速度が足りません）。
**必要なもの：** IMU + 気圧センサー。

### ACRO — 「スティックが回転速度を指定する」
スティックをいっぱいに倒すと 180°/s です。放すと、機体は**そのときの姿勢を保ちます**（背面でも）。ジャイロが突風を打ち消します。アクロバット用です。
**必要なもの：** IMU。IMU がなければ舵面 = スティックです。

### CRUISE (CRZ) — 「針路、高度、速度を保つ」
機体は現在の高度で直進し、スロットルは自動です（ダイヤル `CRUISE_SPEED`：スロットル 30〜55〜85 %。ピトー管がある場合は**対気速度** 10〜14〜22 m/s）。ロールのスティックで旋回します（放すと新しい針路を保ちます）。ピッチのスティックで高度を変えます。ピトー管があると失速防止が働きます。針路は GPS から取ります（対地速度が 3 m/s を超えたとき。2 m/s を下回るとコンパスに戻ります）。GPS がなければコンパス、それもなければジャイロから取ります。シミュレーションでは、4 m/s の横風でも、対地の航跡は ±5° 以内、高度は ±3 m 以内に収まります。
**必要なもの：** IMU + 気圧センサー。針路がずれないようにするには GPS またはコンパスが必要です。

### LOITER (LOIT) — 「ここで旋回する」
モードをオンにした地点の上空を、時計回りに半径 50 m（ダイヤル `LOITER_RADIUS` は 25〜150 m）、現在の高度で旋回します。スロットルは自動です。誘導にはベクトル場を使います。遠くからは接線方向に円へ入り、円に乗ったあとは先行バンクを保ちます。GPS がない場合は、その場で一定のバンクで円を描くだけです。
**必要なもの：** IMU + 気圧センサー + GPS。

### RTH — 「ホームへ帰還」
ホーム（ARM した地点）へ針路を取り、高度は `RTH_ALTITUDE_M` = 40 m にします（それより低ければ途中で上昇し、高ければそのままです）。ホームの上空では、パイロットが操縦を取り戻すまで LOITER の半径で旋回します。GPS またはホームがない場合は、その場で旋回します。通信途絶とジオフェンスも同じモードを起動します。
**必要なもの：** IMU + 気圧センサー + ホームが記録された GPS。

### AUTO_TAKEOFF (TKOFF) — 「スロットルで離陸」
ARM のあとは、パイロットがスロットルを中央より上に上げるまで何も起こりません。その後は次のプログラムです。翼を水平にして 1 秒かけてスロットルを 100 % まで加速し、ピッチ 15° で 2 秒かけて機体を浮かせ、その後はピッチ 10° で、パイロットがモードを切り替えるまで上昇します。スティックの操作はプログラムに加算されるので、離陸滑走中に針路を修正できます。
**必要なもの：** IMU。

### LAUNCH (LNCH) — 「手投げ発進」
1. ARM して、スロットルを中央より上にすると、発進は**待機状態**になります（モーターは止まったままです）。
2. 投げ出し：前方への加速度が 1.5 g を超える状態が 40 ms より長く続くこと。
3. 0.3 秒後（手がプロペラから離れたころ）に、スロットル 100 %、ピッチ 15° で、翼を水平にして 6 秒間、または 30 m まで上昇します。
4. その後は、到達した高度での CRUISE と同じです。

投げ出す前にスティックを少しでも動かすと（150 µs を超えた場合）、発進は取り消され、機体はパイロットの手に戻ります。
**必要なもの：** IMU（加速度センサー）。シミュレーションでは、手の高さから 9 m/s で投げると、機体は一度も地面に触れず、15 秒で 15 m 以上上昇します。

### AUTO_LAND (LAND) — 「着陸」
モーターは停止し、ピッチ −4° で針路に沿って滑空します。気圧センサーで 3 m を下回るとフレア（+4°）に入ります。ロールのスティックでアプローチの針路を修正できます。直線コースで、向かい風の中、高度 20〜40 m で、滑走路に余裕をもって有効にしてください。シミュレーションでは、接地時の垂直速度は 1.5 m/s 未満で、翼は水平、機首から突っ込むことはありません。
**必要なもの：** IMU + 気圧センサー（電源投入時に地上でゼロ点を取ったもの）。

### SOARING (SOAR) — 「サーマルでのソアリング」
モーターは停止し、滑空します。バリオメーター（ピトー管があれば全エネルギー方式で、スティックを引いたことによる偽の「サーマル」は出ません）が 0.5 m/s を超える状態が 1.5 秒より長く続くとサーマルと判断し、バンク 25° で旋回します。8 秒間の平均上昇率が −0.2 m/s を下回ると、サーマルを抜けます。高度 30 m を下回るとモーターを使い、100 m まで上昇します。ホームから 400 m より遠いときは、ホームへ向けて滑空します。シミュレーションでは、サーマル（中心部 3 m/s）を見つけ、モーターなしで 50 m 以上上昇します。
**必要なもの：** IMU + 気圧センサー。ホームへ戻るには GPS が必要です。

### RESCUE (RESQ) — 「助けて」
翼を水平に、機首を +8°、スロットルを 70 % にします。どんならせん降下からでも回復できます。向きが分からなくなったら、スイッチを切り替えて、ひと息つきましょう。シミュレーションでは、バンク 70°、機首 −40° のらせん降下から、4 秒で翼が水平になり、上昇に移ります。
**必要なもの：** IMU。

## 機能（スイッチ）

| 機能 | 動作 | 詳細と数値（`Config.h`） |
|---|---|---|
| `FLAPS` | 両方のエルロンを下げる（フラッペロン） | `FLAPS_DEPLOYED_US` = 220 µs、1 秒かけて滑らかに。ロールはその上に重ねて効く |
| `AIRBRAKE` | 両方のエルロンを上げる（エアブレーキ）。グライドスロープが急になる | `AIRBRAKE_US` = 250。フラップより優先 |
| `AUTO_TRIM` | スティックなしで機体を真っすぐに保てるよう学習する。水平飛行中の一定の舵指令がトリムに「流れ込む」 | 20 %/秒、最大 ±120 µs。**地上で** DISARM したあとフラッシュに保存される |
| `TURN_COORDINATION` | 旋回にラダーを合わせ、バンク中は機首を上げる | ナビゲーション系のモードでは常にオン |
| `MOTOR_KILL` | どのモードでもモーターを止める（自動モードでも） | どのモードやスロットルよりも優先 |
| `BEEPER` | 「ここにいます」ブザー | スイッチがなくても自動で鳴る：地上で、通信途絶が 10 秒を超えたとき |
| `PAYLOAD_DROP` | スイッチがオンの間、AUX1 のサーボが開く | 1000 µs で閉、2000 で開 |
| `GEOFENCE` | ホームから 500 m より遠く、または高度 120 m より上で RTH | `GEOFENCE_ALWAYS_ON`：スイッチなしで常時有効 |
| `HOME_RESET` | ホーム = 現在地（スイッチをオンにした瞬間の位置） | GPS が良好なときのみ |
| `CAMERA_STAB` | AUX2 のカメラが水平線に対する角度を保つ | 機体のピッチを差し引く |

## ダイヤル

ダイヤルの中央 = `Config.h` の標準値で、両端が最小値と最大値です。割り当てていない場合は、標準値が使われます。

| ダイヤル | 最小 … 中央 … 最大 | 作用する範囲 |
|---|---|---|
| `STAB_GAIN` | ×0.25 … ×1 … ×2 | スタビライズ付きのすべてのモードと ACRO：「やわらかく / かたく」 |
| `MAX_BANK` | 15° … 45° … 60° | スティックとナビゲーションでの最大バンク角 |
| `CRUISE_SPEED` | スロットル 30 … 55 … 85 %（ピトー管あり：10 … 14 … 22 m/s） | CRUISE、LOITER、RTH、SOARING でのモーター |
| `FLAPS` | フラップ 0 … 50 … 100 % | スイッチの代わりに滑らかに操作するフラップ |
| `CAMERA_TILT` | −90° … 0° … +30° | カメラの角度（AUX2） |
| `RATES` | スティック操作量の 30 … 65 … 100 % | すべてのモード：スティックの感度 |
| `LOITER_RADIUS` | 25 … 50 … 150 m | LOITER とホーム上空の旋回 |

> 役立つ使い方：VrA に `STAB_GAIN` のダイヤルを割り当てると、飛行中に係数を「リアルタイムで」探れます。機体が揺れるなら下げ、反応が鈍いなら上げ、そのあと決まった倍率を `Config.h` に移してください。

## 通信途絶、ジオフェンス、ホーム

**ホーム**は、GPS が良好（3D フィックス、衛星 ≥ 6 個、精度 ≤ 5 m）なら ARM のときに記録されます。ARM の時点で GPS がまだ測位していなければ、測位した時点で記録されます。現場で変更するには `HOME_RESET` 機能を使います。

**通信途絶**（iBUS のフレームが 0.5 秒を超えて来ない、または受信機が 950 µs を下回るスロットルを送ってきた場合。これは送信機で設定した failsafe です。`docs/PILOT_GUIDE.md` を参照）：

| 状況 | 機体の動作 |
|---|---|
| 地上（ARM されていない） | モーター 0、舵面はニュートラル。10 秒後にブザー |
| 空中で、GPS とホームがある | モーターを使った **RTH**。ホームの上空では高度 40 m で旋回 |
| 空中で、GPS がない | **滑空**：モーター停止、翼は水平、機首 −3° |
| 通信が回復 | すぐにパイロットのスイッチのモードに戻る |

すでに始まっている帰還は、GPS が短時間途切れても滑空に切り替わりません。`FAILSAFE_RTH = false` にすると、滑空のみになります。

**ジオフェンス**（`GEOFENCE` または `GEOFENCE_ALWAYS_ON`）：`FENCE_RADIUS_M`（500 m）より遠く、または `FENCE_ALTITUDE_M`（120 m）より高く出ると RTH になります。操縦を取り戻すには、モードスイッチを別の位置に切り替えます（モードは位置の変化で有効になります）。機体が 10 % の余裕をもって内側に戻ると、再び作動します。

## 自作ピトー管

市販の差圧センサーなしで対気速度を得る方法：**気圧センサー 2 個**。

```
           流入する気流 ─►  ┌──────────── 管（PVC/真鍮、Ø4〜6 mm） ──┐
                            │  BMP581 (I2C 0x47) — 全圧              │  気密
                            └────────────────────────────────────────┘
   胴体：メインの気圧センサー（BMP581 0x46 / SPL06 / BMP388）— 静圧

   速度  V = √(2·(P_tube − P_static − zero) / ρ),   ρ — 静圧と温度から求める
```

**製作**。BMP581（アドレス 0x47 のモジュール：SDO ピンを VCC に接続）を、前方だけが開いた管の中に接着します。基板は気密の空洞の内側に入り、配線はシーリング材を通して引き出します。管は前向きに、プロペラの後流を避けて（主翼の上か機首の上）取り付けます。2 個目の気圧センサーは胴体の中に置き、直接の風が当たらないようにします（スポンジ）。

**ファームウェアでの有効化** — `sensors/SensorSelection.h`：`SENSOR_KIT_LSM6DSV_PITOT` または `SENSOR_KIT_ICM45686_PITOT`（用意済みのキット）、あるいは自分のキットで `SENSOR_AIRSPEED = SENSOR_AIRSPEED_PITOT_BMP581` を指定します。

**ゼロ点**。2 個の気圧センサーは、常に少しずれます。それぞれの絶対精度は数十パスカルで、低速ではそれがそのまま差圧のすべてになります（10 m/s ≈ 60 Pa）。電源投入後の最初の 1 秒間、ファームウェアは差を平均して、それをゼロとみなします。**電源投入時は機体を静止させ、管は指やキャップでふさぐか、風上に向けておきます**。計測値は、ゼロ点を取ったあとに OLED、ダッシュボード、テレメトリーに表示されます。

**`PITOT_SCALE` のキャリブレーション**。胴体内の圧力は厳密な静圧ではありません。無風の日に、CRUISE で直線を往復して飛び、GPS の平均対地速度と管の速度を比べます：`PITOT_SCALE = V_GPS / V_tube`。

**保護**。差圧が大きなマイナスのまま 2 秒を超えたとき（ホースの取り違え、水の侵入）、または管のサンプルが 0.2 秒より古いときは、速度を出力しません。オートパイロットは、ダイヤルで決めたスロットルと、対気速度なしの針路制御に切り替わります。両方の気圧センサーにノイズを加えた閉ループのシミュレーションで検証済みで、飛行中の速度誤差は 0.5 m/s 未満です。

管で得られるもの：CRUISE がスロットルではなく**対気速度**を保つこと、失速防止、SOARING 用の全エネルギー方式バリオメーター、テレメトリーの正直な速度です。

## 地上局：Wi-Fi ダッシュボードと MAVLink

**ESP32：Wi-Fi ダッシュボード**。アクセスポイントは `OpenPlane-Debug`、パスワードは `12345678` で、アドレスはシリアルモニターに表示されます。チャンネル、出力、すべてのセンサー、モード、ナビゲーション、有効な機能を確認でき、モードと PID を変更することもできます。詳細は `docs/PILOT_GUIDE.md` を参照してください。

**STM32H743：無線モデム経由の MAVLink**（UART4：PD0 RX、PD1 TX、57600 ボー。SiK の標準設定）。SiK 433/868/915 MHz、MAVLink モードの ELRS、Wi-Fi ブリッジとしての ESP-01 が使えます。**QGroundControl** と **Mission Planner** は、この機体を ArduPilot の飛行機として認識します：

- 水平線、ホームつきの地図、速度（ピトー管があればその値）、高度、バリオメーター、スロットル。
- モードは ArduPlane の名前で表示されます。STABILIZE → FBWA、ALT_HOLD → FBWB、CRUISE → CRUISE、LOITER → LOITER、RTH → RTL、AUTO_TAKEOFF/LAUNCH → TAKEOFF、SOARING → THERMAL、RESCUE → STABILIZE、AUTO_LAND → AUTO。failsafe は RTL または CIRCLE として表示されます。
- メッセージ欄：ARM/DISARM、モードの切り替え（OpenPlane 側の名前で）、通信途絶、ジオフェンス。
- **地上からのモード切り替え**：GCS のモードボタンで行います（AUTO を除く。OpenPlane にはミッションがありません）。
- **パラメーター** `RLL_KP … PTCH_KD`：ロールとピッチの PID で、飛行中に GCS のパラメーター画面から読み出して変更できます（再起動後は保存されません。よい値は `Config.h` に移してください）。

地上からの ARM/DISARM は**拒否されます**。操作できるのは送信機のスイッチだけです。ハードウェアなしでデータストリームを確認するには：`OPENPLANE_MAVLINK_DUMP=/tmp/tlm.bin pio test -e native -f native/test_mavlink && python3 tools/check_mavlink.py /tmp/tlm.bin`（`pip install pymavlink` が必要です）。

## 新しい機体の設定手順

1. **地上での MANUAL**：舵面の向き（`Config.h` の `*_REVERSED`）、フラップを下げた状態、AUX を確認します。出力の確認はコンソールの `p` で行います（プロペラを外すこと！）。
2. **地上でのセンサー確認**：`b` でバスのスキャン、`s` で状態、`o` で IMU の取り付けキャリブレーション（3 つの姿勢、1 回だけ）、`m` でコンパスを確認します。
3. **地上での STABILIZE**：機体を右に傾けると、右エルロンが**下**に動くはずです（水平に戻すため）。機首を上げると、エレベーターは下に動きます。そうならない場合は、リバースの設定か IMU の取り付けが間違っています。
4. **最初の飛行は MANUAL で**、高度 50 m 以上まで上昇してから STABILIZE に切り替えます。揺れるなら `STAB_GAIN` を下げ、反応が鈍いなら上げます。
5. 水平飛行で **AUTO_TRIM** を 20〜30 秒間働かせ、着陸して DISARM します。トリムが保存されます。
6. **ALT_HOLD**、次に **CRUISE** で、高度と針路を確認します。ピトー管がある場合は `PITOT_SCALE` をキャリブレーションします。
7. **LOITER** と **RTH** は、十分な高度で、視認できる範囲で、指を MANUAL に置いて試します。
8. それが済んでから初めて、**failsafe のテスト**（高度のある場所で送信機の電源を切り、機体がホームへ向かうことを確認）と、自動離陸 / 自動着陸を行います。

## オートパイロットの飛行前チェック

- [ ] 電源投入時に出力された割り当てが、想定どおりのものである。
- [ ] コンソール / OLED：IMU ok、IMU の飛行前チェックに合格している（電源投入時に機体が静止していた）。
- [ ] 気圧センサーが地上でゼロ点を取っている（OLED の高度が約 0）。
- [ ] ピトー管がある場合：地上での速度が約 0 で、管に息を吹き込むと上がる。
- [ ] GPS：**ARM の前に** 3D フィックスで衛星 ≥ 6 個になっている。そうでないとホームが記録されず、RTH も使えない。
- [ ] 地上での STABILIZE：エルロンとエレベーターが機体を水平に戻す向きに動き、傾きを悪化させる向きには動かない。
- [ ] 送信機に failsafe が設定されており（通信途絶時にスロットルが 950 未満）、**地上で**プロペラを外した状態で送信機の電源を切って確認した。
- [ ] MANUAL が指の下にある。
