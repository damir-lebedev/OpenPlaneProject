ここには機体そのものを置いています。Fusion 360 のプロジェクトと、3D プリント用の STL ファイルです。電子部品とフライトコントローラー基板については [FC_BOARD.md](../FC_BOARD.md)、組み立てと初飛行については[パイロットガイド](../PILOT_GUIDE.md)で説明しています。

## モデルのバージョン：v2

このフォルダーには **Astro-Cargo v2** が入っています。リポジトリに v1 はありません。最初のモデルは公開しないため、2 番目のモデルが最初の公開バージョンになりました。

- [Fusion 360 のプロジェクト](../../../../airframe/fusion360/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.f3d)：14 MB
- [印刷用の STL ファイル](../../../../airframe/stl/Astro-Cargo%20v2%20%28Bad%20wheel%20%26%20no%20battery%20mount%29.stl)：6 MB

ファイル名は、この版のどこに問題があるかがひと目で分かるように付けています（詳細は下記）。

> [!WARNING]
> **v2 で重大な設計上の欠陥が見つかっています。**
>
> 1. **降着装置（脚）と胴体の固定が弱すぎます。** 固定部が機体の重さに耐えられず、取り付け部で胴体が裂けます。
> 2. **バッテリーを固定するマジックテープ（面ファスナー）のバンドを取り付ける場所がありません。**
>
> どちらの欠陥も、次の試作機 **Astro-Cargo v3** で修正する予定です。v3 のモデルは、完成しだいこのフォルダーに追加します。それまでは、v2 を改修せずに飛ばさないでください。降着装置の固定部を各自で補強し、マジックテープ用の取り付け場所も自分で用意してください。

## 何がどこにあるか

| フォルダー | 内容 |
|---|---|
| [`fusion360/`](../../../../airframe/fusion360/) | 元のプロジェクト：`.f3d` ファイル（プロジェクトが複数ファイルの場合は `.f3z` アーカイブ）。寸法を変更して部品を書き出し直せます |
| [`stl/`](../../../../airframe/stl/) | 印刷できる状態の部品（STL 形式） |

## ファイル名のつけ方

- 名前は半角英字で付け、バージョン番号を入れます。v2 のファイル名は欠陥が分かるように付けましたが、今後はスペースや括弧を避けるほうが望ましいです：`astro-cargo_v3.f3d`、`astro-cargo_v3.stl`。ドキュメントからファイルを参照しやすくなります。部品が複数ある場合は、部品ごとに別のファイルにします：`fuselage_v3.stl`、`wing_left_v3.stl`。
- v3 のファイルはその隣に置き（`astro-cargo_v3.f3d`）、v2 のファイルも残します。何が修正されたのかがひと目で分かります。
- 単位はミリメートルです。プロジェクトで別の単位を使っている場合は、ファイルのそばに明記してください。

## ファイルが大きすぎる場合

GitHub は 100 MB を超えるファイルを受け付けず、50 MB から警告を出します。そのため、コミットする前にファイルサイズを確認してください。このようなファイルはリポジトリに置かず、次のいずれかに置きます。

- GitHub の **Releases** セクション：リリースにファイルを添付でき、1 ファイルあたり最大 2 GB まで置けます。
- [Git LFS](https://git-lfs.com)：ファイルをリポジトリ内に置き、コードと一緒に更新したい場合。
- 外部ホスティング：その場合は、この README にリンクを追記してください。

このフォルダーの `.stl`、`.f3d`、`.f3z`、`.step`、`.stp`、`.3mf` ファイルは、git がバイナリとして扱います（[`.gitattributes`](../../../../.gitattributes) を参照）。改行コードは変更されず、行単位の差分も表示されません。
