# ブラックボックス

> 🌐 このページは[ロシア語の原文](../../BLACKBOX.md)の翻訳です。翻訳と原文に違いがある場合は、原文が優先されます。ファームウェアはコンソールメッセージをロシア語で出力するため、そのまま引用しています。

ファームウェアは、すべてのフライトを自分でボード内蔵のフラッシュに記録します。センサー、スティック、サーボへの出力、オートパイロットの判断、イベントです。フライトの後、記録は USB でダウンロードされ、CSV の表に展開されます。

2 種類のボードで動作します。

| ボード | 記録先 | 入る量（約 20 KB/s の場合） |
|---|---|---|
| **ESP32-S3 N16R8**（メイン） | 内蔵フラッシュの 13.9 MB のパーティション | 約 **11 分** |
| **STM32H743**（DevEBox、WeAct） | SD カード上のファイル、[後述](#sd-カードstm32h743) | 64 MB で約 **55 分**。サイズはファイルで決まります |

その他のボード（ESP32-C3、通常の ESP32）には記録媒体がないため、ブラックボックスは無効で、飛行の邪魔にはなりません。

---

## いつ記録するか

| | 条件 |
|---|---|
| **開始** | ARM されていて、**かつ**スロットルが上がっていること（スティックまたは ESC が `THROTTLE_LOW_US` を超えた場合）。それより**前の 10 秒**も記録に含まれます。ARM の瞬間と離陸前の待機です |
| | 異常（パニック、ウォッチドッグ、電源電圧の低下）による再起動：最初の制御周期から、少なくとも 60 秒間記録します。空中で起きた場合は、その後どうなったかが分かります |
| | コンソールから手動で（`k` → `r`）：テストベンチ用 |
| **停止** | **DISARM の 10 秒後** |
| | ARM されているが、モーターが止まっていて、機体が **30 秒間静止している**場合：着陸または墜落して、DISARM を忘れたとき |
| | 手動で（`k` → `r`） |
| **停止しない** | 通信途絶、failsafe、空中でのモーターのゼロ、滑空、機体がまだ転がっている間の DISARM なしの着陸 |

「静止」とは、次のすべてが同時に成り立つことです。全軸で回転が 5 °/s 未満、加速度センサーが 1g ± 0.1 を示す、気圧センサーでほとんど垂直速度がない、GPS とピトー管（あれば）で速度が 2 m/s 未満。飛行中に、これほど静かな状態が 30 秒間続くことはありません。

## 何が記録されるか

| レコード | 周波数 | 内容 |
|---|---|---|
| `IMU` | 制御周期ごと、500 Hz | ジャイロ（°/s）、加速度センサー（g）、制御周期の処理にかかった時間（µs） |
| `CTRL` | 100 Hz | ロール / ピッチ / 針路、オートパイロットの目標、パイロットのスティック、最終的な指令、**7 つの出力すべて**（µs）、ロールとピッチの PID の各成分（P、I、D）、パイロットとオートパイロットのスロットル、フラップ、モード、フラグ（ARM、通信、failsafe、センサーが生きているか ...）、有効な機能 |
| `RC` | 50 Hz | 送信機の全 10 チャンネル、iBUS フレームのカウンター（正常なものと壊れたもの） |
| `BARO` | サンプルごと（約 50 Hz） | 気圧、温度、高度、垂直速度、高度の目標 |
| `MAG` | 最大 50 Hz | 3 軸の磁場、方位 |
| `GPS` | 測位解ごと | 座標、高度、速度、進路、衛星、フィックス、精度 |
| `AIR` | 最大 50 Hz | ピトー管：差圧、指示対気速度と真対気速度、密度 |
| `NAV` | 10 Hz | ホーム（距離、方位角）、針路と針路の目標、ナビゲーション速度、針路の情報源、手投げ発進とソアリングの段階、オートトリム |
| `POWER` | 10 Hz | バッテリー電圧と電流センサーの出力（フライトコントローラー基板の分圧器、[FC_BOARD.md](FC_BOARD.md)、ブロック B） |
| `SYS` | 1 Hz | 制御ループの周波数と最悪の周期、空きメモリ、iBUS のカウンター、IMU の温度、ブラックボックスのキュー、失われたレコード、フラッシュへの最長の書き込み、空き容量 |
| `EVENT` | イベント発生時 | ARM/DISARM、理由つきの ARM 拒否、モードの切り替え、通信の途絶 / 回復、センサーの故障 / 復帰、GPS のフィックス、ホームの記録、スイッチの機能、ジオフェンス、失速防止、手投げ発進とソアリングの段階 |

各フライトの先頭には、パラメーターが入ります。ファームウェア（ビルド日）、起動と直前の再起動の理由、搭載されているセンサーと飛行前チェックに合格したかどうか、PID の係数（ダッシュボードでの変更を含む）、トリム、`Config` の重要な値、スイッチの割り当てです。

## 使い方

### 飛行前

何もする必要はありません。電源を入れると、シリアルモニターに状態が表示されます（コンソールの出力はロシア語です。下の行は「ARM とスロットルを待機中 | 前方の消去済み 12.9 MB（約 11 分）/ 全体 13.9 MB | フライト数 1」という意味です）。

```
BlackBox: ждёт ARM и газ | стёрто впереди 12.9 МБ (≈11 мин) из 13.9 МБ | полётов 1
```

「前方の消去済み」は、次のフライトに入る量のことです。電源を入れたあと、ブラックボックスは数秒間（長いフライトのあとは最長 1 分）かけて空き容量を準備し、古い記録を消去します。その間、地上では飛行ループが約 0.15 秒止まることがあり、舵面が遅れてピクッと動くことがありますが、正常です。**空中でフラッシュが消去されることは決してありません。**

### 飛行後：ダウンロード

1. USB を **COM** コネクターにつなぎます。シリアルモニターは閉じてください（ポートを占有しているためです）。
2. プロジェクトのフォルダーで次を実行します。

   ```bash
   python tools/blackbox.py download          # 最後のフライト
   python tools/blackbox.py download --all    # すべて
   python tools/blackbox.py list              # ボードに入っているもの
   ```

   `pyserial` が必要です：`pip install pyserial`。または、すでに入っている PlatformIO の Python を使います：`%USERPROFILE%\.platformio\penv\Scripts\python tools\blackbox.py download`。

3. フライトは `blackbox/` フォルダーにダウンロードされ（約 200 KB/s：10 分のフライトで約 1 分）、すぐ隣の同名のフォルダーに展開されます。

ダウンロード中は飛行ループが止まるため、ARM していないときにしか実行できません。

### フライトのフォルダーの中身

| ファイル | 内容 |
|---|---|
| `summary.txt` | 概要：継続時間、周波数、角度・高度・速度・電圧の範囲、最悪の制御周期、失われたレコード、すべてのイベント |
| `events.txt` | フライトのパラメーターと、時刻順のすべてのイベント |
| `IMU.csv`、`CTRL.csv`、`RC.csv`、... | レコードの種類ごとに 1 つの表 |

すべての表の時刻は `time_s` で、記録開始（ARM とスロットル）からの秒数です。事前記録の部分はマイナスになります。値はすでに単位つきに換算されています。度、g、メートル、m/s、パルスのマイクロ秒です。`CTRL.csv` ではモードが名前で追加され（`mode_name`）、機能はリストになり（`features_on`）、フラグは 0/1 の列に分けられています（`armed`、`rx_lost`、`fs_glide`、`imu_ok` ...）。

CSV は Excel や LibreOffice で開けますが、時間軸のグラフには [PlotJuggler](https://github.com/facontidavide/PlotJuggler) のほうが便利です：File → Load Data → CSV、時刻の列は `time_s` を選びます。

`.bbl` ファイルはフラッシュの生イメージで、もう一度展開できます：`python tools/blackbox.py decode blackbox/flight_001_....bbl`。

### コンソール：`k`

シリアルモニターで `k` キーを押すと、ブラックボックスのメニューが開きます。状態、フライトの一覧、`r` で記録の手動開始 / 停止（テストベンチでの確認用）、`e` で全フライトの消去（`y` で確認、約 40 秒）です。

## フラッシュの空き容量

- フライトはリング状に書き込まれます。空きが少なくなると、ブラックボックスは地上で、前方に 10 MB の空きができるまで**最も古いフライトを丸ごと**消去します（`BLACKBOX_MIN_FREE_BYTES`、約 9 分）。
- **最後に記録されたフライトは決して消えません**。消えるのは、次の記録で場所が足りなくなったときに、その記録によって上書きされる場合だけです。
- 消去済みの領域が空中で尽きた場合、記録は PSRAM 内のキューに続けて書かれます（4 MB、直近の約 3 分のデータ）。着陸して DISARM すると、ブラックボックスが空きを作ってそれを書き出します。パーティション全体（約 11 分）より長いフライトは収まりきらず、最初の部分が残って最後の部分は失われます。
- だから、**飛行のたびにダウンロードしてください**。特に最初の飛行のあとは必ずです。

## 信頼性

- いつ電源が切れても（墜落、バッテリーが外れた場合など）、最後の約 15 ms を除いてすべて保存されます。書きかけのレコードは CRC によって破棄されます。`summary.txt` では、この件が「Недописанных записей (CRC)」という行（概要はロシア語で、「書きかけのレコード数（CRC）」という意味です）に出ます。
- フライト番号、リングの先頭、フライトの一覧は、セクターそのものから復元されます。壊れうる別個の「地図」はありません。
- ダウンロードでは、各セクターとフライト全体の CRC-32 が検証されます。

## 飛行への影響

- 飛行ループは、スナップショットを PSRAM 内のキューに入れるだけで、数マイクロ秒で済みます。フラッシュへの書き込みは、コア 0 上の別のタスクが 1 ページ（256 バイト）ずつ、**制御周期の直後**に行います。フラッシュへの書き込みは ESP32 の両方のコアを 0.6〜0.9 ms 止めますが、その停止が周期と周期のあいだの空き時間に収まるようにしています。
- テストベンチでの測定（センサーなしの DevKit、30〜40 秒の記録を 2 回）：周期の間隔は 2.00 ms、間隔の 99.2〜99.7% が 1.9〜2.1 ms の範囲に入り、最長は 2.5 ms で、抜けた周期は 1 つもありませんでした。周期の処理量は記録なしの場合と同じです。周期がはっきり揺らぐのは、地上で ARM していない間に、ブラックボックスが空き領域を照合して消去しているときだけです（64 KB ブロックの読み出しで約 3 ms の停止、消去で約 0.15 秒）。
- センサーがあると 1 周期は約 0.7 ms で、ページの書き込みは残りの 1.3 ms に収まります。最初のフライトのあとの確認方法：`summary.txt` の「Такт IMU」と「Цикл: худший такт」の行を見ます（ロシア語で、それぞれ「IMU の周期」と「ループ：最悪の周期」の意味です）。

## SD カード（STM32H743）

STM32H743 では、ブラックボックスは SD カード（SDMMC1 の µSD スロット、4 ビット、24 MHz）に書き込みます。カードは普通の **FAT32** のままです。ルートにあらかじめ作っておいたファイル `BLACKBOX.BIN` があり、ファームウェアはその中に生のブロックを書き込み、FAT テーブルやディレクトリには決して触れません。そのため、飛行中に電源が切れても壊れるものはなく、ファイルはそのまま PC にコピーできます。

### カードの準備（1 回だけ）

1. カードを **FAT32** でフォーマットします（exFAT は不可。Windows は 32 GB までのカードに FAT32 を提案します）。
2. カードをカードリーダーに入れて、PC で次を実行します。

   ```bash
   python tools/blackbox.py sd-prepare E:              # 64 MB、E: はカードのドライブ
   python tools/blackbox.py sd-prepare E: --size 256   # もっと大きくする場合
   ```

   ファイルは空のカード上に連続した 1 つの塊として作られ、`0xFF` で埋められます。最初のセクターは「リングは空」という管理用の印です。ファイルが連続していない場合（カードが空でなく、断片化がひどい場合）や、ファイルがない場合は、電源投入時にコンソールに理由が表示され、ブラックボックスは無効になります。
3. カードをボードに挿します。電源投入時には次のように表示されます（コンソールの出力はロシア語です。「SD カード：15204 MB、SDMMC 24 MHz、4 ビット、ファイル BLACKBOX.BIN：正常」、次に状態の行、最後に「300 ms で準備完了」という意味です）。

   ```
   SD-карта: 15204 МБ, SDMMC 24 МГц, 4 бита; файл BLACKBOX.BIN: ок
   BlackBox: ждёт ARM и газ | стёрто впереди 0.7 МБ из 64.0 МБ | полётов 0
   BlackBox: готов за 300 мс
   ```

   「前方の消去済み」はバックグラウンドで増えていきます。ボードは約 2.5 MB/s の速さで領域を照合します。

### フライトの取り出し

- **ボード経由で USB から**：ESP32 と同じく `python tools/blackbox.py download`（STM32 のコンソールは USB CDC で、ダウンロード速度は約 400 KB/s、1 MB は 3 秒未満です）。`list`、`--all`、`--flight N` も同じように使えます。
- **カードを抜いて**：カード上の `BLACKBOX.BIN` を、そのまま CSV に展開できます。

  ```bash
  python tools/blackbox.py ring E:/BLACKBOX.BIN              # 全フライト -> blackbox/
  python tools/blackbox.py ring E:/BLACKBOX.BIN --list       # 一覧表示のみ
  ```

  ファイルはセクターのリングです。ツールがセクター番号からフライトを自分で組み立てます。ファイルの末尾をまたいだフライトも含みます。

### ボードで測定した結果

DevEBox H743 + 16 GB のカード（テスト `test_blackbox_sd`、[TESTING.md](TESTING.md#stm32-ボード上のテスト)）：

| | |
|---|---|
| カードの認識 | 12〜18 ms、4 ビット、24 MHz |
| 256 B のページの書き込み | 平均 2.3〜3.7 ms、**最悪 60〜190 ms**、持続で約 75〜110 KB/s（必要なのは約 20 KB/s） |
| 読み出し | 4 KB のセクターで 4.2 MB/s、ランダムなブロックで 0.6 ms |
| 消去 | 64 KB で 13 ms、64 MB の領域全体で 20〜28 秒 |
| 電源投入 | リングが空なら 0 ms（印による）、フライトがあれば 0.3 秒（約 530 回の読み出しによる抜き取り照合）、64 MB の全照合なら約 20 秒かかる |
| 20 秒のリアルタイム記録（500 Hz の IMU） | 失われたレコードは 1 つもなく、エラーは 0 |
| 記録中の飛行タスク | 周期のずれ 2 ms に対して **1 µs**（記録のそばで最高優先度の模擬タスクを動かした場合） |

ページ書き込みの最悪値は、カード内部の「整理処理」によるものです。RAM のキュー（384 KB ≈ 19 秒分のデータ）は、こうした停止を吸収できます。この点で最も差が出るのは安価なカードです。飛行の前に `test_blackbox_sd` テストでカードを確認しておくとよいでしょう（最悪の書き込みは 250 ms 未満でなければなりません。SD 規格の上限です）。

### ESP32 のフラッシュとの違い

- **書き込みタスク**（`bbox`、優先度 2）は、カードへのアクセスの途中で飛行タスク（5）に割り込まれます。両方のコアを止める ESP32 のように「周期の空き時間に」書くわけではありません。転送には SDMMC のハードウェアフロー制御を使います。これがないと、割り込まれたときに FIFO があふれていました（ボード上では `HAL_SD_ERROR_RX_OVERRUN` が出て、コンソールと記録が数秒止まっていました）。
- **キューは RAM 上**にあり、4 MB の PSRAM ではなく 384 KB です（`BLACKBOX_RING_STM32_BYTES`）。
- **電源投入時の照合は抜き取り方式**です。リングの本物のセクターは連続した 1 本の弧になるので、約 500 個のヘッダーを読み、弧とフライトの境界を二分探索で絞り込みます。結果は全照合と同じです。つじつまが合わないときは全照合に切り替えます。
- **「リングは空」の印**をファイルの最初のセクターに置きます。電源を入れるたびに、空の領域を数秒かけて照合しなくて済むようにするためです。全消去したときと、全照合で何も見つからなかったときに付けられ、最初の書き込みの前に外されます。
- **カードのエラー**（抜かれた、バスの障害）は、1 秒に 1 回、イベント「носитель: ошибок записи …」としてログに記録されます（ロシア語で「記録媒体：書き込みエラー …」の意味です）。失われたページは `0xFF` の穴として残り、セクターの解析はそこで止まります（`tools/blackbox.py` と同じです）。ほかのセクターは無事です。

## 設定（`include/config/Config.h` の「ブラックボックス」セクション）

| 定数 | 標準値 | 意味 |
|---|---|---|
| `BLACKBOX_RING_BYTES` | 4 MB | PSRAM 内のキュー（PSRAM がない場合は `BLACKBOX_RING_NO_PSRAM_BYTES`、32 KB） |
| `BLACKBOX_RING_STM32_BYTES` | 384 KB | STM32：RAM 内のキュー |
| `BLACKBOX_SD_FILE`、`BLACKBOX_SD_MAX_BYTES` | `BLACKBOX.BIN`、256 MB | STM32：カード上のファイルと、使用する部分の上限 |
| `BLACKBOX_PREROLL_MS` | 10 000 | 開始前に何ミリ秒分を記録するか |
| `BLACKBOX_POSTROLL_MS` | 10 000 | DISARM の後に何ミリ秒分を記録するか |
| `BLACKBOX_LANDED_STOP_MS` | 30 000 | ARM したまま静止している場合は停止 |
| `BLACKBOX_LANDED_GYRO_DPS`、`_ACCEL_G`、`_CLIMB_MS`、`_SPEED_MS` | 5、0.1、0.5、2 | 何を「静止」とみなすか |
| `BLACKBOX_RESET_HOLD_MS` | 60 000 | 異常による再起動のあとの記録は、これより短くしない |
| `BLACKBOX_MIN_FREE_BYTES` | 10 MB | 次のフライトのために消去済みにしておく量 |
| `BLACKBOX_ERASE_PAUSE_MS` | 100 | 地上での消去と消去のあいだの休止 |
| `BLACKBOX_IMU_DIVIDER` | 1 | IMU を N 周期に 1 回記録する：2 なら 250 Hz で、記録時間は約 25% 長くなる |
| `BLACKBOX_VBAT_DIVIDER`、`_CURRENT_DIVIDER` | 6.6、1.667 | ボード上のバッテリーと電流センサーの分圧比 |

パーティションテーブルは `partitions_blackbox.csv` です。アプリケーションが 2 MB（ファームウェアは現在約 0.9 MB）、ブラックボックスが 13.9 MB、coredump が 64 KB です。NVS パーティションは元の位置のままなので、このテーブルに移行したあとも、IMU とコンパスのキャリブレーション、およびトリムは保持されます。無線経由のアップデート（OTA）用の 2 つ目のスロットはありません。

## 開発者向け

コードは `include/telemetry/BlackBox*.h` にあります。

| ファイル | 内容 |
|---|---|
| `BlackBoxFormat.h` | フォーマット：セクターヘッダー、レコードの種類と構造体、フィールドのスキーマ、CRC-8/CRC-32 |
| `BlackBoxStorage.h` | `IFlashRegion` 上のセクターのリング：電源投入時の先頭の検索、フライトの一覧、ページ単位の書き込み、古いフライトの段階的な消去 |
| `BlackBoxRing.h` | コア間のレコードのキュー（スピンロック）で、最も古いものを捨てる |
| `BlackBox.h` | 周期内のスナップショット、開始 / 停止、イベント、書き込みタスク、UART 経由のダウンロード |
| `hal/esp32/Esp32FlashPartition.h` | `esp_partition` の上に載せた `IFlashRegion` |
| `hal/SdFileRegion.h`、`storage/Fat32File.h` | FAT32 カード上のファイルの上に載せた `IFlashRegion`：ファイルの検索（FAT は読み取りのみ）、不完全なブロック、`0xFF` による消去、「リングは空」の印 |
| `hal/stm32/Stm32SdCard.h`、`src/stm32/sd_msp.cpp` | `IBlockDevice`：`HAL_SD` 上の SDMMC1（ポーリング、4 ビット、ハードウェアフロー制御）とピン |
| `hal/ResetCause.h` | ESP32 と STM32 での再起動の原因（`RCC->RSR`） |

### フラッシュ上のフォーマット

4 KB のセクター = 16 バイトのヘッダー（`magic "OPBB"`、通し番号の `seq`、オープン時の `millis()`、フライト番号、フォーマットのバージョン、チェックバイト）＋ 続けて並ぶレコード。レコードはセクターの境界をまたぎません。セクターの末尾は `0xFF` です。

レコード：`[種類 u8][長さ u8][データ][CRC-8]`。データは `t_us`（`micros()`）で始まります。フライトの最初のレコードは `SCHEMA` で、テキスト `"16 IMU t_us:I gx:h/10 ..."` が入っています。フィールド名、Python の `struct` の書式文字、除数です。デコーダーはフィールドの情報をログから取得するので、レコードに新しいフィールドを足すときは、`BlackBoxFormat.h` の構造体とスキーマ文字列を直せばよく（両者のサイズは `static_assert` が照合します）、デコーダーを変える必要はありません。

### ダウンロードのプロトコル

コマンドは STX バイト（`0x02`）に続く 1 行で、コンソールがそれをブラックボックスに渡します。

```
PC:  \x02bb list\n
FC:  BB:STATE state=idle free_kb=... total_kb=... flights=... rate_bps=...
     BB:FLIGHT n=3 sectors=234 kb=936 seconds=41 start=1
     BB:END
PC:  \x02bb get 3 2000000\n
FC:  BB:SEND n=3 sectors=234 baud=2000000   （115200 で）、その後 2 Mbaud に切り替える
PC:  2 Mbaud に切り替えて、'G' を送る
FC:  234 フレーム：A5 5A、u16 の番号、セクターの 4096 バイト、u32 の CRC-32
     115200 に戻り、BB:DONE n=3 crc=<全セクターの CRC-32>
```

### テスト

`pio test -e native -f native/test_blackbox_scan`：ランダムな履歴（300 個のリング × 5 回の探索ステップ）でリングの抜き取り照合を全照合と比較し、SD 領域での負荷を測定します。`pio test -e native-stm32 -f native_stm32/test_blackbox_sd` と `test_app_stm32_*`：FAT32、領域、カードのドライバー、カード上のブラックボックス、STM32 のファームウェア全体を確認します。ボード上では `pio test -e stm32h743-devebox -f test_blackbox_sd`（本物のカード）を実行します。

`pio test -e native -f native/test_blackbox`：フォーマット、パーティションの NOR の模擬の上に載せたリング（セクター単位の消去、書き込みはビットを下げるだけで、ビットを上げるとエラー扱い）、再起動、電源断、本物の `FlightController` / `Autopilot` でのフライトの記録、開始 / 停止、イベント、空中でのフラッシュのあふれ、ダウンロードを確認します。デコーダーの検証用のフライトイメージは次のコマンドで作れます：`OPENPLANE_BLACKBOX_DUMP=/tmp/f.bbl pio test -e native -f native/test_blackbox`。
