## Что нужно из железа

Минимальный комплект для сборки и полёта на ручном управлении:

- **Плата ESP32** — берите **esp32-c3-devkitm-1** (см. раздел ниже, почему).
- **RC-приёмник с поддержкой протокола iBUS** (FlySky и совместимые). Нужен только один провод данных — сериальный iBUS, никакого PPM/PWM на несколько проводов.
- **2 сервопривода MG90S** на элероны — по одному на каждую консоль крыла (это не общий элерон-сервопривод на оба крыла, а именно два независимых серво).
- **1 сервопривод MG90S** на лифт (руль высоты).
- **Регулятор оборотов (ESC) 40A**.
- **Мотор D2212 1000KV** + **пропеллер 10x5**.
- **Аккумулятор LiPo 3S**.
- Пульт управления с приёмником iBUS, минимум 4 канала (по факту прошивка ждёт до 10, но обязательны только CH1–CH3).

Опционально, для будущего автопилота (см. раздел про текущее состояние прототипа — на сегодня это не распаяно физически, но код это уже поддерживает):

- **MPU6050 (модуль GY-521)** — гироскоп + акселерометр, I2C.
- **BME280** — барометр/термометр, I2C.

Готовый планер, на котором всё это обкатывалось: размах крыла 1200 мм, хорда 250 мм, профиль NACA 4412, конструкция из PETG (3D-печать).

## Выбор платы и распиновка

Прошивка поддерживает три платы, переключение — один параметр при сборке (`pio run -e <имя окружения>`). Распиновка у каждой платы своя и жёстко прописана в прошивке под конкретное окружение — переставлять провода самовольно нельзя, нужно смотреть таблицу под свою плату.

> **Важно:** из трёх плат прямо сейчас реально прошита и облётана на стенде только **esp32-c3**. Две другие распиновки подобраны по документации чипа и логически, но **не проверены на реальном железе** — если соберёте на них, будьте особенно внимательны на первом включении (см. чек-лист ниже).

### esp32-c3 — облётана, используйте её

`pio run -e esp32-c3`, плата `esp32-c3-devkitm-1`.

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO5 |
| Элерон, правая консоль | GPIO4 |
| Лифт (руль высоты) | GPIO6 |
| ESC (газ) | GPIO7 |
| iBUS от приёмника (RX) | GPIO8 |
| I2C SDA (датчики) | GPIO1 |
| I2C SCL (датчики) | GPIO3 |

Это плата по умолчанию (`default_envs = esp32-c3` в `platformio.ini`) — если просто набрать `pio run -t upload` без указания окружения, соберётся именно она.

### esp32-s3 — целевая плата будущего борта, ЕЩЁ НЕ ОБЛЁТАНА

`pio run -e esp32-s3`, плата `esp32-s3-devkitc-1`.

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO4 |
| Элерон, правая консоль | GPIO5 |
| Лифт (руль высоты) | GPIO6 |
| ESC (газ) | GPIO7 |
| iBUS от приёмника (RX) | GPIO17 |
| I2C SDA (датчики) | GPIO8 |
| I2C SCL (датчики) | GPIO9 |

Планируется как основной лётный контроллер проекта, но пины подобраны по даташиту чипа, а не проверены живым тестом. Если у вас esp32-s3 — отнеситесь к первому включению как к стендовому тесту незнакомой платы.

### esp32-dev (обычная классическая ESP32, 38 пинов) — для стенда/отладки, НЕ ОБЛЁТАНА

`pio run -e esp32-dev`, плата `esp32dev`.

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO13 |
| Элерон, правая консоль | GPIO14 |
| Лифт (руль высоты) | GPIO27 |
| ESC (газ) | GPIO26 |
| iBUS от приёмника (RX) | GPIO16 |
| I2C SDA (датчики) | GPIO21 |
| I2C SCL (датчики) | GPIO22 |

Удобна тем, что это самая распространённая и дешёвая плата линейки — хорошо подходит для стендовой отладки прошивки на столе, но как и esp32-s3, распиновка не проверена в реальном полёте.

## Подключение приёмника

Всё, что нужно от приёмника — это **один провод данных iBUS**, который на большинстве FlySky-совместимых приёмников выведен на отдельный порт (часто подписан "iBUS" или это единственный не-PPM выход). Подключение:

- **Приёмник TX (выход iBUS)** → **RX-пин платы** из таблицы выше (GPIO8 на esp32-c3, GPIO17 на esp32-s3, GPIO16 на esp32-dev).
- **Земля (GND) приёмника** → **GND платы**. Обязательно, без общей земли протокол работать не будет.
- **Питание приёмника** — от отдельного BEC/регулятора или от 5V платы, в зависимости от того, чем вы обычно питаете приёмник в своих сборках; это не завязано на конкретный пин прошивки.

Прошивка не отправляет ничего обратно приёмнику — она только слушает, поэтому линию TX платы никуда подключать не нужно.

Скорость порта iBUS в прошивке — 115200 бод, это стандарт для протокола, менять не нужно, приёмник сам держит эту скорость.

## Карта RC-каналов

Ниже — актуальная, исправленная карта каналов. Если вы видели где-то более раннюю версию, где форсаж (boost) висел на CH6 — она устарела, сейчас это CH8.

| Канал | Название | Что делает |
|---|---|---|
| CH1 | AILERON | Крен — управление элеронами |
| CH2 | ELEVATOR | Тангаж — управление лифтом (рулём высоты) |
| CH3 | THROTTLE | Газ. 1000 мкс = выключен, 2000 мкс = максимум |
| CH4 | RUDDER | Рысканье — **сейчас не используется прошивкой** |
| CH5 | FLAPS | Закрылки, 3 положения: <1250 мкс — убраны, 1250–1749 мкс — половина (доп. смещение элеронов 50 мкс), ≥1750 мкс — выпущены (доп. смещение 100 мкс) |
| CH6 | AUX_1 | Свободный вспомогательный канал, по умолчанию управляет автопилотным режимом AUTO_TAKEOFF |
| CH7 | AUX_2 | Свободный вспомогательный канал, по умолчанию управляет автопилотным режимом ALT_HOLD |
| CH8 | BOOST | Форсаж газа — см. раздел про ARM/failsafe/boost ниже. **Не свободен для назначения автопилоту** |
| CH9 | AUX_4 | Свободный вспомогательный канал, по умолчанию управляет автопилотным режимом STABILIZE |
| CH10 | AUX_5 | Свободный вспомогательный канал, по умолчанию управляет режимом MANUAL (ручное управление, автопилот выключен) |

Все значения каналов — стандартный диапазон импульса приёмника 1000–2000 мкс, 1500 мкс — центр/нейтраль.

## Каналы автопилота

Четыре вспомогательных канала (CH6, CH7, CH9, CH10) назначены под режимы автопилота. Они специально расставлены так, чтобы обойти CH8 (форсаж) и не конфликтовать с ним.

| Канал | Режим по умолчанию | Что делает режим |
|---|---|---|
| CH6 | AUTO_TAKEOFF | Автоматический сценарий взлёта по времени: разгон, затем набор тангажа, газ по фазам |
| CH7 | ALT_HOLD | Удержание высоты, зафиксированной в момент включения режима |
| CH9 | STABILIZE | Автоматическое выравнивание крена и тангажа к горизонту |
| CH10 | MANUAL | Автопилот выключен, чистое ручное управление |

Логика переключателя: **<1500 мкс — выключено, ≥1500 мкс — включено**. Если вы одновременно включили несколько слотов сразу (например и CH6, и CH9), побеждает тот, что стоит раньше в списке — то есть CH6 приоритетнее CH9, а CH9 приоритетнее CH10, и так далее по порядку CH6 → CH7 → CH9 → CH10.

**Назначения можно поменять на лету** без перепрошивки — через веб-дашборд (запрос `POST /api/assignfeature`, на практике — просто через кнопки на странице дашборда с телефона, см. раздел про дашборд ниже). Если ничего не трогать, действует порядок из таблицы выше.

## ARM, failsafe и форсаж

### Процедура ARM

Чтобы прошивка перешла в состояние "armed" (взведено), нужно **удержать газ (CH3) на минимуме не менее 1.5 секунды**. Это стандартная защитная процедура — так исключается случайный резкий газ сразу при включении.

**Важно и без прикрас:** на сегодняшний день ARM в прошивке — это **только индикатор состояния**, он **не блокирует физически подачу газа**. Единственный реальный предохранитель от непроизвольного газа — это failsafe при потере сигнала (см. ниже). Ведите себя так, будто пропеллер может начать вращаться в любой момент, как только на ESC подан газ выше минимума, независимо от того, "armed" сейчас борт или нет.

### Failsafe

Если приёмник перестаёт присылать валидные кадры дольше **500 мс**, прошивка считает, что сигнал потерян, и это имеет **абсолютный приоритет** над всем остальным (даже над автопилотом): элероны и лифт уходят в нейтраль (1500 мкс), газ — на выключение (1000 мкс), состояние ARM сбрасывается. Это встроено в самый верхний уровень логики платы и срабатывает независимо от текущего режима.

Практически это значит: если вы улетели за пределы дальности связи или пульт отключился, мотор должен заглохнуть сам в течение полусекунды.

### Форсаж (BOOST, CH8)

- **<1250 мкс** — форсаж разблокирован (готов к использованию, но ещё не сработал).
- **≥1750 мкс** — форсаж активируется: газ выставляется на максимум на **5 секунд**, после чего автоматически отключается сам.
- Чтобы включить форсаж повторно, канал нужно **сначала вернуть в положение <1250 мкс**, снова "взвести" его, а потом снова поднять выше 1750 мкс.

В обычном (не форсажном) режиме газ дополнительно ограничен: прошивка не даёт выйти за **40% хода газа** от полного диапазона — это сделано, чтобы обычный полёт не был на пределе тяги мотора, а форсаж давал кратковременный полный запас.

## Прошивка платы

Прошивка собирается через **PlatformIO** (framework Arduino, C++).

### Установка PlatformIO

Проще всего поставить расширение **PlatformIO IDE** в VS Code (Extensions → найти "PlatformIO IDE" → Install), тогда появится и CLI, и удобные кнопки сборки в интерфейсе. Также можно поставить командой `pip install platformio` и работать через терминал — оба варианта используют одни и те же команды `pio`.

### Сборка и заливка

Откройте проект (папку репозитория) в VS Code с установленным PlatformIO, подключите плату по USB и выполните в терминале, выбрав команду под свою плату:

```bash
# esp32-c3 (единственная реально облётанная — используйте эту, если не уверены)
pio run -e esp32-c3 -t upload

# esp32-s3 (целевая плата, распиновка не проверена на железе)
pio run -e esp32-s3 -t upload

# esp32-dev (классическая ESP32 38-pin, для стенда)
pio run -e esp32-dev -t upload
```

Если вообще не указать `-e`, соберётся плата по умолчанию — `esp32-c3`.

### Монитор порта

Чтобы увидеть отладочный вывод (состояние каналов, ARM, датчики) прямо в консоли по USB:

```bash
pio device monitor -b 115200
```

Скорость обязательно 115200 — иначе увидите нечитаемую кашу вместо текста.

## Веб-дашборд в поле

На плате поднимается собственная Wi-Fi точка доступа — не нужно никакого домашнего роутера или интернета, всё работает прямо в поле с телефона.

**Как подключиться:**

1. На телефоне или ноутбуке откройте список Wi-Fi сетей.
2. Подключитесь к сети **`OpenPlane-Debug`**, пароль **`12345678`**.
3. Откройте в браузере адрес **`http://192.168.4.1`**.

Никакого приложения ставить не нужно — это обычная веб-страница.

**Что можно делать с телефона в поле, без всякого программирования:**

- Смотреть **живые полоски всех 10 RC-каналов** — удобно проверить, что пульт и приёмник действительно шлют то, что вы двигаете на стике, ещё до того как подключать сервоприводы.
- Видеть статус каждого выхода (элерон левый/правый, лифт, ESC) — подключён ли канал программно.
- Видеть, отвечают ли датчики (IMU, барометр), если они у вас распаяны — честно показывается либо реальные данные (крен/тангаж/высота), либо явная пометка, что датчика физически нет или он не отвечает.
- **Менять режим автопилота** кнопками (ручной / стабилизация / автовзлёт / удержание высоты) прямо со страницы — без пульта.
- **Настраивать коэффициенты ПИД-регулятора** (для крена и тангажа) через форму на странице — полезно для постепенной настройки стабилизации без перепрошивки.
- **Перепривязать, какой вспомогательный канал пульта отвечает за какой режим автопилота** — те самые CH6/CH7/CH9/CH10 из таблицы выше, если хотите, например, поменять местами STABILIZE и ALT_HOLD под свою привычную раскладку пульта.

Дальность этой точки доступа — по факту, десятки метров, это обычный Wi-Fi ESP32, а не дальнобойная телеметрия. Это инструмент для настройки на столе, на стенде и рядом с полем — не для управления бортом в полёте на удалении.

## Предполётный чек-лист и безопасность

Прочитайте этот раздел целиком **до** первого включения, а не после инцидента.

### Обязательно перед любым стендовым тестом

- [ ] **Пропеллер физически СНЯТ**, если вы проверяете каналы, ARM, дашборд, настраиваете ПИД или просто включаете плату впервые на новой распиновке. ESC может дёрнуть мотор на любом этапе теста — это не гипотетический риск, это нормальное поведение при первом включении.
- [ ] LiPo аккумулятор проверен на вздутие/повреждение, заряжен корректным зарядным устройством для LiPo, хранится и заряжается на негорючей поверхности.
- [ ] Пульт включён и его каналы проверены на дашборде (`http://192.168.4.1`) **до** того как аккумулятор подключён к ESC.

### Перед полётом

- [ ] Открытая площадка, без людей и построек в радиусе, достаточном для планера с размахом 1200 мм на ручном управлении с нештатным поведением сервоприводов/крыла (см. раздел про ограничения прототипа ниже — крепление мотора и крыло пока не усилены карбоном).
- [ ] Все три поверхности (элерон левый, элерон правый, лифт) двигаются в верном направлении при отклонении стика — проверьте на столе перед каждым вылетом, а не полагайтесь на память с прошлого раза.
- [ ] Радиус действия пульта проверен, батарея пульта заряжена.
- [ ] Помните: канал ARM переведён в "armed" **не означает**, что газ заблокирован до этого момента — держите руки и лицо подальше от пропеллера в любой момент, когда LiPo подключён к ESC, независимо от состояния ARM на дашборде.
- [ ] Убедитесь, что вы физически можете быстро отключить питание (доступ к разъёму LiPo), а не полагаетесь только на failsafe по потере сигнала — failsafe глушит газ через 500 мс после потери сигнала, но это не резервная кнопка "выключить прямо сейчас".

### Общая техника безопасности с LiPo

- Никогда не оставляйте заряжающийся LiPo без присмотра.
- Не подключайте/не отключайте LiPo к ESC, стоя рядом с плоскостью вращения пропеллера.
- Возите и храните LiPo в защитной сумке/контейнере.

## Troubleshooting

**"Нет сигнала приёмника" / RX выглядит нормально, но каналы на дашборде не двигаются**
Проверьте, что провод данных приёмника подключён именно на RX-пин iBUS из таблицы вашей платы (GPIO8/GPIO17/GPIO16), а не перепутан с землёй или питанием, и что земля приёмника и платы объединена. Если распиновка совпадает и провода целы, а сигнала всё равно нет — проверьте, что приёмник в принципе привязан (bind) к пульту и что выход на приёмнике настроен именно на iBUS, а не на PPM/SBUS.

**Датчик (IMU или барометр) показывает "не отвечает" / NO_RESPONSE**
Это ожидаемо, если датчик физически не распаян на плате — прошивка честно про это сообщает вместо того чтобы выдавать нули как будто всё в порядке. Если вы уверены, что распаяли MPU6050/BME280, проверьте: (1) земля датчика подключена к земле платы; (2) SDA/SCL подключены на I2C-пины именно вашей платы (см. таблицу распиновки); (3) I2C-адрес устройства действительно на линии — стандартный адрес MPU6050 0x68 (иногда 0x69), BME280 — 0x76 (иногда 0x77), в зависимости от того, как разведён пин ADDR/SDO на конкретном модуле.

**Сервопривод не двигается, хотя на дашборде выход показан подключённым ("attached")**
"Подключён" на дашборде означает только то, что прошивка выделила GPIO/таймер под этот канал программно — обратной связи по току или реальному движению рупора у платы нет, это физически невозможно проверить программно. Если выход "attached", а серво стоит на месте, проверьте по цепочке от платы: (1) серво реально запитано (5V/питание отдельно от логики платы, если у вас так разведено); (2) сигнальный провод серво идёт именно на GPIO из таблицы вашей платы, а не перепутан между левым/правым элероном; (3) серво не заклинило механически (роговина упирается в тягу/корпус); (4) серво в принципе исправно — проверьте его напрямую от отдельного тестера/приёмника в обход платы.

**Мотор не крутится совсем, хотя газ на дашборде реагирует на стик**
Проверьте, что LiPo подключён к ESC, ESC откалиброван под ваш пульт/диапазон импульсов, и что вы держали газ на минимуме положенные 1.5 секунды для ARM — хотя, как сказано выше, отсутствие ARM само по себе газ не блокирует, так что если мотор не крутится именно из-за газа, а не из-за ESC/питания, это тоже стоит перепроверить отдельно осциллографом/тестером ESC, а не считать заведомо программной причиной.

**После прошивки плата не выходит на связь / точка доступа `OpenPlane-Debug` не появляется**
Убедитесь, что заливка (`pio run -e <ваша плата> -t upload`) прошла без ошибок и что вы прошили именно то окружение, которое физически держите в руках (esp32-c3 отличается от esp32-s3 и esp32-dev не только пинами, но и чипом — прошивка под чужой чип на плату не встанет или встанет некорректно). Проверьте вывод монитора порта (`pio device monitor -b 115200`) сразу после перезагрузки платы — там печатается, на каком этапе setup() находится плата.

## Текущее состояние прототипа-планера

Чтобы ожидания были честными:

- Первый прототип **уже летал**. По итогам выявлены проблемы: **недостаточная прочность крепления мотора** и **недостаточная прочность крыла** — крылу нужно усиление карбоном. Также требуется дополнительная настройка сервоприводов. Учитывайте это при планировании собственных полётов — это не абстрактная оговорка, а реальный отказ, уже случившийся на этом прототипе.
- **IMU (MPU6050) и барометр (BME280) физически ещё не распаяны** на текущей плате. Код автопилота полностью написан, скомпилирован и подключён в прошивку — это подтверждено живым тестом на реальной плате, датчики честно отвечают "нет ответа", а не притворяются рабочими. То есть автопилот программно готов принять датчики в любой момент, но пока не испытан в полёте — сегодня борт летает только на чистом ручном управлении, автопилотные режимы можно включить на дашборде, но без датчиков они не дадут коррекций.
- Если/когда барометр появится на борту: имейте в виду, что абсолютная высота в текущей реализации — это приближение, не откалиброванное по полной формуле датчика, поэтому не ориентируйтесь на неё как на точную величину. Для удержания высоты (ALT_HOLD) это не критично, потому что важна не абсолютная точность, а стабильность показаний относительно точки включения режима.
- Лицензия проекта пока не выбрана.

Если вы строите свой борт по этому гайду — начните с esp32-c3 (единственная реально проверенная распиновка), пролетайте его на ручном управлении, и только потом переходите к датчикам и автопилоту.
