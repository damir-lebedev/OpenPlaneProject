# Гайд пилота OpenPlaneProject

Это практический гайд «что куда подключать и как летать» для тех, кто держит в руках паяльник и пульт, а не читает исходники. Если хочется разобраться в архитектуре кода — это в другие документы репозитория. Здесь — только железо, каналы, прошивка и полёты.

Репозиторий: https://github.com/damir-lebedev/OpenPlaneProject, ветка `main`.

Сразу честно: проект в активной разработке, это **не готовый продукт**. Первый прототип уже летал, но с оговорками, которые ниже расписаны отдельным разделом. Читайте его перед полётом, а не после.

## Что нужно из железа

Комплект текущей сборки (на нём проверена прошивка):

- **Плата ESP32-S3 N16R8** (DevKitC-1-клон с двумя USB-C: "USB" и "COM").
- **Пульт FS-i6 + приёмник FS-iA6B** (протокол iBUS, 10 каналов). Нужен один провод данных — порт iBUS SERVO. Пульт должен уметь задавать failsafe — это обязательная настройка, см. раздел про failsafe.
- **2 сервопривода MG90S** на элероны — по одному на каждую консоль (два независимых серво, не один на оба крыла).
- **1 сервопривод MG90S** на лифт (руль высоты).
- **1 сервопривод MG90S** на руль направления — на его же ось посажено рулевое колесо шасси (руление на земле).
- **Регулятор оборотов (ESC)** 60–80A с BEC 5V (BEC питает сервы и приёмник).
- **Мотор D3548 1100KV** + **пропеллер 10x5**.
- **Аккумулятор LiPo 3S**.

Датчики автопилота (все по I2C, без них борт летает в ручном режиме):

- **GY-521** — гироскоп + акселерометр (на плате бывает MPU6050 или, как у нас, MPU6500 — оба поддерживаются).
- **BMP388** — барометр.
- **GY-273** — компас (у нас на нём QMC5883P; QMC5883L тоже поддерживается).
- Опционально **OLED 128×64 SSD1306** (I2C) — экран статуса на борту.

Планер: размах крыла 1200 мм, хорда 250 мм, профиль NACA 4412, конструкция из PETG (3D-печать). Первый прототип летал на ESP32-C3, моторе D2212 1000KV и ESC 40A.

## Выбор платы и распиновка

Прошивка поддерживает три платы, переключение — один параметр при сборке (`pio run -e <имя окружения>`). Распиновка у каждой платы своя и жёстко прописана в прошивке под конкретное окружение — переставлять провода самовольно нельзя, нужно смотреть таблицу под свою плату.

> **Важно:** основная плата теперь **esp32-s3 (N16R8)** — её распиновка проверена на стенде со всеми датчиками. **esp32-c3** — старый облётанный прототип. Распиновка **esp32-dev** подобрана по документации чипа и **не проверена на реальном железе**.

### esp32-s3 (N16R8) — основная плата, проверена на стенде

`pio run -e esp32-s3`, плата `esp32-s3-devkitc-1` с настройками под модуль N16R8 (16 МБ флеша, 8 МБ octal PSRAM). Это плата по умолчанию (`default_envs = esp32-s3`).

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO4 |
| Элерон, правая консоль | GPIO5 |
| Лифт (руль высоты) | GPIO6 |
| ESC (газ) | GPIO7 |
| Руль направления + рулевое колесо | GPIO18 |
| iBUS от приёмника (RX) | GPIO17 |
| I2C датчиков SDA / SCL (MPU, BMP388, компас) | GPIO8 / GPIO9 |
| I2C OLED SDA / SCL (отдельная шина) | GPIO1 / GPIO2 |
| Резерв: SPI (ICM42688) SCK / MISO / MOSI / CS | GPIO12 / 13 / 11 / 10 (+ CS BMP388 — GPIO21) |
| Резерв: GPS RX / TX | GPIO15 / GPIO16 |

Не занимать: GPIO0/3/45/46 (от них зависит режим загрузки), 19/20 (USB), 26–32 (флеш), 33–37 (PSRAM у N16R8), 43/44 (разъём "COM"), 48 (RGB-светодиод).

Подключение датчиков на стенде (все модули — от **3.3V**, не от 5V):

| Модуль | Пины |
|---|---|
| MPU-6050 / GY-521 (на плате может стоять MPU6500 — это нормально) | VCC–3.3V, GND–GND, SCL–GPIO9, SDA–GPIO8, AD0–GND, INT/XDA/XCL — не подключать. Плата чипом вверх, стрелка X — к носу; поворот осей чипа — `IMU_ROTATION_CW_DEG` в `Config.h` (у нашего клона 90) |
| BMP388 | VCC–3.3V, GND–GND, SCL–GPIO9, SDA–GPIO8, SDO–GND (адрес 0x76), **CSB–3.3V** (иначе чип уходит в SPI), INT — не подключать |
| GY-273 (QMC5883P) | VCC–3.3V, GND–GND, SCL–GPIO9, SDA–GPIO8, DRDY — не подключать. Подальше от проводов серв/ESC/мотора |
| OLED 128×64 SSD1306 | VCC–3.3V, GND–GND, SCL–GPIO2, SDA–GPIO1 |

Сервы питаются **не от платы**, а от BEC регулятора (или отдельного 5V ≥2 А); земля всех источников общая. Красный провод ESC не подключать к 5V платы, пока воткнут USB.

### esp32-c3 — старый прототип, облётан

`pio run -e esp32-c3`, плата `esp32-c3-devkitm-1`.

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO5 |
| Элерон, правая консоль | GPIO4 |
| Лифт (руль высоты) | GPIO6 |
| ESC (газ) | GPIO7 |
| Руль направления | — (свободных пинов нет) |
| iBUS от приёмника (RX) | GPIO8 |
| I2C SDA (датчики) | GPIO1 |
| I2C SCL (датчики) | GPIO3 |

### esp32-dev (обычная классическая ESP32, 38 пинов) — для стенда/отладки, НЕ ОБЛЁТАНА

`pio run -e esp32-dev`, плата `esp32dev`.

| Назначение | GPIO |
|---|---|
| Элерон, левая консоль | GPIO13 |
| Элерон, правая консоль | GPIO14 |
| Лифт (руль высоты) | GPIO27 |
| ESC (газ) | GPIO26 |
| Руль направления | GPIO25 |
| iBUS от приёмника (RX) | GPIO16 |
| I2C SDA (датчики) | GPIO21 |
| I2C SCL (датчики) | GPIO22 |

Удобна тем, что это самая распространённая и дешёвая плата линейки — подходит для стендовой отладки прошивки, но распиновка не проверена на железе.

## Подключение приёмника

Всё, что нужно от приёмника — это **один провод данных iBUS**, который на большинстве FlySky-совместимых приёмников выведен на отдельный порт (часто подписан "iBUS" или это единственный не-PPM выход). Подключение:

- **Приёмник TX (выход iBUS)** → **RX-пин платы** из таблицы выше (GPIO8 на esp32-c3, GPIO17 на esp32-s3, GPIO16 на esp32-dev).
- **Земля (GND) приёмника** → **GND платы**. Обязательно, без общей земли протокол работать не будет.
- **Питание приёмника** — от отдельного BEC/регулятора или от 5V платы, в зависимости от того, чем вы обычно питаете приёмник в своих сборках; это не завязано на конкретный пин прошивки.

Прошивка не отправляет ничего обратно приёмнику — она только слушает, поэтому линию TX платы никуда подключать не нужно.

Скорость порта iBUS в прошивке — 115200 бод, это стандарт для протокола, менять не нужно, приёмник сам держит эту скорость.

## Карта RC-каналов

Карта проверена на стенде с пультом FS-i6 (10 каналов, режим 2) и приёмником FS-iA6B.

| Канал | Орган пульта | Название | Что делает |
|---|---|---|---|
| CH1 | правый стик ←→ | AILERON | Крен — элероны (2000 = вправо) |
| CH2 | правый стик ↑↓ | ELEVATOR | Тангаж — лифт (2000 = от себя, нос вниз) |
| CH3 | левый стик ↑↓ | THROTTLE | Газ. 1000 мкс = выключен, 2000 мкс = максимум, без ограничений |
| CH4 | левый стик ←→ | RUDDER | Руль направления и рулевое колесо шасси (одна серва) |
| CH5 | SwA | ARM | Тумблер ARM — см. раздел про ARM ниже |
| CH6 | SwB | FLAPS | Закрылки: вниз, к себе — выпущены, вверх — убраны (см. ниже) |
| CH7 | SwC (3 положения) | AUX_2 | Режим автопилота: <1250 мкс — MANUAL, 1250–1749 мкс — STABILIZE, ≥1750 мкс — AUTO_TAKEOFF |
| CH8 | SwD | AUX_3 | Свободен (раньше был форсаж — убран вместе с лимитом газа 40%) |
| CH9 | VrA | AUX_4 | Свободен |
| CH10 | VrB | AUX_5 | Свободен |

Все значения каналов — стандартный диапазон импульса приёмника 1000–2000 мкс, 1500 мкс — центр/нейтраль.

### Закрылки (флапероны)

Отдельных закрылков нет — их роль играют элероны. **SwB вниз** (к себе): оба элерона плавно, примерно за секунду, опускаются на одинаковый угол (`FLAPS_DEPLOYED_US` = 220 мкс ≈ 20° поворота качалки — меняется в `include/Config.h`). Это увеличивает подъёмную силу для взлёта и посадки на меньшей скорости. Крен стиком и автопилотом при этом работает как обычно — элероны расходятся в разные стороны, но уже вокруг опущенного положения. **SwB вверх** — так же плавно убираются. На OLED при выпущенных закрылках в первой строке горит `FL`.

При полном крене с выпущенными закрылками опускающийся элерон упирается в край хода раньше поднимающегося — это нормально, работает как дифференциал элеронов.

Выпуск закрылков обычно поднимает нос — будьте готовы чуть отдать ручку от себя; если эффект сильный, это настраивается уменьшением `FLAPS_DEPLOYED_US`.

## Каналы автопилота

Режим автопилота выбирается **одним каналом CH7** (тумблер SwC: вверх — MANUAL, середина — STABILIZE, вниз — AUTO_TAKEOFF):

| Положение CH7 | Режим | Что делает режим |
|---|---|---|
| <1250 мкс | MANUAL | Автопилот выключен, чистое ручное управление |
| 1250–1749 мкс | STABILIZE | Автоматическое выравнивание крена и тангажа к горизонту поверх стиков |
| ≥1750 мкс | AUTO_TAKEOFF | Автовзлёт (см. ниже) |

**AUTO_TAKEOFF.** После ARM ничего не происходит, пока вы сами не поднимете газ выше половины — это защита от раскрутки мотора сразу после взвода. Дальше: 0–1 с — газ плавно до 100%, крылья ровно, тангаж 0° (разгон / бросок с руки); 1–3 с — 100%, тангаж +15°; дальше — 100%, тангаж +10°, пока вы не переключите SwC. Газ в этом режиме = максимум из стика и программы: добавить можно, убрать ниже программы — нет. Выход — SwC в другое положение или DISARM.

Стабилизация (в STABILIZE и AUTO_TAKEOFF) двигает рули и когда борт **не заармлен** — так на столе видно, в какую сторону она отвечает на наклон. Интегратор при этом не копится.

Знаки углов (как на OLED и в логе): **крен R > 0 — правое крыло вниз, тангаж P > 0 — нос вверх.**

Никакой неоднозначности с приоритетами тут нет — включён всегда ровно один режим, потому что это одно и то же значение одного канала, а не несколько независимых переключателей.

**ALT_HOLD с пульта не выбирается.** Он остаётся доступен только с веб-дашборда (`POST /api/setmode`, кнопка на странице) — включается там и держится, пока вы физически не переведёте CH7 в другое положение (тогда самолёт вернётся к тому режиму, который показывает CH7).

## ARM и failsafe

### Процедура ARM

- **ARM:** газ (CH3) внизу → тумблер **SwA (CH5) вниз, к себе** (на FS-i6 это CH5 = 2000; вверх = 1000). В Serial появится `ArmingManager: ARM`, на OLED — `ARMED`.
- **DISARM:** SwA вверх, от себя — мгновенно, в любой момент, мотор сразу останавливается.
- Если SwA перевели в ARM с газом не внизу или не прошли предполётные проверки — ARM **не** происходит (причина печатается в Serial). Нужно вернуть SwA вверх, убрать газ и снова перевести вниз.
- Если плату включили с SwA уже в положении ARM (вниз) — она **не** армится: прошивка должна сначала увидеть SwA вверху (OFF).

**ARM реально блокирует газ:** пока борт не armed, газ на ESC принудительно держится на минимуме независимо от стика. Перед взводом проверяется, что датчики, нужные выбранному режиму CH7, отвечают — например, STABILIZE без живого IMU не заармится, пока не переключитесь в MANUAL. Всё равно ведите себя так, будто пропеллер может начать вращаться в любой момент после ARM.

### Failsafe

Потеря связи имеет **абсолютный приоритет** над всем остальным (даже над автопилотом): элероны и лифт уходят в нейтраль (1500 мкс), газ — на выключение (1000 мкс). Прошивка распознаёт потерю связи двумя способами:

1. **Нет iBUS-кадров дольше 500 мс** — обрыв провода или приёмник без питания.
2. **Газ ниже 950 мкс** — так приёмник сообщает, что потерял пульт. **Это требует настройки failsafe в пульте** (см. ниже): FS-iA6B при потере связи НЕ перестаёт слать кадры, а повторяет последние значения стиков — без настройки прошивка потерю связи не увидит, и самолёт продолжит лететь с последним газом.

ARM при failsafe **не** сбрасывается: когда связь вернулась, самолёт снова слушается стиков без повторного взвода (переключать тумблер в воздухе с газом в ноль опаснее).

### Настройка failsafe в пульте FS-i6 (обязательно, один раз)

Идея: при потере связи приёмник должен выдавать газ ~900 мкс — ниже нормального минимума 1000.

1. `Menu → Functions setup → End points` → канал 3: нижнюю точку (левое значение) поставить **120%**. Сохранить (долгое нажатие Cancel).
2. Газ — **в самый низ**.
3. `Menu → Functions setup → Failsafe` → Channel 3 → **On**, газ всё ещё внизу → сохранить долгим нажатием Cancel. Приёмник запомнит ~900 мкс.
4. Вернуться в `End points` → канал 3 → нижнюю точку обратно **100%**. Сохранить.
5. Проверка: ARM не нужен. Выключите пульт — в Serial через ~1 с появится `RX=LOST(failsafe пульта)`, на OLED — инверсная строка `RX LOST`. Включите пульт — `RX=OK`.

Триммер газа держите в центре: с сильно опущенным триммером газ может уйти ниже 950 и прошивка примет это за потерю связи.

Раньше здесь был **форсаж на CH8** и лимит газа 40% — они убраны: лимит берёг слабую сборку 3S1P, новым аккумуляторам полный газ не страшен. Форсаж к тому же включался сам, если SwD был поднят при включении платы.

## Прошивка платы

Прошивка собирается через **PlatformIO** (framework Arduino, C++).

### Установка PlatformIO

Проще всего поставить расширение **PlatformIO IDE** в VS Code (Extensions → найти "PlatformIO IDE" → Install), тогда появится и CLI, и удобные кнопки сборки в интерфейсе. Также можно поставить командой `pip install platformio` и работать через терминал — оба варианта используют одни и те же команды `pio`.

### Сборка и заливка

Откройте проект (папку репозитория) в VS Code с установленным PlatformIO, подключите плату по USB и выполните в терминале, выбрав команду под свою плату:

```bash
# esp32-s3 N16R8 (основная плата)
pio run -e esp32-s3 -t upload

# esp32-c3 (старый прототип)
pio run -e esp32-c3 -t upload

# esp32-dev (классическая ESP32 38-pin, для стенда)
pio run -e esp32-dev -t upload
```

Если вообще не указать `-e`, соберётся плата по умолчанию — `esp32-s3`.

**esp32-s3:** у платы два разъёма USB-C. Прошивка и Serial идут через разъём **"COM"** (мост CH343, в Windows — "USB-Enhanced-SERIAL CH343"). Разъём "USB" (нативный USB чипа) для работы не нужен, но может быть воткнут — ничему не мешает.

### Монитор порта

Чтобы увидеть отладочный вывод (состояние каналов, ARM, датчики) прямо в консоли по USB:

```bash
pio device monitor -b 115200
```

Скорость обязательно 115200 — иначе увидите нечитаемую кашу вместо текста. Раз в 10 секунд печатается строка `SYS:` — частота цикла (должна быть ~500 Гц), время цикла, счётчики iBUS, свободная память.

### Консоль (команды в мониторе порта)

Буква + Enter. Калибровки работают только когда не заармлено.

| Команда | Что делает |
|---|---|
| `h` | список команд |
| `s` | подробный статус всех датчиков (включая счётчики ошибок I2C) |
| `i` | повторная калибровка IMU — 2 с, плату не двигать, стоять так, как самолёт должен лететь ровно |
| `m` | калибровка компаса — 15 с вращать плату/самолёт по всем осям. Результат сохраняется во флеш и переживает перезагрузку |

При каждом включении IMU калибруется сам (~2 с): **включайте плату неподвижно и ровно** — это положение станет "горизонтом" для стабилизации.

### OLED-экран

Если OLED подключён (GPIO1/GPIO2), на нём 5 раз в секунду:

```
RX ok disarm STAB        <- связь / ARM / режим (при потере связи строка инверсная)
R  +1.2 P  -0.4          <- крен / тангаж, °
Alt +0.3 Vz +0.1         <- высота от точки включения, м / вертикальная скорость, м/с
Hdg 123  Thr 1000        <- курс по компасу / газ на ESC, мкс
L1500 R1500 E1500        <- PWM элеронов и лифта, мкс
Loop 500Hz max 1100us    <- частота и худшее время цикла
```

## Веб-дашборд в поле

На плате поднимается собственная Wi-Fi точка доступа — не нужно никакого домашнего роутера или интернета, всё работает прямо в поле с телефона.

**Как подключиться:**

1. На телефоне или ноутбуке откройте список Wi-Fi сетей.
2. Подключитесь к сети **`OpenPlane-Debug`**, пароль **`12345678`**.
3. Откройте в браузере адрес **`http://192.168.4.1`**.

Никакого приложения ставить не нужно — это обычная веб-страница.

**Что можно делать с телефона в поле, без всякого программирования:**

- Смотреть **живые полоски всех 10 RC-каналов** — удобно проверить, что пульт и приёмник действительно шлют то, что вы двигаете на стике, ещё до того как подключать сервоприводы.
- Видеть статус каждого выхода (элерон левый/правый, лифт, ESC) — подключён ли канал программно.
- Видеть, отвечают ли датчики (IMU, барометр), если они у вас распаяны — честно показывается либо реальные данные (крен/тангаж/высота), либо явная пометка, что датчика физически нет или он не отвечает.
- **Менять режим автопилота** кнопками (ручной / стабилизация / автовзлёт / удержание высоты) прямо со страницы — без пульта.
- **Настраивать коэффициенты ПИД-регулятора** (для крена и тангажа) через форму на странице — полезно для постепенной настройки стабилизации без перепрошивки.

Дальность этой точки доступа — по факту, десятки метров, это обычный Wi-Fi ESP32, а не дальнобойная телеметрия. Это инструмент для настройки на столе, на стенде и рядом с полем — не для управления бортом в полёте на удалении.

## Предполётный чек-лист и безопасность

Прочитайте этот раздел целиком **до** первого включения, а не после инцидента.

### Обязательно перед любым стендовым тестом

- [ ] **Пропеллер физически СНЯТ**, если вы проверяете каналы, ARM, дашборд, настраиваете ПИД или просто включаете плату впервые на новой распиновке. ESC может дёрнуть мотор на любом этапе теста — это не гипотетический риск, это нормальное поведение при первом включении.
- [ ] LiPo аккумулятор проверен на вздутие/повреждение, заряжен корректным зарядным устройством для LiPo, хранится и заряжается на негорючей поверхности.
- [ ] Пульт включён и его каналы проверены на дашборде (`http://192.168.4.1`) **до** того как аккумулятор подключён к ESC.

### Перед полётом

- [ ] Открытая площадка, без людей и построек в радиусе, достаточном для планера с размахом 1200 мм на ручном управлении с нештатным поведением сервоприводов/крыла (см. раздел про ограничения прототипа ниже — крепление мотора и крыло пока не усилены карбоном).
- [ ] Все три поверхности двигаются в верном направлении — проверьте на столе перед каждым вылетом, а не полагайтесь на память с прошлого раза:
  - правый стик вправо → **правый элерон вверх, левый вниз**;
  - правый стик на себя → **лифт вверх**;
  - левый стик вправо → **руль направления и колесо вправо**;
  - SwB (закрылки) вниз → **оба элерона плавно вниз**, и крен стиком при этом по-прежнему разводит их в разные стороны;
  - в STABILIZE наклоните самолёт правым крылом вниз → **правый элерон вниз, левый вверх** (рули возвращают его к горизонту); нос вниз → **лифт вверх**.
  Если что-то не так — поменяйте соответствующий `*_REVERSED` в `include/Config.h` (раздел "Направление серво"), а не реверс на пульте: иначе стик и автопилот разойдутся.
- [ ] Failsafe настроен в пульте и проверен: выключили пульт → `RX LOST` на OLED/в Serial (см. раздел про failsafe).
- [ ] Радиус действия пульта проверен, батарея пульта заряжена.
- [ ] Держите руки и лицо подальше от пропеллера в любой момент, когда LiPo подключён к ESC — после ARM газ отрабатывает сразу по стику, без дополнительных предупреждений. DISARM — SwA вверх.
- [ ] Убедитесь, что вы физически можете быстро отключить питание (доступ к разъёму LiPo), а не полагаетесь только на failsafe по потере сигнала.

### Общая техника безопасности с LiPo

- Никогда не оставляйте заряжающийся LiPo без присмотра.
- Не подключайте/не отключайте LiPo к ESC, стоя рядом с плоскостью вращения пропеллера.
- Возите и храните LiPo в защитной сумке/контейнере.

## Troubleshooting

**"Нет сигнала приёмника" / RX выглядит нормально, но каналы на дашборде не двигаются**
Проверьте, что провод данных приёмника подключён именно на RX-пин iBUS из таблицы вашей платы (GPIO8/GPIO17/GPIO16), а не перепутан с землёй или питанием, и что земля приёмника и платы объединена. Если распиновка совпадает и провода целы, а сигнала всё равно нет — проверьте, что приёмник в принципе привязан (bind) к пульту и что выход на приёмнике настроен именно на iBUS, а не на PPM/SBUS.

**Датчик (IMU, барометр, компас) показывает "не отвечает" / NO_RESPONSE**
Прошивка честно сообщает, что датчик не отвечает, вместо того чтобы выдавать нули. Проверьте: (1) питание модуля — 3.3V и земля платы; (2) SDA/SCL — на I2C-пинах именно вашей платы; (3) адрес на линии: MPU 0x68 (AD0 на GND), BMP388 0x76 (SDO на GND, **CSB на 3.3V** — иначе чип в режиме SPI), QMC5883P 0x2C, QMC5883L 0x0D. Если датчик то отвечает, то нет (или откликается на чужой адрес) — это плохой контакт в макетке: пережмите VCC/GND/SDA/SCL, каждый модуль лучше питать прямо от 3.3V/GND платы. Команда `s` в консоли показывает счётчики ошибок I2C по каждому датчику.

**Углы на OLED перепутаны (нос вверх меняет R, а не P) или не того знака**
На клонах GY-521 чип бывает запаян повёрнутым относительно нарисованных стрелок. Поверните оси в `Config.h` → `IMU_ROTATION_CW_DEG` (0/90/180/270). Проверка: нос вверх → P в плюс, правое крыло вниз → R в плюс, стрелка X строго вверх → P ≈ +90.

**Сервопривод или ESC реагирует не на тот стик / не реагирует**
Команда `p` в консоли измеряет реальный импульс на каждом выходе (GPIO4–7) и сравнивает с ожидаемым. Всё "OK", а серво не двигается — проблема дальше платы: (1) серво не запитано (BEC/5V, общая земля); (2) сигнальный провод не на том пине; (3) механика заклинила. "НЕ СОВПАДАЕТ" — проблема в прошивке/периферии, сообщите разработчику.

**Мотор не крутится совсем, хотя газ на OLED/дашборде реагирует на стик**
Проверьте, что LiPo подключён к ESC и что борт реально armed — до ARM газ на ESC принудительно держится на минимуме, это не неисправность. ESC, который при включении увидел не минимальный газ, может постоянно пищать и не армиться — переподключите аккумулятор при газе внизу. Если после SwA вниз нет `ArmingManager: ARM`, смотрите Serial — прошивка печатает причину (газ не внизу, не отвечает датчик, нужный текущему режиму CH7); верните SwA вверх, устраните причину и переведите вниз снова.

**Мотор глохнет или дёргается на разгоне**
Если ESC питается от лабораторного блока питания — упирается ограничение тока БП: мотор даже без винта кратковременно тянет несколько ампер, напряжение проседает, ESC перезапускается. Поднимите лимит тока или используйте LiPo. Выбросы от такого перезапуска могут повесить USB-мост платы (порт "COM" перестаёт открываться) — переподключите кабель.

**После прошивки плата не выходит на связь / точка доступа `OpenPlane-Debug` не появляется**
Убедитесь, что заливка (`pio run -e <ваша плата> -t upload`) прошла без ошибок и что вы прошили именно то окружение, которое физически держите в руках (esp32-c3 отличается от esp32-s3 и esp32-dev не только пинами, но и чипом — прошивка под чужой чип на плату не встанет или встанет некорректно). Проверьте вывод монитора порта (`pio device monitor -b 115200`) сразу после перезагрузки платы — там печатается, на каком этапе setup() находится плата.

## Текущее состояние прототипа-планера

Чтобы ожидания были честными:

- Первый прототип **уже летал**. По итогам выявлены проблемы: **недостаточная прочность крепления мотора** и **недостаточная прочность крыла** — крылу нужно усиление карбоном. Также требуется дополнительная настройка сервоприводов. Учитывайте это при планировании собственных полётов — это не абстрактная оговорка, а реальный отказ, уже случившийся на этом прототипе.
- **Стенд на esp32-s3 собран со всеми датчиками** (GY-521 с MPU6500, BMP388 по I2C, GY-273 с QMC5883P, OLED) — все отвечают, цикл 500 Гц. Автопилотные режимы проверены на столе, но **ещё не испытаны в полёте**.
- Барометр BMP388 считается по полной формуле компенсации Bosch; высота — относительно точки включения. Абсолютная высота над морем — по стандартной атмосфере, без поправки на погоду.
- Компас QMC5883P требует калибровки (`m` в консоли) уже на собранном самолёте — рядом с мотором и проводами смещения другие, чем на макетке. Курс пока без компенсации наклона и ни одним режимом не используется.
- Лицензия проекта пока не выбрана.

Если вы строите свой борт по этому гайду — пролетайте его сначала на ручном управлении (MANUAL), и только потом переходите к автопилоту.
