# SPLIT_HEADERS.md — ветка `.h` + `.cpp`

Ветка `feature/split-headers` — та же прошивка, что в основной ветке,
в классической раскладке: в заголовках `include/` остались объявления,
а реализация (615 функций) переехала в 72 файла `src/core/`, повторяющих
дерево `include/`. Поведение то же самое: те же 330 тестов, та же
матрица «4 платы × 6 наборов датчиков» без предупреждений.

Ветка **не пишется руками** — она генерируется из основной скриптом
`tools/split_headers.py`. Правки кода делайте в основной ветке и
перегенерируйте эту (ниже), иначе две раскладки разойдутся.

---

## Что отличается

| | Основная ветка (header-only) | Эта ветка |
|---|---|---|
| Реализация | в `include/**/*.h` | в `src/core/**/*.cpp`; в заголовках — объявления, однострочные геттеры, шаблоны, `constexpr` |
| Единиц трансляции прошивки | 1 (`src/main.cpp` или `src/stm32/main.cpp`) | 1 + 72 |
| Оптимизация | компилятор видит всё сразу | LTO для кода проекта (`build_src_flags = -flto` + `tools/pio_split_lto.py`) |
| Нативные тесты | `test_build_src = no`, прошивка — в самом тесте | `src/core/` собирается библиотекой и линкуется к каждому тесту |
| Прошивка ESP32 38-pin на ПК | `pio test -e native` (тест переключает плату `#define`) | `pio test -e native-esp32dev`: пины теперь в `src/core/` (`Esp32Board`, `FlightOutputs`), и библиотеку надо собрать под эту плату |
| Тесты на плате | `pio test -e esp32-s3` | так же; `tools/pio_split_tests.py` при `pio test` убирает из сборки `src/main.cpp` (у теста свои `setup()/loop()`) |

Что скрипт оставляет в заголовке: однострочные функции (их компилятор
встраивает и без LTO), шаблоны, `constexpr`, операторы, `= default`,
функции внутри `#if` (иначе `.cpp` потерял бы условие) и `static`
функции файла. В `.cpp` у метода убираются `virtual/static/explicit/
override` и значения параметров по умолчанию, тип результата уходит в
хвост (`auto Класс::метод(...) -> Тип`), чтобы не квалифицировать
вложенные типы класса.

## Размер прошивки: честно

Одна единица трансляции — это не «раздутие»: компоновщик и так
выбрасывает всё, что не вызвано (`-ffunction-sections` +
`--gc-sections`), а компилятор видит весь код разом и встраивает мелкие
функции драйверов прямо в полётный цикл. Когда те же функции разнесены
по `.cpp`, встраивать через границу файла компилятор не может, и без
LTO прошивка **больше** header-only:

| Плата | Header-only | `.h + .cpp` без LTO | `.h + .cpp` с LTO (как в ветке) |
|---|---|---|---|
| ESP32-S3 | 870 161 | 878 605 (+8,4 КБ, +1,0 %) | 870 001 (−160 байт) |
| ESP32 38-pin | 898 905 | 914 053 (+14,8 КБ, +1,7 %) | 901 297 (+2,3 КБ, +0,3 %) |
| ESP32-C3 | 930 582 | 940 302 (+9,5 КБ, +1,0 %) | 931 218 (+0,6 КБ, +0,07 %) |
| STM32H743 | 133 332 | 135 884 (+2,5 КБ, +1,9 %) | 133 124 (−208 байт) |

Байты флеша, набор `SENSOR_KIT_BENCH_GY521` (по умолчанию); в
остальных 20 сборках матрицы разница того же порядка — сравните
таблицы `tools/build_matrix.sh` в обеих ветках. Поэтому LTO здесь
включён по умолчанию: с ним раскладка `.h + .cpp` стоит столько же,
сколько header-only (±0,3 %), но и не меньше — «раздутия» у
header-only не было.

LTO — только для кода проекта: ядро Arduino и FreeRTOS вызывают
`app_main()` и `vTaskSwitchContext()` из ассемблера, и LTO по всему
проекту выбрасывает их как неиспользуемые (сборка не линкуется).

## Время сборки

ESP32-S3, 4 ядра, секунды; «правка» — изменение содержимого файла
(SCons сравнивает содержимое, `touch` пересборку не вызывает):

| Что изменилось | Header-only | `.h + .cpp` (LTO) |
|---|---|---|
| ничего | 3,5 | 4,1 |
| драйвер BMP581 (`.h` / `.cpp`) | 6,8 — 1 файл | 9,3 — 1 файл + LTO |
| `config/Config.h` | 7,4 — 1 файл | 13,6 — 36 файлов |
| `sensors/SensorInterface.h` | 6,8 — 1 файл | 12,4 — 27 файлов |
| сборка с нуля (с ядром Arduino) | 17,6 | 25,5 |

Прошивка небольшая: вся header-only единица трансляции компилируется
за 3 секунды, поэтому раздельная компиляция здесь не ускоряет даже
правку одного драйвера (LTO пересобирает код проекта при линковке), а
правка общего заголовка пересобирает десятки `.cpp`. Эта ветка — для
тех, кому привычнее раскладка `.h` + `.cpp` при чтении и навигации по
коду, а не ради скорости или размера.

## Как обновить ветку из основной

Ветка — это основная ветка плюс два коммита: «Split layout: build
config and docs» (этот файл, `platformio.ini`, `tools/pio_split_*.py`,
тест esp32-dev) и сгенерированный код. Обновление — пересоздать её:

```bash
git fetch origin
CONFIG=$(git log origin/feature/split-headers -1 --format=%H --grep '^Split layout: build config')
git checkout -B feature/split-headers origin/main
git cherry-pick "$CONFIG"              # конфликт — обычно в platformio.ini
python3 tools/split_headers.py         # нужен libclang: pip install libclang
git add -A && git commit -m "Split layout: generate src/core from include/"

pio test -e native -e native-stm32 -e native-esp32dev
tools/build_matrix.sh
git push --force-with-lease origin feature/split-headers
```

Скрипт идемпотентен: повторный запуск на уже разделённых заголовках
ничего не переносит. Если он пишет `не разобрался (...) — оставлен
header-only`, заголовок не компилируется с фейками из
`test/native/support` — поправьте в основной ветке, иначе этот файл
просто останется целиком в заголовке.
