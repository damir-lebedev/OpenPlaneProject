# Чёрный ящик

Прошивка сама пишет каждый полёт во встроенный флеш платы: датчики, стики,
выходы на сервы, решения автопилота, события. После полёта запись
выгружается по USB и разбирается в таблицы CSV.

Работает на двух платах:

| Плата | Куда пишет | Сколько влезает (при ~20 КБ/с) |
|---|---|---|
| **ESP32-S3 N16R8** | раздел встроенного флеша 13.9 МБ | около **11 минут** |
| **STM32H743** (DevEBox — основная; WeAct) | файл на SD-карте, [ниже](#sd-карта-stm32h743) | 64 МБ — около **55 минут**, размер задаёт файл |

На остальных платах (ESP32-C3, обычный ESP32) носителя нет: ящик выключен и
полёту не мешает.

---

## Когда пишет

| | Условие |
|---|---|
| **Старт** | Заармлено **и** газ поднят (стик или ESC выше `THROTTLE_LOW_US`). В запись попадают и **10 с до этого** — момент ARM и стоянка перед взлётом |
| | Перезагрузка из-за сбоя (паника, сторожевой таймер, просадка питания) — запись с первого такта и не меньше 60 с: если это случилось в воздухе, видно, что было дальше |
| | Вручную из консоли (`k` → `r`) — для стенда |
| **Стоп** | Через **10 с после DISARM** |
| | Заармлено, но мотор стоит и самолёт **неподвижен 30 с** — сел или упал, а DISARM забыли |
| | Вручную (`k` → `r`) |
| **Не стоп** | Потеря связи, failsafe, мотор в ноль в воздухе, планирование, посадка без DISARM, пока самолёт катится |

«Неподвижен» — это сразу всё: вращение меньше 5 °/с по всем осям,
акселерометр показывает 1g ± 0.1, по барометру почти нет вертикальной
скорости, по GPS и трубке Пито (если есть) медленнее 2 м/с. В полёте так
ровно 30 секунд подряд не бывает.

## Что пишется

| Запись | Частота | Что в ней |
|---|---|---|
| `IMU` | каждый такт, 500 Гц | гироскоп (°/с), акселерометр (g), сколько длилась работа такта (мкс) |
| `CTRL` | 100 Гц | крен/тангаж/курс, цели автопилота, стики пилота, итоговые команды, **все 7 выходов** (мкс), составляющие ПИД крена и тангажа (P, I, D), газ пилота и автопилота, закрылки, режим, флаги (ARM, связь, failsafe, датчики живы...), включённые функции |
| `RC` | 50 Гц | все 10 каналов пульта, счётчики кадров iBUS (целых и битых) |
| `BARO` | каждый отсчёт (~50 Гц) | давление, температура, высота, вертикальная скорость, цель высоты |
| `MAG` | до 50 Гц | поле по трём осям, курс |
| `GPS` | каждое решение | координаты, высота, скорость, курс, спутники, фикс, точность |
| `AIR` | до 50 Гц | трубка Пито: перепад давления, приборная и истинная скорость, плотность |
| `NAV` | 10 Гц | дом (дистанция, пеленг), курс и цель курса, скорость навигации, источник курса, стадии запуска с руки и парения, автотриммер |
| `POWER` | 10 Гц | напряжение батареи и выход датчика тока (делители платы полётника, [FC_BOARD.md](FC_BOARD.md), блок B) |
| `SYS` | 1 Гц | частота и худший такт цикла, свободная память, счётчики iBUS, температура IMU, очередь ящика, потерянные записи, самая долгая запись во флеш, свободное место |
| `EVENT` | по событию | ARM/DISARM, отказ в ARM с причиной, смена режима, связь потеряна/есть, датчик отказал/вернулся, фикс GPS, дом записан, функции тумблеров, геозабор, защита от сваливания, стадии запуска и парения |

В начале каждого полёта — параметры: прошивка (дата сборки), причина старта и
последней перезагрузки, какие датчики стоят и прошли ли предполётную
проверку, коэффициенты ПИД (с учётом правок с дашборда), триммеры, важные
значения `Config` и привязки тумблеров.

## Как пользоваться

### Перед полётом

Ничего делать не нужно. При включении в мониторе порта видно состояние:

```
BlackBox: ждёт ARM и газ | стёрто впереди 12.9 МБ (≈11 мин) из 13.9 МБ | полётов 1
```

«Стёрто впереди» — сколько влезет в следующий полёт. После включения ящик
несколько секунд (после длинного полёта — до минуты) готовит место: стирает
старые записи. В это время полётный цикл на земле иногда замирает на
~0.15 с — рули могут дёрнуться с опозданием, это нормально. **В воздухе флеш
не стирается никогда.**

### После полёта — выгрузка

1. Подключите USB к разъёму **COM**. Монитор порта закройте (он держит порт).
2. Запустите в папке проекта:

   ```bash
   python tools/blackbox.py download          # последний полёт
   python tools/blackbox.py download --all    # все
   python tools/blackbox.py list              # что лежит на плате
   ```

   Нужен `pyserial`: `pip install pyserial`. Или Python от PlatformIO, где он
   уже есть: `%USERPROFILE%\.platformio\penv\Scripts\python tools\blackbox.py download`.

3. Полёт скачивается в папку `blackbox/` (~200 КБ/с: 10 минут полёта — около
   минуты) и сразу разбирается рядом, в папку с тем же именем.

Пока идёт выгрузка, полётный цикл стоит, поэтому она работает только без ARM.

### Что внутри папки полёта

| Файл | Что это |
|---|---|
| `summary.txt` | Сводка: длительность, частоты, диапазоны углов, высоты, скорости, напряжения, худший такт цикла, потерянные записи, все события |
| `events.txt` | Параметры полёта и все события по времени |
| `IMU.csv`, `CTRL.csv`, `RC.csv`, ... | По таблице на тип записи |

Время во всех таблицах — `time_s`, секунды от старта записи (ARM и газ);
предзапись — с минусом. Значения уже в единицах: градусы, g, метры, м/с,
микросекунды импульса. В `CTRL.csv` режим дописан именем (`mode_name`),
функции — списком (`features_on`), флаги разложены по колонкам 0/1
(`armed`, `rx_lost`, `fs_glide`, `imu_ok`...).

CSV открываются в Excel/LibreOffice, но для графиков по времени удобнее
[PlotJuggler](https://github.com/facontidavide/PlotJuggler): File → Load
Data → CSV, колонка времени `time_s`.

Файл `.bbl` — сырой образ флеша, его можно разобрать снова:
`python tools/blackbox.py decode blackbox/flight_001_....bbl`.

### Консоль: `k`

В мониторе порта клавиша `k` открывает меню ящика: состояние, список
полётов, `r` — начать/остановить запись вручную (проверить на стенде), `e` —
стереть все полёты (с подтверждением `y`, ~40 с).

## Место на флеше

- Полёты пишутся по кругу. Когда места мало, ящик на земле стирает **самые
  старые полёты целиком**, пока впереди не станет 10 МБ
  (`BLACKBOX_MIN_FREE_BYTES`, ~9 минут).
- **Последний записанный полёт не стирается никогда** — только следующей
  записью, если ей не хватило места.
- Если стёртое место кончилось в воздухе, запись продолжается в очередь в
  PSRAM (4 МБ, ~3 минуты последних данных); после посадки и DISARM ящик
  освобождает место и дописывает её. Полёт длиннее всего раздела (~11 мин)
  не влезает целиком: сохраняется начало, конец теряется.
- Поэтому **выгружайте полёт после каждого вылета** — особенно первого.

## Надёжность

- Обрыв питания в любой момент (упал, отсоединилась батарея): сохраняется
  всё, кроме последних ~15 мс. Недописанные записи отбрасываются по CRC —
  в `summary.txt` это строка «Недописанных записей (CRC)».
- Номер полёта, голова кольца и список полётов восстанавливаются по самим
  секторам: никакой отдельной «карты», которую можно испортить.
- Выгрузка проверяет CRC-32 каждого сектора и всего полёта.

## Влияние на полёт

- Полётный цикл только складывает снимок в очередь в PSRAM — единицы
  микросекунд. Во флеш пишет отдельная задача на ядре 0, по одной странице
  (256 байт) **сразу после такта цикла**: запись флеша останавливает оба
  ядра ESP32 на 0.6–0.9 мс, и она попадает в паузу между тактами.
- Замер на стенде (DevKit без датчиков, два прогона по 30–40 с записи):
  интервал между тактами 2.00 мс, 99.2–99.7% интервалов в пределах
  1.9–2.1 мс, самый длинный — 2.5 мс, ни одного пропущенного такта;
  работа такта та же, что без записи. Заметнее цикл вздрагивает только на
  земле без ARM, пока ящик сверяет и стирает место (чтение блока 64 КБ —
  пауза ~3 мс, стирание — ~0.15 с).
- С датчиками такт занимает ~0.7 мс, запись страницы всё равно
  укладывается в оставшиеся 1.3 мс. Проверка после первого полёта: в
  `summary.txt` строки «Такт IMU» и «Цикл: худший такт».

## SD-карта (STM32H743)

На STM32H743 ящик пишет на SD-карту (слот µSD на SDMMC1, 4 бита, 24 МГц).
Карта остаётся обычной **FAT32**: в её корне лежит заранее созданный файл
`BLACKBOX.BIN`, внутри него прошивка пишет сырые блоки, а таблицу FAT и
каталог не трогает никогда. Поэтому нечему испортиться при пропаже питания в
полёте, а файл можно просто скопировать на ПК.

### Подготовка карты (один раз)

1. Отформатируйте карту в **FAT32** (не exFAT; Windows предлагает FAT32 для карт до 32 ГБ).
2. Карта в картридере, на ПК:

   ```bash
   python tools/blackbox.py sd-prepare E:              # 64 МБ, E: — диск карты
   python tools/blackbox.py sd-prepare E: --size 256   # или больше
   ```

   Файл создаётся одним куском на пустой карте и заливается `0xFF`; первый сектор
   — служебная метка «кольцо пусто». Если файл лежит не подряд (карта
   не пустая и сильно фрагментирована) или его нет, при включении в консоли
   будет причина, а ящик выключен.
3. Вставьте карту в плату. При включении:

   ```
   SD-карта: 15204 МБ, SDMMC 24 МГц, 4 бита; файл BLACKBOX.BIN: ок
   BlackBox: ждёт ARM и газ | стёрто впереди 0.7 МБ из 64.0 МБ | полётов 0
   BlackBox: готов за 300 мс
   ```

   «Стёрто впереди» растёт в фоне: плата сверяет место по ~2.5 МБ/с.

### Забрать полёт

- **Через плату по USB** — как на ESP32: `python tools/blackbox.py download`
  (консоль STM32 — USB CDC, скорость выгрузки ~400 КБ/с, 1 МБ — меньше 3 с).
  `list`, `--all`, `--flight N` работают так же.
- **Вынув карту**: файл `BLACKBOX.BIN` с карты разбирается прямо в CSV —

  ```bash
  python tools/blackbox.py ring E:/BLACKBOX.BIN              # все полёты -> blackbox/
  python tools/blackbox.py ring E:/BLACKBOX.BIN --list       # только перечислить
  ```

  Файл — кольцо секторов: утилита сама собирает полёты по номерам секторов, в
  том числе перешедшие через конец файла.

### Что измерено на плате

DevEBox H743 + карта 16 ГБ (тест `test_blackbox_sd`, [TESTING.md](TESTING.md#тесты-на-плате-stm32)):

| | |
|---|---|
| Опознание карты | 12–18 мс, 4 бита, 24 МГц |
| Запись страницы 256 Б | в среднем 2.3–3.7 мс, **худшая 60–190 мс**, ~75–110 КБ/с устойчиво (нужно ~20 КБ/с) |
| Чтение | сектор 4 КБ — 4.2 МБ/с; случайный блок — 0.6 мс |
| Стирание | 64 КБ — 13 мс; вся область 64 МБ — 20–28 с |
| Включение | с пустым кольцом — 0 мс (по метке); с полётами — 0.3 с (выборочная сверка ~530 чтений); полная сверка 64 МБ шла бы ~20 с |
| 20 с записи в реальном времени (500 Гц IMU) | ни одной потерянной записи, ошибок 0 |
| Полётная задача при записи | отклонение периода 2 мс — **1 мкс** (задача-имитатор высшего приоритета рядом с записью) |

Худшая запись страницы — внутренняя «уборка» карты; очередь в ОЗУ (384 КБ ≈ 19 с
потока) такие паузы переживает. Дешёвые карты на этом отличаются сильнее всего:
перед полётами карту стоит проверить тестом `test_blackbox_sd` (худшая запись
должна быть меньше 250 мс — предел спецификации SD).

### Чем отличается от флеша ESP32

- **Задача записи** (`bbox`, приоритет 2) вытесняется полётной (5) посреди
  обращения к карте — а не «в паузе цикла», как на ESP32 с его остановкой
  ядер. Передача идёт с аппаратным управлением потоком SDMMC: без него FIFO
  переполнялся при вытеснении (на плате это были `HAL_SD_ERROR_RX_OVERRUN` и
  замершие на секунды консоль и запись).
- **Очередь — в ОЗУ**, 384 КБ (`BLACKBOX_RING_STM32_BYTES`), а не 4 МБ PSRAM.
- **Сверка при включении выборочная**: настоящие сектора кольца — одна
  непрерывная дуга, читается ~500 заголовков, границы дуги и полётов
  уточняются делением пополам. Результат тот же, что у полной сверки;
  если картина не сходится — полная.
- **Метка «кольцо пусто»** в первом секторе файла: чтобы пустую область не
  сверять секундами при каждом включении. Ставится при стирании всего и когда
  полная сверка ничего не нашла; снимается до первой записи.
- **Ошибки карты** (вынули, сбой шины) раз в секунду попадают в журнал событием
  «носитель: ошибок записи …»; потерянная страница оставляет дыру `0xFF`, и
  разбор сектора останавливается на ней (так же, как в `tools/blackbox.py`),
  остальные сектора целы.

сейчас ~0.9 МБ), чёрный ящик 13.9 МБ, coredump 64 КБ. Раздел NVS остался на
прежнем месте — калибровки IMU, компаса и триммеры после перехода на эту
таблицу сохраняются. Второго слота для обновления по воздуху (OTA) нет.

## Для разработчика

Код — `include/telemetry/BlackBox*.h`:

| Файл | Что |
|---|---|
| `BlackBoxFormat.h` | Формат: заголовок сектора, типы и структуры записей, схемы полей, CRC-8/CRC-32 |
| `BlackBoxStorage.h` | Кольцо секторов на `IFlashRegion`: поиск головы при включении, список полётов, запись страницами, стирание старых полётов шагами |
| `BlackBoxRing.h` | Очередь записей между ядрами (спинлок), выбрасывает самое старое |
| `BlackBox.h` | Снимки в цикле, старт/стоп, события, задача записи, выгрузка по UART |
| `hal/esp32/Esp32FlashPartition.h` | `IFlashRegion` поверх `esp_partition` |
| `hal/SdFileRegion.h`, `storage/Fat32File.h` | `IFlashRegion` поверх файла на FAT32-карте: поиск файла (только чтение FAT), неполные блоки, стирание `0xFF`, метка «кольцо пусто» |
| `hal/stm32/Stm32SdCard.h`, `src/stm32/sd_msp.cpp` | `IBlockDevice`: SDMMC1 на `HAL_SD` (опрос, 4 бита, аппаратный поток) и выводы |
| `hal/ResetCause.h` | Причина перезагрузки на ESP32 и STM32 (`RCC->RSR`) |

### Формат на флеше

Сектор 4 КБ = заголовок 16 байт (`magic "OPBB"`, сквозной `seq`, `millis()` при
открытии, номер полёта, версия формата, контрольный байт) + записи подряд.
Запись не переходит границу сектора; хвост сектора — `0xFF`.

Запись: `[тип u8][длина u8][данные][CRC-8]`, данные начинаются с `t_us`
(`micros()`). Первые записи полёта — `SCHEMA`: текст
`"16 IMU t_us:I gx:h/10 ..."` — имя поля, символ `struct` Python, делитель.
Декодер берёт поля из лога, поэтому новое поле в записи — это правка
структуры и строки схемы в `BlackBoxFormat.h` (их размеры сверяет
`static_assert`), декодер менять не нужно.

### Протокол выгрузки

Команды — строка после байта STX (`0x02`), консоль передаёт её ящику:

```
ПК:  \x02bb list\n
ФК:  BB:STATE state=idle free_kb=... total_kb=... flights=... rate_bps=...
     BB:FLIGHT n=3 sectors=234 kb=936 seconds=41 start=1
     BB:END
ПК:  \x02bb get 3 2000000\n
ФК:  BB:SEND n=3 sectors=234 baud=2000000   (на 115200), переходит на 2 Мбод
ПК:  переходит на 2 Мбод, шлёт 'G'
ФК:  234 кадра: A5 5A, u16 номер, 4096 байт сектора, u32 CRC-32
     возвращает 115200, BB:DONE n=3 crc=<CRC-32 всех секторов>
```

### Тесты

`pio test -e native -f native/test_blackbox_scan` — выборочная сверка кольца против полной на случайных историях (300 колец × 5 шагов проб) и стоимость на области SD. `pio test -e native-stm32 -f native_stm32/test_blackbox_sd` и `test_app_stm32_*` — FAT32, область, драйвер карты, ящик на карте, прошивка STM32 целиком. На плате — `pio test -e stm32h743-devebox -f test_blackbox_sd` (настоящая карта).

`pio test -e native -f native/test_blackbox` — формат, кольцо на NOR-фейке
раздела (стирание секторами, запись только опускает биты — подъём бита
считается ошибкой), перезагрузки, обрыв питания, запись полёта на настоящих
`FlightController`/`Autopilot`, старт/стоп, события, переполнение флеша в
воздухе, выгрузка. Образ полёта для проверки декодера:
`OPENPLANE_BLACKBOX_DUMP=/tmp/f.bbl pio test -e native -f native/test_blackbox`.
